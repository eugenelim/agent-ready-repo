# Create mode

Enter only after the user explicitly requests creation and the target root is
unambiguous and confined.

1. Reconfirm the framed activation boundary and portable outcome.
2. Inspect only the bounded repository conventions needed for the target.
3. Surface the exact destination and files before writing.
4. Create `SKILL.md` with required `name` and `description` frontmatter. Add
   only resources justified by the workflow; link every reference from an
   instruction path that says when to read it.
5. Keep platform projections, installers, catalogue publication, credentials,
   and runtime profiles outside the portable skill.
6. Validate syntax, local routes, activation positives and negatives, and at
   least one realistic success and failure path.

If a write is interrupted, stop and report the files that may exist. Do not
delete broadly or retry outside the confirmed root.
