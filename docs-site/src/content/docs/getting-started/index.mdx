## Install the CLI once

Every `agentbundle install` line below needs the CLI. Install it once, in a terminal:

```bash
python -m pip install agentbundle
agentbundle --help
```

If the second command prints usage text, the install worked. If you do not use a terminal, ask whoever runs your tooling to run these lines, or use the [Claude apps route](#use-the-claude-apps-without-a-terminal).

Add `--dry-run` to any install to preview the files it writes before it writes them. A pack installs skills, subagents, hooks, commands, and seed files as readable files; `agentbundle` is not a hosted agent runtime.

## Pick your route

Find your role, install its packs, and paste the first prompt into your agent. A pack is a bundle of skills (repeatable workflows) that your agent finds from your request. Every route shows where the output lands; [find and open those files](/agent-ready-repo/docs/guides/_shared/how-to/find-and-open-your-files/) covers opening them.

### Build and fix code

You get a supervised loop: a spec you approve, an implementation, mechanical checks, and an independent review. The `core` pack runs it.

```bash
agentbundle install --pack core
```

First prompt:

```text
I need to make the login test deterministic. Route this request.
```

Output lands in your repository as `docs/specs/<slug>/spec.md` and `plan.md`, then as a diff you review. Continue with [run the build loop](/agent-ready-repo/docs/guides/core/how-to/start-the-work/).

### Shape an idea

You get a written outcome and a de-risked plan, ready for a delivery team. The `product-engineering` pack does the shaping, `desk-research` adds evidence, and `product-strategy` adds market and direction work.

```bash
agentbundle install --pack product-engineering --scope user
```

First prompt:

```text
Frame this as a product intent: our onboarding drops half of new accounts before they connect a data source.
```

Output lands in your product folder, `docs/product/` by default, and the agent names each path. Continue with [shape an idea](/agent-ready-repo/docs/guides/product-engineering/how-to/frame-the-intent/).

### Design an experience

You get a customer journey, a content brief, and reviewed screens. The `experience-design` pack does this.

```bash
agentbundle install --pack experience-design --scope user
```

First prompt:

```text
Map the journey for a new account owner who wants to connect their first data source. The current experience breaks at setup.
```

Output lands in your design folder, and the agent names each path. Continue with [design the experience](/agent-ready-repo/docs/guides/experience-design/how-to/map-the-customer-journey/).

### Write product docs

You get a page drafted from your code, or a list of the pages your docs are missing. The `product-documentation` pack does this.

```bash
agentbundle install --pack product-documentation
```

First prompt:

```text
Audit this project's docs and tell me which stages of the reader journey are missing.
```

The audit changes no files. New pages land where your repository already keeps docs. Continue with [write the docs](/agent-ready-repo/docs/guides/product-documentation/how-to/write-a-guide/).

### Design an architecture and record decisions

You get a half-page architecture concept you agree before anyone builds, and a short record of each decision you make. The `architect` pack writes the concept, and the `repo-governance` pack records decisions.

```bash
agentbundle install --pack architect --scope user
agentbundle install --pack repo-governance
```

First prompt:

```text
Draft the architecture concept for account notifications.
```

The concept lands in your design folder, and decision records land in `docs/adr/` unless your repository keeps them elsewhere. Continue with [design the architecture](/agent-ready-repo/docs/guides/architect/how-to/shape-an-architecture-concept/).

### Release and report

You get a release checked in a temporary environment that stops for your approval before production. The `release-engineering` pack runs the release, and `core` is its base.

```bash
agentbundle install --pack core
agentbundle install --pack release-engineering
```

First prompt:

```text
Run the release loop for the v2.3.0 payment service deployment.
```

Output is a release-readiness record shown in your session. The release needs a way to create and tear down a temporary environment. To report delivery speed from Jira, add the `atlassian` pack. Continue with [release a change](/agent-ready-repo/docs/guides/release-engineering/how-to/run-a-release/).

## Use the Claude apps without a terminal

The Claude desktop and web apps can install the user-scope packs from this catalogue as a plugin, so a strategist, designer, or writer needs no terminal. In the left sidebar, open Customize, then the Plugins tab. Choose Add, then Add marketplace, then Add from a repository, and enter `eugenelim/agent-ready-repo`.[^apps]

Plugins need a paid plan: Pro, Max, Ultra, Team, or Enterprise. An organization can block a marketplace it has not allowed. If "Add from a repository" does not appear in your app build, register the marketplace in Claude Code instead:

```bash
claude plugin marketplace add eugenelim/agent-ready-repo
```

The apps route lacks three things the terminal route has:

- Sub-agents and hooks do not run in the chat apps, so reviewers and retrievers that a method calls do not run and the result is thinner.
- The chat apps read nothing from your computer's files, so the agent shows its result in the conversation. Copy it from there.
- Repo-scoped packs, such as `core`, `repo-governance`, and `release-engineering`, are not on this route. They install with `agentbundle`.

The Claude apps and Claude Code keep separate plugin lists, so register the marketplace in each place you work.
