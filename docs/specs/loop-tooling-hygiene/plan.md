## Declined patterns

- **Tempted:** bound `lint-spec-status.py`'s four `git` calls while bounding
  `run_git` — same class, same session, four lines. **Declined:** its own entry says
  it is *not* a mechanical ride-along but an observable change to a shipped CLI's
  failure mode on a slow repository, needing its own criterion. Bundling it would
  bury that judgement in a hygiene PR.
- **Tempted:** delete `run_git` instead of bounding it, since it has no callers.
  **Declined:** deletion is a bigger claim than the entry makes, and the entry's stated
  value is that it is the nearest copy-paste hazard to the guard extraction site — a
  bounded exemplar is worth more than an absent one.
- **Tempted:** extract a shared `_load_sibling_module()` helper, since the two
  `_statelock` loaders and the `_loop_guards` loader are now near-identical.
  **Declined:** the three live in two scripts that deliberately share no module
  (stdlib-only, loadable where `agentbundle` is absent). A shared helper would need a
  fourth file on the import path of the lock loader itself, which is the opposite of
  what this change is for.
- **Tempted:** put `name:` first in the fixture's job blocks, where it reads best.
  **Declined after doing it:** it broke four unrelated mutations that rely on
  `  <job>:\n    runs-on: …` adjacency. Inserted after `timeout-minutes:` instead.
  Mapping key order is irrelevant to YAML and to every assertion.
- **Tempted:** assert `name:` is present AND equals the id, which is stricter.
  **Declined:** an absent `name:` makes GitHub display the job id, so the required
  check still reports. Failing on it would be asserting a style preference as a
  posture violation.
