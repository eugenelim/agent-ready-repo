## Approach

Ten tasks. The collision comparison currently tests the whole stored source string, so a revision change reads as a different source and is refused as a collision; it must test the identity tuple, with the ref suffix excluded. That refusal does not become a permission: RFC-0098 D4 keeps revision changes to upgrade, so after T2 an install at a different ref still exits 1 — with a code that names the upgrade form instead of a collision. T3 depends on T2 because a `--source` upgrade re-enters the shared writer path the gate guards, not because the `--skill` selector consults it; the selector reads the row from state by `(name, adapter)`.

`upgrade --skill` is then a selector over the existing preflight, projection, and ownership paths, per RFC-0098 D6. It reads the row's `source` and `source-path`, hands them to the same admissibility gate install uses, and replaces through the same writer.

## Constraints

- RFC-0098 D4 fixes the identity tuple and states revision and digest change only through upgrade.
- RFC-0098 D6 requires the lifecycle verbs to be thin selectors over the existing pack-keyed paths, not separate engines.
- `tools/lint-direct-code-table.py` asserts set equality between `DIRECT_CODES` and the published table, and passes today. A new member must land with its table row in the same change or CI reddens.
- The state schema stays at 0.5.
- `packages/agentbundle/tests/unit/test_direct_architecture_controls.py` governs `direct_source`, `direct_source_acquisition`, `direct_source_state`, `direct_install`, `direct_validate`, and `bounded_metadata`. In those modules `lstat`, `stat`, `fstat`, `resolve`, `realpath`, `abspath`, and `readlink` are banned, and any path join with a variable right operand must reach a `CONFINEMENT_CALLS` member in the same function body. Measured: `unlink`, `rmdir`, `rmtree`, and `remove` appear nowhere in the controls, so AC12's deletion needs **no** new blessed helper — it belongs in `direct_install`, in a function that validates through an existing confinement call before joining and unlinking, and it must not check the path with a banned observer first. Moving it to a new module would place it outside `DIRECT_MODULES` and silence both controls, which is the evasion the control's own comment records.
- Capability re-consent is deferred, so this plan's refusal must not grow an acceptance path.

## Construction tests

The criteria are the checklist. These name mechanism an implementer cannot infer from them.

- **No test drives a `git+https` install today, and four tasks need one.** Every `ref_kind` is a `git+https`-only property, so T2's different-ref refusal, T4's whole `--source` matrix, and T7's remote `--yes` and `--dry-run` cases are unbuildable with the local-directory fixtures `test_direct_install.py` uses; the string appears there only as a renderer label, and `acquire_git_https_archive` is monkeypatched nowhere. **T1 builds it**, because T1 pins F7's remote-`--yes` ordering and `direct_install.py:516` gates that block on a `git+https://` source, so T1 needs it before any other task. T2, T4 and T7 then consume it. It is one fake at the acquisition boundary returning a prepared archive for a `(repository, ref)` pair, so a ref move is expressible without a network. This is the mechanism the criteria cannot state and the single largest build risk in the plan.
- **AC4 has three observable outcomes and needs a case per outcome.** A byte-identical reinstall still proceeds and repairs in place (the two shipped tests); the same identity at a **different** ref refuses and names the upgrade form; a differing tuple keeps refusing as `CAT-D009`. Any two of the three pass while the remaining one is unimplemented — in particular, keeping today's `same_source → continue` for an equal tuple satisfies both the proceed case and the collision case while the different-ref refusal is absent.
- **The direct route has no `--force` collision test to re-run.** `packages/agentbundle/tests/integration/test_direct_install.py` sets `force` only as a namespace default and `direct_install.py` never reads it; the only `--force` collision suite is `packages/agentbundle/tests/unit/test_source_conflict_guard.py`, which drives the catalogue route. So parent AC11's "`--force` never resolves them" is untested on this route, and T2 writes that case rather than re-running one.
- **The ref-stripping is where this goes wrong.** AC4 states the rule; the mechanism it does not state is the fixture — a local path containing `@`, proving the strip never reaches it.
- **AC3's refusal can only be driven on the source element.** `--source` takes one source string with no path component, and AC2 takes `source-path` from the row, so a same-repo-different-path case is not constructible under this flag; T4 drives a different repository instead. The `source-path` element is exercised where it can vary — T2's moved-path collision, on the install route.
- **AC7 does not read `CapabilityDelta` at all, so do not extend it.** The pre-spike design had AC7 read typed per-axis fields off the shipped delta. F9 retired that: the producer returns the three axes, `compare_capabilities` keeps zero production callers, and adding typed fields to its return type would ship a carrier with no production producer and no production reader. AC7's predicate runs over the axes directly; the comparison that must not be reused is `requires_reconsent`, for the reason below.
- **AC7 must NOT key on `requires_reconsent`.** That function is `unknown or bool(differences)`, and `compare_capabilities` appends `SKILL.md digest changed` and `payload digest changed` — exactly the conditions AC6 calls an available update — so keying on it refuses every upgrade. The test needs a fixture whose payload digest changed with no capability axis touched, asserting the upgrade PROCEEDS; without it the inert implementation passes.
- **AC7's integration test drives a real projection and row**, because a unit test of the comparison passes while the upgrade still writes. It needs an `unknown` fixture — an unreadable projected `SKILL.md` — asserting refusal, because `compare_capabilities` returns an EMPTY difference list in that case and a predicate reading only differences admits the least-safe case.

## Design (LLD)

### Design decisions

- **Identity is a tuple, computed once.** One helper returns `(source-kind, ref-stripped stored source, source-path)` for a row and for a candidate; the collision gate and the upgrade row lookup both consume it. It must **not** call `canonicalize_source`, which lowercases scheme and netloc and resolves a schemeless value against the CWD — F6 records why, and AC4 names the two cases that would then pass by accident.
- **The identity source element excludes the ref.** The ref is provenance, recorded in `source-revision`; keeping it in the identity is what strands an installed skill.
- **`--source` is how a fixed skill moves.** Re-resolution alone cannot move it, so the adopter names the target, and the identity tuple guards against pointing at something else.

### Failure, edge cases & resilience

The destructive edge is the one the criteria create rather than inherit: AC12 deletes a file the new revision drops, and AC2 refuses an adopter-edited destination. Those interact — a dropped file the adopter also edited must refuse, not delete, so the deletion pass runs behind the same ownership check the writer applies and never ahead of it.

The other edge is remediation reachability. Six refusals print a next command; F8 is the only measured route that terminates for a pinned row, so each printed command is asserted by running it rather than by matching its text.

## Risks

- **T2 changes a shipped, ticked refusal, and the direct route has no test of it.** The parent's AC11 stays as shipped — a ticked criterion may not carry unbuilt behaviour — so the ADR records the change. The mitigation cannot be re-running the parent's collision test, because no direct-route `--force` test exists: `direct_install.py` never reads `force`, and the only such suite drives the catalogue route. T2 writes that case, so the shipped guarantee is asserted for the first time by the change that narrows it.
- **AC4's three outcomes are stated once, in AC4.** Every other mention here references it rather than restating it; the release entry drifting from the criterion is how round 4 found a contradiction. **AC4's byte-identical branch is what keeps `_destination_holds_foreign_content` reachable.** The two shipped reinstall tests are the positive cases for that guard, and one of them exists specifically so the guard "could not pass by refusing everything". An AC4 that refused every reinstall would delete both, leaving the adopter-edit refusal with no reachable negative case on this route. T2 keeps all three green rather than replacing their coverage.
- **Ref-stripping is the likeliest defect.** A local path containing `@` must be untouched, which is why it has its own fixture.
- **The deferred re-consent slice will relax AC7.** AC7 refuses on a capability-axis difference or on `unknown`, and lets a content-only change proceed; the deferred slice adds the acceptance path for the axis differences and keeps the `unknown` refusal, which the shipped comparison already treats as unacceptable even with a flag. Extending it is additive.
