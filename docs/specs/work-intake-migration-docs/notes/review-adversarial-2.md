# Adversarial implementation review — round 2

## Blockers

**1. Rollback can bypass the applied-fingerprint guard after an external exact revert.** `packs/core/.apm/skills/workspace-status/scripts/workspace_status.py:1575` `_migration_workspace_state()` returns `legacy` for pre-apply bytes, and `rollback_migration_operation()` accepts that state for an `applied` operation before recording `rolled_back`, so an external exact revert bypasses AC10’s applied-fingerprint guard. Require `state == "target"` for applied rollback, allow `legacy` only for `rollback_pending` crash recovery with an exact recorded recovery fingerprint, and add the regression.

**2. Apply does not prove the supplied selection is the planned selection.** `packs/core/.apm/skills/workspace-status/scripts/workspace_status.py:1691` The retry path compares only source membership, target entry, target membership, and processor, so a different selection file with changed `legacy_finding_id`, `workspace_fingerprint`, or `provenance_reference` is accepted against a pending ledger operation. Persist and compare a canonical selection digest, or compare all closed selection fields including `legacy_finding_id`, `workspace_fingerprint == pre_apply_workspace_fingerprint`, `provenance_reference`, and privacy attestation before consuming confirmation.

**3. Unsafe workspace symlinks bypass the migration result envelope.** `packs/core/.apm/skills/workspace-status/scripts/workspace_status.py:2082` For `repair-plan` and `repair-rollback`, the shared pre-branch workspace symlink escape guard emits `_canonical_failure_payload(...)` with no `migration` object, violating AC27’s stable migration envelope for path refusals. When `migration_mode` is true, emit the migration JSON envelope with `unsafe_path` and add CLI coverage for symlink-escape workspaces on plan and rollback.

**4. The stale-semantic audit missed an unconditional feature-to-brief guide.** `guides/product-engineering/how-to/shape-a-feature-intent.md:65` The current guide still sends an app-scale single feature intent through “Decompose to a brief,” while the walkthrough claims no unconditional feature/issue/story-to-brief rule remains, so AC17’s audit evidence is false. Update the guide to route one independently shippable feature directly to a spec and reserve briefs for multi-spec or cross-repo coordination, then rerun and correct the audit note.
