# Adversarial implementation review — round 3

## Blockers

**1. Status/explain migration projection still reads `workspace.toml` through an unguarded path.** `packs/core/.apm/skills/workspace-status/scripts/workspace_status.py:441`, `docs/specs/work-intake-migration-docs/spec.md:231`. `_canonical_projection()` feeds `Path.read_bytes()` output into migration finding construction, bypassing AC7's confined `O_NOFOLLOW`/pre-fstat-post-stat read contract for the exact legacy slice. Fix: route this projection read through the guarded migration read helper and fail closed with a non-echoing unsafe-path result/finding when it cannot be read safely.

**2. Ledger semantic validation does not enforce the published operation-digest invariant.** `contracts/jsonschema/work-intake-migration-manifest.schema.json:12`, `packs/core/.apm/skills/workspace-status/scripts/workspace_status_engine.py:4538`. The schema says every operation digest binds immutable operation material to the ledger repository identity, but `validate_migration_ledger_invariants()` only checks uniqueness, receipt binding, and state order, so a schema-valid ledger with a tampered unselected operation is accepted and can be re-persisted. Fix: recompute `_migration_operation_digest(operation, ledger["repository_identity"])` for every operation during ledger semantic validation and add a schema-valid invalid fixture for digest mismatch.

**3. Fix: update those current sources to route one independently shippable feature directly to `new-spec`, reserve briefs/`receive-brief` for multi-spec or cross-repo coordination, and refresh the audit note.
