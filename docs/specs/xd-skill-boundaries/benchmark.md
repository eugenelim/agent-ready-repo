# Experience-design skill-boundary benchmark

This is the pre-edit and reconciliation baseline for the 20 skills listed in
`packs/experience-design/pack.toml`. Canonical skill frontmatter and activation
fixtures remain the shipped routing contract; this file records why each planned
change exists.

## Controlling scope

RFC-0071 Area D requires: “All 19 skills: update trigger descriptions to natural
requests; add near-miss guards for strategy, PE shaping, and routine FE.” Its
2026-08-02 erratum corrects that inventory to 20 because `copy-direction` shipped
before this work. The same erratum supersedes Area D's reversed copy relationship:
`tone-of-voice` produces the cross-surface brand register, which may anchor the
surface-specific work of `copy-direction`.

The benchmark derives five fixture types from that contract:

- `P+` — natural-positive request for the skill's own decision or artifact.
- `S−` — product-strategy question about markets, positioning, adoption, or
  organization-level direction.
- `PES−` — product-engineering shaping request about framing, appetite, scope,
  solution options, or commitment.
- `FE−` — routine frontend implementation, code, styling, or build work.
- `C−` — a copy-layer near miss: brand register, surface content structure,
  acquisition copy direction, or product UI strings owned by another skill.

Every proposed fixture below declares one of these types. “Strategy / shaping /
frontend” exits are explicit for every row even when one is not the closest
negative fixture; descriptions should state the closest applicable exits without
becoming mechanical lists.
