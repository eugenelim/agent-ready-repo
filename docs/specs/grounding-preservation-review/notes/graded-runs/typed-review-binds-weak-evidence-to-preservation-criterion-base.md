## Blockers

**1. CRIT-2 test is tautological and cannot fail.** `evals/files/preservation-review/test_graph.py:14-20`. The test builds `expected` by calling `resolve_calls(graph)` itself and then asserts `resolve_calls(graph) == expected`, so it compares the resolver to its own output. A resolver that maps `call limit` to the `value limit` node, which is exactly what CRIT-2 ("Ordinary calls resolve to no value node") forbids, would still pass, as would any other resolver output. The test name also promises "resolve to definitions", but nothing checks that. Fix: CRIT-2 needs evidence that goes red if any call resolves to a value node. Assert against an independently written expected mapping that includes a call whose name matches a value line (`call limit` maps to no value node) and a positive control (`call run` maps to the `def run` node).

**2. CRIT-3 default-search exclusion has no test that can catch its loss.** `evals/files/preservation-review/test_graph.py:23-26`. The only search test queries `"run"`, and no value node matches that name. Deleting the `include_values or n.kind != VALUE` guard at `evals/files/preservation-review/graph.py:50` would leave it green. Nothing exercises the default exclusion of `value limit` or the explicit `include_values=True` opt-in. Fix: CRIT-3 needs a search case where a value node matches the query. It must show the value node is absent by default, with a non-value match present as a positive control, and present when the explicit flag is set.

**3. CRIT-3 listing exclusion is untested, and the current listing would fail such a test.** `evals/files/preservation-review/test_graph.py:3`, `evals/files/preservation-review/graph.py:54-56`. No test imports or exercises `outline`, the listing surface. `outline` returns every node, including `value limit`, which contradicts CRIT-3 ("Default search and listing exclude value nodes"). The missing evidence therefore hides a reachable violation of that criterion. Spec conformance of `outline` itself warrants the adversarial-reviewer lens. Fix: CRIT-3 needs a listing test that fails while default listing includes value nodes. It must include a positive control showing that def and call entries still appear in build order.

## Nits

**4. CRIT-1 fixture cannot tell "each" from "first".** `evals/files/preservation-review/test_graph.py:5-11`. `LINES` holds a single value line, so a builder that kept only the first value node, or dropped repeated ones, would still pass a criterion that says "for each value line". Fix: CRIT-1 evidence must include more than one value line and assert one value node per line, in order.
