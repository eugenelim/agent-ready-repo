## Execution time observations

| Phase | Observation |
|-------|-------------|
| Fixture generation | ~0.34 s (313 spec.md files written, workspace.toml written) |
| Analysis — warm (second run) | ~0.11 s |
| Analysis — cold (file writes in same process) | < 0.2 s |

The dominant cost is reconciliation: all three scan types read spec.md files.
Type 1 alone walks every `docs/specs/` subdirectory; the 313-directory fixture
reads 313 + active-queue files. On a real repo with thousands of specs this
scales linearly with spec count — the "no quick mode" design flaw (KD-04) means
every session-start pays the full O(spec_count) cost.

## Output size

Scales with the number of blocked entries (longer `blocking_needs` lists).

## Known test gaps

| Gap | Notes |
