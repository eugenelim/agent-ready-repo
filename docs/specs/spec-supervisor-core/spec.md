> PR must match this spec, or update it. Verification must be derivable from it.
>
> **Not every section is contract.** `Agent Rules`, `Testing Strategy` and
> `Acceptance Criteria` are what a completion gate reads, and an amendment
> changes them. `Outcome`, `What Changes`, `Durable Outputs`, `Follow-ons` and
> `Assumptions` are working material: they orient a reader and an author corrects them in place
> as the work teaches, without an amendment and without a review round. A review
> finding against working material is advisory — it cannot block, because nothing
> gates the text it cites. Marking the tiers is the spec's job; honouring them
> when a finding is adjudicated is the reviewing surface's.

## Outcome

A user or controller drives a drafted spec and plan from admission through review rounds to the `spec-approved`, `review-cap` and `review-weak` consent requests with six commands, and a fresh process resumes from the repository with no step lost or repeated. The supervisor approves nothing, binds each consent to the revision the reviewers read, and accepts a step only when protected content is untouched; it checks content, not who committed it, and it does not prove that an independent review ran (see the accepted risks under Assumptions).

## Agent Rules

### Always do

- Run the pack tests for the supervisor before reporting a task done.
- Keep the supervisor stdlib-only, as `work-supervisor.py` is.
- Reconfigure stdout and stderr to UTF-8 before the supervisor's first print.
- Stop at an approval only by issuing a consent request: no verb of the supervisor stops at an approval any other way.
- Treat reviewer, author and human text as untrusted data: carry identifiers and grammar-checked file references, bound any text, neutralise control, escape and bidirectional characters, and mark it untrusted.

### Ask first

- Adding a request kind, a stage value or a command to the supervisor.
- Changing a default in `spec-policy.json`.
- Adding a path to the set a request kind may change, or an item to the protected set.
- Widening an allowed edit of a protected item, or removing an item from the protected set.

### Never do

- Change any file in the work-loop pin set: no file in the work-loop pin set changes (ADR-0163 D3, ADR-0144).
- Import, or load at run time, any work-loop script.
- Give the supervisor a verb, flag or default that approves a gate.
- Add a new top-level dependency or a runtime import of a third-party package.
- Write the ledger, an attempt record or the store from anywhere but a supervisor verb.
- Place the supervisor's store inside `<git-dir>/agentbundle-supervisor/`.
- Put an internal record citation in a file shipped under `packs/`.

## Testing Strategy

- **Admission and confinement (AC-0001, AC-0002, AC-0003):** TDD over a temporary repository, because each refusal is a compressible invariant and each closed list is a parametrized case set. The confinement case includes a link swapped in between a check and the open.
- **Manifest, requests and roles (AC-0004, AC-0005, AC-0006, AC-0007):** TDD for the request shapes, the author rule and the role set, and goal-based for the manifest, which a schema validator decides.
- **Report, ledger and protected content (AC-0008, AC-0009, AC-0010, AC-0011, AC-0012, AC-0013, AC-0014, AC-0015, AC-0016, AC-0017):** TDD over a temporary repository with real commits, including foreign commits landed between steps, a forged one-line append and edits outside the allowed paths.
- **Coexistence and scope (AC-0018, AC-0019):** goal-based, an integration test against the real installed `work-supervisor.py`, never a stub, and a diff check against the work-loop pin set at closeout.
- **Resume (AC-0020, AC-0021):** TDD with a process killed at named points and a fresh process started after.
- **Review procedure (AC-0022, AC-0023, AC-0024, AC-0025, AC-0027, AC-0028, AC-0029, AC-0030, AC-0031, AC-0032):** TDD over recorded reviewer reports, because rounds, weakness and stops are state transitions.
- **Classifier equivalence (AC-0026):** goal-based, a behavior comparison against the real `review-artifact.py` over recorded reports, since ADR-0163 D3 forbids sharing its code.
- **Consent, park, gates and untrusted text (AC-0033, AC-0034, AC-0035, AC-0036):** TDD over a temporary repository, with injected hostile report text.
- **Consent digest (AC-0037):** goal-based, a behavior comparison with the work supervisor's gate digest on the same inputs, run in the pack tests and at closeout.
- **Pins (AC-0038, AC-0039, AC-0040):** goal-based digest comparisons, TDD for the refusals, and a behavior comparison with the work supervisor's pin code on the same inputs.
- **Release and shipped text (AC-0041, AC-0042):** goal-based, the changelog validator, the core release check, the self-host drift check and a citation scan of added lines.

## Acceptance Criteria

- [ ] **AC-0001.** `start <spec-dir>` on a directory that holds `spec.md` and `plan.md`, on a clean working tree and a branch other than the repository's default branch, admits the subject and records the admission as one ledger line in one commit; the admission line holds the run id, the reviewer role set, the pin digests and the pair identity of AC-0017.
- [ ] **AC-0002.** `start` refuses, and writes nothing, in each case of this closed set: the current branch is the default branch (`default-branch-refused`), the default branch cannot be determined (`default-branch-unknown`), `HEAD` is detached (`detached-head`), the working tree holds a modified, staged or untracked non-ignored path (`checkout-dirty`), `spec.md` is missing, `plan.md` is missing, the subject is already admitted or ended, `max_review_rounds` is present in `spec-policy.json` and is not an integer of at least 1, a file under `scripts/` has a name outside the portable pin form of AC-0038, or `pinned_files` of `supervisor.toml` differs from the installed listing.
- [ ] **AC-0003.** Every verb that takes `<spec-dir>` refuses, and writes nothing, in each case of this closed set: the argument is not a repository-relative POSIX path whose every segment matches `[A-Za-z0-9._][A-Za-z0-9._-]*` and is neither `.` nor `..`, the path lies inside the git directory, a component of it is a symlink or not a directory, or `spec.md`, `plan.md` or the ledger inside it is a symlink or not a regular file, whether the link exists at the check or appears before the open.
- [ ] **AC-0004.** `supervisor.toml` validates against `supervisor-manifest.v1`, and its listed request kinds equal the kinds `next` returns across a driven run of this release.
- [ ] **AC-0005.** Every request `next` returns carries `schema_version` 1, `request_id`, `run_id`, `kind` and `stage`, validates against `supervisor-request-envelope.v1`, has a `kind` in `author-spec`, `review-round`, `adjudicate`, `revise`, `consent` and a `stage` in `authoring`, `reviewing`, `revising`, `awaiting-human`, `delegating`, `terminal`, and pairs them as `author-spec` with `authoring`, `review-round` and `adjudicate` with `reviewing`, `revise` with `revising`, and `consent` with `awaiting-human`.
- [ ] **AC-0006.** `next` issues `author-spec` exactly when the admitted pair has no recorded review round and no recorded author, and the author's agent definition is recorded from the first reported `author-spec` result.
- [ ] **AC-0007.** The required reviewer role set is `adversarial` always and `security` when the spec's risk triggers include `security-boundary` or `destructive`, is recorded in the admission line, is recomputed from the pair at each reported `author-spec` and `revise` step, and never shrinks: a role once recorded stays required, and a step that removes its risk trigger leaves it required.
- [ ] **AC-0008.** Each completed step adds exactly one commit, and that commit holds exactly one new ledger line and the files the step changed.
- [ ] **AC-0009.** A commit that adds ledger content is accepted as a step commit only when it adds exactly one well-formed line of this run whose `previous` equals the last recorded commit (the newest earlier commit on the branch that changed the ledger, read from git history) and, when the line completes the open request, whose kind and request id equal that request's, and the commit changes no path outside the kind's path set; any other ledger-adding commit is refused `ledger-foreign-append` and nothing is written.
- [ ] **AC-0010.** `report` refuses, and writes nothing, in each case of this closed set: a request id other than the open one, a second report on a completed step (`request-consumed`), a result file that is a symlink, is not a regular file, is over 16 MiB, is not UTF-8 JSON, repeats a key, or nests deeper than 16 levels, a `facts` key outside the kind's closed set or repeated (the sets are `agent_definition` for `author-spec`, `adjudicate` and `revise`, plus `outcome` and `report_path` for `review-round`, and `report_path` for `adjudicate`; `consent` has none), an `agent_definition` outside `human` or `[A-Za-z0-9._-]{1,64}`, or a `consent` result with no answer record (`no-human-answer`); the supervisor computes the classification, finding count and `weak` itself and reads none of them from `facts`.
- [ ] **AC-0011.** `report` on `author-spec` refuses when `spec.md` does not read `Status: Draft`, when `plan.md` does not read `Status: Drafting`, or when `lint-contract-item-alignment.py`, run with a scrubbed environment and bytecode writing off, does not exit 0 on the spec directory.
- [ ] **AC-0012.** Every verb refuses when the ledger is not a strict append-only extension of the ledger at the last recorded commit of AC-0009.
- [ ] **AC-0013.** `next` and `report` accept every commit landed since the last recorded commit, whoever made it, except one that changes an item of the protected set outside that item's allowed edit, which they refuse `protected-content-changed`, writing nothing. The protected set and each item's allowed edit are: the ledger, one appended line in a step commit; `spec-policy.json`, `supervisor.toml` and every pinned script, no edit (their digests are the pins of AC-0038); the preamble `Status:` line of `spec.md` and of `plan.md` and the approval-entry lines of `plan.md`, the edit of AC-0014 only.
- [ ] **AC-0014.** A commit that changes only protected lines (adds, removes or changes a preamble `Status:` line or an approval-entry line, the two defined as the work supervisor's gate digest masks them) is accepted when it leaves `spec.md` and `plan.md` otherwise byte-identical and the repository is in one of two states: an issued `consent` request for `spec-approved` or `plan-approved` covers the current reviewed revision (open, parked, or completed with no later ledger line), or an approve answer to `review-cap` or `review-weak` is recorded for the open request and no later ledger line exists; the new status tokens are `Approved` or the reverting `Draft` and `Drafting`.
- [ ] **AC-0015.** The edit of AC-0014 is refused `protected-content-changed` in every other state and for every other shape, including a commit before any consent is issued, a commit after the window closes, a commit that inserts a second `Status:` line, adds an approval entry outside the region the gate digest drops, or changes any other byte of either file.
- [ ] **AC-0016.** `report` refuses, and writes nothing, when the working tree or the index differs from `HEAD` outside the closed path set of the request's kind, counting an untracked non-ignored file as a difference; the path set is `spec.md` and `plan.md` with every protected line unchanged for `author-spec` and `revise`, none for `review-round`, `adjudicate` and `consent`, and the ledger file in every kind with exactly one appended line that matches the open request, so a repeated `report` after a kill between the ledger write and the commit completes.
- [ ] **AC-0017.** Each ledger line of an `author-spec`, `revise`, `review-round` or `adjudicate` step records the pair identity (the sha256 of each of `spec.md` and `plan.md` with the protected lines of AC-0014 removed), and a content change to either file that no `author-spec` or `revise` step made voids every earlier convergence: `next` opens a further round for the new revision, counted in the round total, and issues a `consent` request only when the current identity equals the identity of the round that converged.
- [ ] **AC-0018.** With a populated supervisor store and the ledger present, the real `work-supervisor.py` `status`, `park` and `start` answer as they do with neither, including a `start` that admits an Approved pair.
- [ ] **AC-0019.** At closeout, the diff of the change set against `origin/main` holds no path in the work-loop pin set (`packs/core/.apm/skills/work-loop/scripts/`, `supervisor-policy.json`, `review-rules.json`) and none of its projections under `.claude/skills/work-loop/` and `.agents/skills/work-loop/` that rewrite them.
- [ ] **AC-0020.** After a fresh process, and after a process killed at either of two points inside `report` (step files and ledger line written before the commit, commit made before the attempt closes), `next` or a repeated `report` returns the open request id or completes the step with no ledger line lost or repeated and no more than one commit for the step.
- [ ] **AC-0021.** `status` writes no file, store record or commit, and names the stage, the open request id and, for an ended run, the recorded reason.
- [ ] **AC-0022.** `next` issues one `review-round` request for each required role of AC-0007, naming the role and, as `exclude_profile`, the author's agent definition, and issues no later request kind until each has reported.
- [ ] **AC-0023.** The path of a raw report or adjudication is derived by the supervisor as `.context/reviews/<run_id>/<round>-<role>-<raw|adjudication>.md`, `report` refuses a `report_path` that differs from it, and `next` refuses `reviews-not-ignored` before issuing a request that names a report path while `git check-ignore -q .context/reviews` fails.
- [ ] **AC-0024.** `report` reads a report file only through a link-refusing open of a regular file of at most 1 MiB, and refuses `report-replayed` when the sha256 of the file is already recorded in the ledger for this run.
- [ ] **AC-0025.** A run stops, `next` then issues no request, and the stop is recorded with a reason, in each case of this closed set: a reviewer or an adjudicator reports unavailable, the classifier marks a raw report `invalid`, or the classifier marks an adjudication `invalid` for any reason code of `review-artifact.py` (`envelope-headings`, `prose-before-envelope`, `audit-numbered-finding`, `indeterminate-present`, `indeterminate-audit-not-none`, `sustained-line-shape`, `legacy-report`); an invalid or indeterminate adjudication is recorded as such and never as clean.
- [ ] **AC-0026.** On each recorded raw report and each recorded adjudication in the equivalence corpus, the supervisor's classifier returns the classification, the reason code of an invalid input, and for a raw report the finding count and `## Not checked` flag, that `review-artifact.py` returns.
- [ ] **AC-0027.** A raw report classified `clean` with no `## Not checked` footer records its reviewer clean with no `adjudicate` request, and every other non-`invalid` report is followed by an `adjudicate` request that names the reviewer's agent definition as `exclude_profile`, and `report` on it refuses an adjudication made with that agent definition.
- [ ] **AC-0028.** A round in which any reviewer's agent definition equals the author's is recorded `weak`, and a weak round is never recorded as converged.
- [ ] **AC-0029.** After a non-weak round that did not converge and left a sustained finding open, with the round total below the allowance of AC-0031, `next` issues `revise` and then a further round.
- [ ] **AC-0030.** After a non-weak round in which every adjudicated finding is refuted or none exists, `next` issues the `consent` request for `spec-approved` and no `revise` or further round.
- [ ] **AC-0031.** When a round is weak, `next` issues the `consent` request for `review-weak`; otherwise, when the round total equals the allowance with no round converged, it issues `review-cap`; and after either it issues no `review-round` or `revise`; the allowance is `max_review_rounds` of `spec-policy.json` (3 when the key is absent) unless a ledger line of `spec-supervisor-gates` sets it.
- [ ] **AC-0032.** A `review-cap` or `review-weak` request names each open sustained finding by a supervisor-assigned identifier and a file reference that is a repository-relative path to an existing regular file followed by an integer line (any other reference is dropped), and lists the answers `approve`, `request-changes` and `reject`, whose fixed text says that `approve` accepts the residue and leads to the `spec-approved` consent request, `request-changes` continues exactly one further round after a revision, and `reject` stops the run with no further request.
- [ ] **AC-0033.** A `consent` request holds only supervisor-fixed text, file digests, supervisor-assigned finding identifiers and checked file references, and every other output field that carries reviewer, author or human text (a request field, a refusal `detail`, a `status` field, relayed lint output) is cut to 512 characters, has its control, escape, line-separator and bidirectional-override characters replaced, and sits in an entry marked `"untrusted": true`.
- [ ] **AC-0034.** `next` on an open `consent` request returns it unchanged with no attempt record and no commit, and `next` on a request that `park` has recorded refuses `parked` while `status` names it.
- [ ] **AC-0035.** `park` on an open `consent` request records in the store, with no commit and no tracked-file change, a record holding the run id, request id, gate, spec digest, plan digest, the `HEAD` commit, the state `pending` and the park time read from the supervisor's own clock.
- [ ] **AC-0036.** `gates` lists each parked `consent` record of this supervisor with its run id, request id, gate, both digests, commit, park time, fixed answer text and a state of `pending` (the recorded digests equal the gate digests of the files at the recorded commit and of the working tree), `stale` or `invalid` (a record that fails its field checks), with no text taken from a reviewer or a human, and writes nothing.
- [ ] **AC-0037.** On each input in the digest corpus, the spec and plan digests in a `consent` request equal the gate digests the work supervisor's `gate_digest` returns for the same bytes, and a refusal input refuses in both; the copy carries `gate_digest`, `_drop_approval_entries`, `_APPROVAL_ENTRY_RE`, `_unsafe`, `_LINE_SEPARATORS`, `_INVISIBLE_CAP`, `canonical_contract`, and the helpers they call from the lint scripts (`is_hidden_char`, `_RUN_CHARS`, `_MAX_ADJACENT_INVISIBLE`, `invisible_budget`, `_HTML_COMMENT_RE`, `_SECTION_HEADING_RE`, `_STATUS_RE`, `extract_status_token`); the corpus holds a plain file, an approval-entry line with each optional suffix and the final period, a wrapped entry, a last exact `## Changelog` among several, a heading or fence after it, blank-run folding, dropped trailing blanks, trailing whitespace on the heading, a changed `Status:` token, a comment before `Status:`, checkbox normalisation in the acceptance section and plan-wide, a fence inside the acceptance section, a lowercase `criteria` heading, edits outside the acceptance section, a missing and a repeated acceptance heading, CRLF, a lone CR, a BOM, a NUL, NFC and NFD forms, no final newline, invalid UTF-8, a hidden-character run at and over the budget, a zero-width joiner run, and 200 seeded generated inputs.
- [ ] **AC-0038.** The admission ledger line records the sha256 of every file under the supervisor's `scripts/` directory at any depth, of `supervisor.toml` and of `spec-policy.json`, leaving out only directories named `__pycache__`, and the `pinned_files` of `supervisor.toml` list the same files, each in the portable form of `supervisor-manifest.v1` (no segment starting with `.`).
- [ ] **AC-0039.** `next`, `report`, `status` and `park` refuse `supervisor-changed` when a file under `scripts/` (other than in `__pycache__`) is modified, added or removed or when `supervisor.toml` or `spec-policy.json` differs from its digest in the spec directory's admission line, `gates` and `answer` compare each parked record's spec directory the same way, `start` compares `pinned_files` with the installed listing, and no verb loads or executes a bytecode file planted beside a pinned module.
- [ ] **AC-0040.** On a recorded corpus of directory trees, the supervisor's pin code and the work supervisor's pin code return the same digests for every file both pin, and the supervisor's differs from it only in refusing the entries AC-0002 refuses.
- [ ] **AC-0041.** `packs/core/pack.toml` and `packs/core/.claude-plugin/plugin.json` carry the same version, one patch above `main`; `python3 tools/changelog.py validate` passes with this release's fragment; and `make build-self` leaves no diff in the `new-spec` projections under `.claude/skills/` and `.agents/skills/`.
- [ ] **AC-0042.** No line this change adds to a file under `packs/` matches a record citation (`ADR-`, `RFC-`, a path under `docs/adr`, `docs/rfc` or `docs/architecture`, or the name of a spec directory under `docs/specs/`); the scan reads added lines only, so text already in a changed file is not counted.

## Assumptions

- Defaulted: Technical: `park` records an open `consent` request as handed to a human in the supervisor's own store with no commit, `gates` lists those records, and `next` refuses `parked` while one waits — the sources fix a sibling store root, a parked `consent` gate and a `parked` refusal, and leave the record's fields, the park time and the refusal's timing open; the record carries the fields `spec-supervisor-gates` reads, and the park time is the supervisor's own clock because the work supervisor's park record has no time field — default: these meanings; if wrong: they change before the gates spec builds on them (settled by: repository owner, eugenelim).
- Defaulted: Technical: a stopped run and an ended run are one state: `status` reports stage `terminal` with a recorded reason (a reviewer or classifier stop reason, `rejected`, `abandoned` or `admitted`), and `next` answers `{"terminal": true}` as `work-supervisor.py` does — default: that merge; if wrong: a stopped run gets its own stage and recovery verb (settled by: repository owner, eugenelim).
- Defaulted: Technical: the six stage values of AC-0005, because page 05 leaves each sibling's `stage` enum to the sibling — default: those six; if wrong: the enum changes in the manifest-listed request shapes (settled by: repository owner, eugenelim).
- Defaulted: Technical: a human-drafted pair starts at `author-spec` like any other, and its author reports the agent definition `human`; the `--author-human` flag of an earlier draft is not built — default: no flag; if wrong: a start flag records the author (settled by: repository owner, eugenelim).
- Defaulted: Technical: the reviewer roles are `adversarial` always and `security` for `security-boundary` or `destructive`, because the spec-stage review requires the infra security pass for a destructive trigger plus an infrastructure-as-code match and this supervisor cannot classify the match, so it requires the pass for every destructive spec; design-intent and frontend roles are not driven — default: two roles; if wrong: the role table gains rows or the destructive rule narrows (settled by: repository owner, eugenelim).
- Defaulted: Technical: an adjudication reported with the reviewer's own agent definition is refused, not recorded weak — default: refuse; if wrong: it is recorded and the run parks (settled by: repository owner, eugenelim).
- Defaulted: Technical: the 512-character text bound, the 16 MiB result bound that matches `work-supervisor.py`, a 1 MiB report bound, a 16-level nesting bound and the 64-character agent-definition bound — default: those values; if wrong: the constants change (settled by: repository owner, eugenelim).
- Defaulted: Technical: the digest copy carries the functions and constants AC-0037 names, because the work-loop scripts are not importable by name — default: a tested copy, compared at closeout and in the corpus suite; if wrong: the copy shrinks to the part the equivalence corpus shows is needed (settled by: repository owner, eugenelim).
- Defaulted: Technical: the pair identity of AC-0017 hashes each file with the protected lines removed by the copied approval-entry drop and a status-line mask, because a full-byte hash would void convergence on the human's own approval commit; every other byte is hashed — default: that identity; if wrong: the mask narrows or the approval commit re-enters review (settled by: repository owner, eugenelim).
- Defaulted: Technical: the last recorded commit is derived from git history as the newest commit that changed the ledger, and the store holds no copy that a check trusts, because a fresh clone must resume from the repository alone — default: history-derived; if wrong: a signed anchor replaces it under `ferryman` (settled by: repository owner, eugenelim).
- Defaulted: Technical: the default branch is read from `origin/HEAD`, and a repository without it refuses `default-branch-unknown` — default: refuse; if wrong: a policy key names the branch (settled by: repository owner, eugenelim).
- Defaulted: Technical: a run pinned under another installed version refuses every verb `supervisor-changed`, and the recovery is to reinstall the pinned version or to remove the ledger in a human commit so that `start` admits a new run on the unadmitted directory, which re-reviews the pair; the work supervisor keeps its pins in a per-run local store and this supervisor commits them in the ledger — default: no migration of a run across versions; if wrong: a `--repin` flag lands in a later spec (settled by: repository owner, eugenelim).
- Defaulted: Technical: a dot-file, or any name outside the portable pin form, under `scripts/` refuses `start` and, when it appears later, is `supervisor-changed`, while `__pycache__` directories are never pinned, never trusted and never a refusal because bytecode writing and loading are off — default: that rule everywhere the pin set is stated; if wrong: the form widens with a new manifest version (settled by: repository owner, eugenelim).
- Technical: the ledger, attempt and store paths — `implementation-discovered`, settled when the first test needs them (settled by: the implementing task).
- Accepted risk: a commit that appends exactly one well-formed ledger line is accepted as a step commit, so the supervisor cannot tell its own step commit from a foreign commit that forges such a line, including a `clean` review line that carries the open request id; the checks of AC-0009 and AC-0016 narrow what a forged line can do and do not close it (settled by: repository owner, eugenelim; not covered by the Brief 1 owner waiver; closed by `ferryman`'s guard and scribe in phase P0 of brief `ferryman-local-delivery`).

- Accepted risk: attempt records and the store live outside commits, so the commit-based check cannot see a deleted park record or a forged attempt record, although both are supervisor-written items (settled by: repository owner, eugenelim; not covered by the Brief 1 owner waiver; closed by `ferryman`'s guard).
