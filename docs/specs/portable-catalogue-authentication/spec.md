## Outcome

Catalogue users can install protected HTTPS catalogues with their existing
bearer, JFrog CLI, or exact-machine `.netrc` setup, while public sources still
work without credential setup. Skills remain independent of AgentBundle, and
no catalogue path copies vendor credentials into AgentBundle state or output.

## What Changes

- Target-bound HTTP access resolution becomes a public `credbroker` library surface — `packages/credbroker/`.
- HTTPS catalogue acquisition moves behind one provider-bound fetch session — `packages/agentbundle/agentbundle/catalogue_fetch/` and `https_catalogue.py`.
- AgentBundle declares a compatible `credbroker` dependency while the credential-brokers user-library floor remains independently deployable — package metadata and projection tests.
- Exact-machine `.netrc` and JFrog CLI delegation join the existing bearer and anonymous HTTPS paths — resolver and fetch-provider modules.
- Current architecture, package design, setup guidance, troubleshooting guidance, and release records describe the portable authentication behavior — established documentation and changelog surfaces.

## Agent Rules

### Always do

- Normalize every host with one profile: ASCII-lowercase, then the standard library's own IDNA codec—the same encoding Python applies when it opens the connection. One profile governs every host comparison in this feature: bearer and `.netrc` origin binding, anonymous requests, `credbroker`'s JFrog profile-to-target prefix match, and AgentBundle's own JFrog origin checks. For every request AgentBundle itself opens, byte identity between the form compared against a credential record, the form a credential is bound to, and the host actually connected to holds by construction rather than by assertion, because the comparison uses the same codec that opens the socket. The delegated JFrog leg is the stated exception: ADR-0136 D6 and D11 place the connection inside the `jf` process, which prepends its own configured platform base, so AgentBundle compares and pins the Artifactory and platform bases but never opens that connection. Host identity on the delegated leg is an explicit accepted residual, recorded alongside the redirect residual AC-0010 already states. A host that will not encode under that profile is an invalid HTTPS target: `credbroker.resolve_http_access` refuses it before provider selection begins, raising `HttpAccessError` with provider class `target` and code `invalid_target_host`, so no provider is reached and no provider state is implied.
- Resolve access once against the initial normalized HTTPS URL and reuse that target-bound result for the descriptor and archive, as required by ADR-0137 D1, D7, and D8.
- Preserve descriptor validation, digest verification, provenance, safe extraction, resource limits, proxy behavior, corporate-CA behavior, and the direct HTTP socket-inactivity bound when routing acquisition through the facade.
- Test isolated AgentBundle, isolated credential-aware skill, ordinary-skill, and co-located user-library deployment shapes before changing either package's compatibility claims.
- Bound and sanitize every subprocess stream and diagnostic before it crosses from a credential or vendor boundary into AgentBundle-visible output.

### Ask first

- Ask the spec owner before changing provider order, unavailable-versus-broken classification, target binding, or the no-fallback rule governed by ADR-0137.
- Ask package maintainers before widening `credbroker>=0.7,<0.8`, changing the supported co-location window, or changing either package's public compatibility promise.
- Ask architecture and security reviewers before adding another credential source, helper executable, credential store, redirect policy, or outbound transport.

### Never do

- Never emit credentials, derived authorization values, usernames, JFrog server identifiers, discovery payloads, `.netrc` contents, or credential-bearing URLs through stdout, stderr, logs, exceptions, receipts, provenance, state, or agent-visible output.
- Never read JFrog credential fields or vendor credential files, pass JFrog credentials to AgentBundle, invoke a shell, or accept an unbound endpoint for delegated acquisition.
- Never make a skill import, invoke, discover, or otherwise depend on AgentBundle.
- Never fall through to a lower provider after a configured provider is broken or after the selected provider fails.
- Never add catalogue credentials to `catalogue.toml`, AgentBundle user configuration, organization defaults, install state, provenance, receipts, or a new AgentBundle credential store.
- Never route local-path or Git-backed catalogue sources through the HTTP resolver.

## Testing Strategy

- **TDD, unit (AC-0004, AC-0005, AC-0006, AC-0007, AC-0008, AC-0009, AC-0010, AC-0011, AC-0012, AC-0013, AC-0014):** The published resolver result types, provider-state matrix, `.netrc` rules, JFrog discovery, endpoint confinement, resource bounds, and redaction have compact input/output invariants and run with controlled environments and subprocess fixtures.
- **TDD, package and integration (AC-0001, AC-0002, AC-0003, AC-0015, AC-0016, AC-0017):** Isolated wheels, user-library projection, import precedence, the fetch-session facade, unchanged catalogue safety behavior, and non-HTTP source routing cross package or transport boundaries.
- **Goal-based checks over built artifacts (AC-0018):** The built packages and real AgentBundle CLI run through anonymous, `.netrc`, and JFrog paths. The JFrog leg uses a compatible official CLI with a disposable profile and loopback service inside a disposable Linux container, with the loopback CA supplied through `SSL_CERT_FILE`; it uses no customer system or real credential.
- **Goal-based documentation checks (AC-0019):** The documentation build and bounded searches reject stale bearer-only claims and credential-bearing examples.
- **Stub accounting:** T1–T4 each carry one exact pytest stub block in `plan.md`, covering every TDD task family. T5 records `no stub (goal-based)`: once T4 lands, the facade already accepts all four providers, so T5 adds no behavioural seam a stub could drive red. T5 is verified by the built-artifact and documentation checks above.

## Acceptance Criteria

- [ ] **AC-0001.** Installing the built AgentBundle wheel into an empty Python 3.11 environment installs `credbroker>=0.7,<0.8`, and imports resolve from that environment rather than the repository checkout.
- [ ] **AC-0002.** A representative credential-aware skill imports and uses the supported `credbroker` public surface in an environment where AgentBundle is absent; a representative ordinary skill imports in an environment where both packages are absent.
- [ ] **AC-0003.** When a compatible installed `credbroker` 0.7 and a vendored 0.6 user-library floor are co-located, normal import precedence selects 0.7 and every public 0.6 skill-facing symbol remains available with compatible call behavior.
- [ ] **AC-0004.** `credbroker.resolve_http_access(target_url, *, env)` returns exactly one public immutable result variant—`BearerHttpAccess`, `JfrogCliHttpAccess`, `NetrcHttpAccess`, or `AnonymousHttpAccess`—or raises `HttpAccessError` with a stable non-secret `provider` and `code`; the function, error, and four result variants are the six new names exported from `credbroker`.
- [ ] **AC-0005.** For the existing bearer and anonymous fixture corpus, acquisition through the fetch-session facade produces the same accepted bytes, redirects, errors, and provenance as the baseline path.
- [ ] **AC-0006.** For every availability combination in the closed provider set, resolution selects the first available provider in ADR-0137 D2 order and performs no catalogue network request during discovery.
- [ ] **AC-0007.** Each configured-but-broken condition in ADR-0137 D4 raises `HttpAccessError` for that provider before any lower provider is evaluated, while each unavailable condition in ADR-0137 D3 permits the next provider.
- [ ] **AC-0008.** One resolution result is reused for a descriptor and its resolved archive; an authentication, HTTP, subprocess, timeout, redirect, size, or output failure after selection produces one terminal error and zero lower-provider attempts.
- [ ] **AC-0009.** `.netrc` resolution accepts only the standard user file and the exact-machine lookup sequence in ADR-0135 D1–D4, including default-port, non-default-port, host fallback, missing match, `default`-only, incomplete, malformed, and unsafe-permission fixtures. The machine key is compared against the target host under the single host-normalization rule in `Agent Rules`, so a Unicode host and its punycode spelling compare equal. A machine key in the file that will not encode under that profile is a malformed record, and so configured-but-broken under ADR-0135 D7; an unencodable target host is not a record defect and is refused earlier, by that same rule. The fixture matrix covers a case-differing record, both spellings of an internationalized host, a label the codec folds lossily (`ß` to `ss`) asserting that the compared and connected forms still agree, and an unencodable host refused as an invalid target.
- [ ] **AC-0010.** Bearer and `.netrc` authorization are sent only to their normalized HTTPS origin—normalized under the single host-normalization rule in `Agent Rules`, with the bound origin and the connected host byte-identical—and survive a same-origin HTTPS redirect. The bearer leg carries its own internationalized-host fixture asserting the bound origin and the connected host are byte-identical under that profile. For every request AgentBundle itself issues—bearer, `.netrc`, and anonymous—a redirect that changes origin or scheme is rejected before the redirected request is sent; withholding the authorization header while still issuing the request does not satisfy this criterion. The delegated JFrog path is out of scope here and is a stated residual: ADR-0136 D11 places redirect handling inside the JFrog CLI process, which AgentBundle neither issues nor observes.
- [ ] **AC-0011.** JFrog discovery uses one bounded JSON profile query, selects the unique longest exact-origin segment prefix or a still-valid explicit server choice, rejects the topology and ambiguity cases in ADR-0136 D2–D5, and rejects JFrog CLI versions below 2.105.0. The profile-to-target prefix match normalizes both sides under the single host-normalization rule in `Agent Rules`, and carries the same internationalized-host and both-spellings fixtures AC-0009 and AC-0010 carry, so a profile and a catalogue URL spelling one host differently still match rather than silently falling through to a lower provider.
- [ ] **AC-0012.** Before `jf api` starts, each delegated URL is proven to be beneath the pinned Artifactory base and its endpoint is derived beneath the pinned platform base; user information, query strings, fragments, dot-segment ambiguity, encoded separators, backslashes, control characters, and endpoint escape produce zero fetch subprocesses. The derived endpoint is never option-like—a leading `-` or `--` is rejected—and is delimited from the option set so no fetched path segment can be parsed as a flag by the child.
- [ ] **AC-0013.** JFrog discovery, version probing, and at most two fetch subprocesses terminate at 10, 5, and 30 seconds respectively, never exceed a 75-second aggregate subprocess budget, use closed stdin and list-form arguments without a shell, and terminate the child before removing partial output. `jf` resolves only to an absolute path found by searching `PATH`, with the working directory and every relative or empty `PATH` entry excluded; a non-absolute or working-directory hit fails closed rather than executing. The resolved target must be a directly executable image: a batch or command-script shim—the shape the npm and Chocolatey distributions install as `jf.cmd` or `jf.bat`—fails closed rather than executing, because the platform services such a target by launching a command interpreter, which would defeat the no-shell rule transitively however the arguments were passed. A refused resolution—non-absolute hit, working-directory hit, or non-executable image such as a `.cmd` or `.bat` shim—is classified by whether JFrog intent is already established, at the same seam ADR-0137 D3 draws for an absent executable. With an explicit JFrog server requested, the refusal is configured-but-broken under ADR-0137 D4 and terminates resolution with code `jfrog_cli_not_executable`, so a deliberately configured JFrog path never degrades silently to `.netrc` or anonymous. With no explicit JFrog server requested, the refusal makes the provider unavailable under ADR-0137 D3 exactly as an absent executable does, and resolution continues, so a user who has a vendor-packaged `jf` shim but no JFrog setup still installs a public catalogue anonymously as AC-0017 requires. The Windows shim fixture drives both branches. Termination escalates to an unconditional kill after a bounded grace period, and that grace and kill are accounted inside the call's own deadline and inside the aggregate budget, so the 10, 5, and 30-second limits and the 75-second total are the outer bounds rather than sums that exclude cleanup. Every delegated subprocess starts in a controlled directory that no catalogue, archive, or untrusted clone content can write to. Termination is scoped to the direct child; whether JFrog CLI 2.105.0 leaves descendants holding the output pipe is an open discovery that T4's real-executable contract test settles, and a positive result takes the controlled-amendment path to tree-scoped termination.
- [ ] **AC-0014.** Version-probe stdout and stderr first fail when either exceeds 8 KiB; discovery stdout first fails above 1 MiB; discovery and each `jf api` stderr first fail above 64 KiB; descriptor output first fails above 1 MiB; and archive output first fails above 256 MiB. The descriptor and archive limits bound the bytes AgentBundle accepts on every leg. On the delegated JFrog leg, the JFrog CLI appends one `0x0a` to a body that does not already end in one, so `jf api` stdout first fails above the limit plus that one byte. Stdout of exactly the limit plus one byte is accepted only when its final byte is `0x0a`, and that byte is then removed as the appended one, so no more than the limit ever reaches descriptor parsing, digest acceptance, or extraction. Every over-limit path terminates and reaps the child before parsing or diagnostic emission, and that reap always runs against an already-terminated process so it cannot extend past the call's deadline, removes partial output, and emits only the applicable stable non-secret failure code. The version probe runs in `credbroker`, so its over-limit, timeout, and execution-failure states carry the resolver-side codes the plan names rather than any AgentBundle-side code. The AgentBundle-side bounds carry their own closed code set—`jfrog_fetch_stderr_too_large`, `descriptor_too_large`, `archive_too_large`, `jfrog_fetch_timeout`, `jfrog_fetch_failed`, `redirect_not_permitted` for the AC-0010 rejections, and `endpoint_not_permitted` for the AC-0012 rejections—exposed as a stable non-secret attribute on the raised fetch error rather than interpolated into its message.
- [ ] **AC-0015.** Canary credentials and credential-derived values are absent from request URLs, subprocess arguments, the environment handed to every child process, captured or emitted stdout and stderr, logs, exception text, install state, provenance, receipts, and agent-visible output for every success, rejection, timeout, and hostile-child fixture. Non-secret JFrog profile metadata may occur only in bounded captured discovery stdout, and the selected non-secret server ID may occur only there and as the value of the bounded `jf api --server-id` argument; neither may reach AgentBundle-visible output or persisted state. A carried proxy variable may hold embedded user information, because dropping it would break the proxy behavior AC-0016 obliges. The child process environment is the single channel exempted for that value and for no other; every remaining channel above still excludes it. A canary fixture places a credential inside a carried proxy variable and asserts it reaches no emitted output, diagnostic, exception text, log, persisted state, provenance, or receipt—including under a hostile child that echoes its own environment, whose captured stream is bounded and sanitized before it crosses into AgentBundle-visible output. Diagnostics may retain only the stable non-secret provider class and failure code required by AC-0004.
- [ ] **AC-0016.** Existing HTTPS descriptor validation, digest verification, safe extraction, archive-member and expanded-size limits, proxy handling, corporate-CA handling, and the 30-second direct HTTP socket-inactivity bound pass unchanged through the new facade. Every request AgentBundle itself opens keeps exact digest verification. On the delegated JFrog leg alone, an archive is accepted when the bytes AC-0014 admits match the expected SHA-256 exactly, or when they match after exactly one trailing `0x0a` is removed, because the JFrog CLI appends that byte to a body that does not already end in one; a mismatch on both candidates fails as a digest mismatch. After a match, only the matched candidate goes on to extraction and to any persisted artifact, so the extracted input is always the verified bytes. The descriptor is JSON, so its parse is unaffected by that byte.
- [ ] **AC-0017.** Public HTTPS sources complete anonymously without credential setup, while local-path and Git-backed sources execute their existing transports without importing or calling HTTP access resolution.
- [ ] **AC-0018.** The installed, built AgentBundle CLI completes representative descriptor and archive acquisition through anonymous, exact-machine `.netrc`, and compatible JFrog CLI paths against disposable local fixtures, with no repository import shadowing, customer system, or real credential. The JFrog leg runs in a disposable Linux container, where `jf api` trusts the disposable loopback CA through `SSL_CERT_FILE`. On macOS, `jf api` trusts only the system keychain, so a private CA must already be there; that is a stated residual, not a property this feature holds.
- [ ] **AC-0019.** The established AgentBundle and credential-broker guides build successfully and describe provider setup, precedence, terminal failures, JFrog CLI 2.105.0, package independence, and troubleshooting without a bearer-only claim or credential-bearing example.
