# Delivery knowledge projection verification ledger

Execution observations for the approved spec and plan. The spec and plan stay
frozen; evidence goes here.

## T1: the read-only feed and pure projector

### Chosen seams (recorded before any behavior was green)

- **Admission seam.** One read-only accessor was added to the Slice 1 module:
  `replay_admitted_frames(raw)` in `_evidence_store.py`. It builds an unopened
  `EvidenceStore` over `os.devnull`, runs the store's own `_index_frames` on the
  bytes the caller supplies, and returns the admitted `(tx, records)` frames,
  the per-kind semantic index, and the superseded receipt IDs. `_index_frames`
  gained one optional output-only keyword, `admitted_frames`, which appends each
  admitted frame and changes no index, identity, or admission decision. The
  feed never calls `EvidenceStore.open()`, so nothing truncates a torn frame.
  A direct byte read with a second admission loop was rejected: it would copy
  the first-wins and `_validate_review_transition` rules and could drift.
- **Modules.** `_delivery_feed.py` (confined reads, snapshot, paging,
  `feed_page`/`render_page`), `_knowledge_projection.py` (pure
  `project_record`), and the CLI `delivery-fact-feed.py`, all under
  `packs/core/.apm/skills/work-loop/scripts/`.
- **Torn frame.** The feed cuts the bytes it read at the last newline before
  replay. The snapshot digest still covers the full length and sha256, so an
  append that completes a torn frame changes the snapshot.
- **Source resolution.** `_find_receipt_source` and `_find_report_finding` from
  `_evidence_store.py` resolve the report and finding; the review-policy
  fingerprint is the report's `lineage.review_policy_fingerprint`.
- **Schemas.** `knowledge-observation.v1` holds the shared identifier, spec
  path, repository path, and untrusted-text definitions; `delivery-fact-feed.v1`
  references them and states the page bounds once.

### Green and deviations

- Fix: the feed cuts the bytes at the last newline before replay. The same
  command then passed. The contract, confinement, projector, and CLI suites
  pass (`test_delivery_fact_feed.py`, `test_delivery_fact_feed_confinement.py`,
  `test_knowledge_projection.py`).
- Deviation (roster): the schema parity suite extends the existing
  `tests/roster/test_delivery_contract_bundle.py` instead of adding a new roster
  file, so no `build-check.yml` step, `STEP_DISPOSITION` entry, or
  `.workspace-prune-protected.toml` entry is needed.
- Deviation (content refusal): the Slice 2 writers already refuse credentials,
  shebangs, and control characters, so a `content-refused` fact cannot be built
  through them. The feed-level test lowers the `knowledge-observation` profile
  cap to reach it; the projector table drives credential and email text directly.
- Deviation (page byte count): the page size is counted exactly, including the
  continuation token length, so a page ends only when the next entry would exceed
  the bound.
- Expected red outside T1: `tests/roster/test_t9a_conformance_rollup.py` projection
  byte-identity fails until the `.claude/` and `.agents/` projections are
  regenerated by self-host, which T1 did not run.
- Unrelated failure seen: `test_loop_engine.py::test_recover_engine_state_tmp_never_tracebacks_and_deletes_only_bad_content[deep-nesting]`

## T2: the read-only candidate mode and per-record quarantine

### Chosen seams (recorded before any behavior was green)

- **Candidate mode.** `project_knowledge.py` gains `--candidates` (a member of the
  existing mutually exclusive mode group) with one extra option, `--continue-from N`.
  It branches before the store is loaded, so it needs no repository root, lock, or
  deadline. The pure entry point is `render_candidates(raw, *, start=0)`; the page
  checks are `parse_feed_page` and `validate_feed_page`, the per-candidate check is
  `candidate_omission_reason`. Every other mode option is refused with it.
- **Page validator.** Self-contained stdlib code that restates `delivery-fact-feed.v1`
  and `knowledge-observation.v1`: patterns, enums, and bounds live in
  `FEED_PATTERNS` and sibling constants, pinned to the canonical schemas by a roster
  test. Integers follow JSON Schema (a bool or a fraction fails, `1.0` passes). The
  4 KiB observation bound, which a schema cannot state, is checked on the canonical
  ASCII serialization.
- **Strict parse and character policy (the deferred Nit).** The page parse reuses
  `_parse_strict_json` and so `_assert_safe_unicode`: controls, DEL, lone surrogates,
  and the bidi embeddings. That function does not cover U+0085, U+2028, U+2029, the
  zero-width characters, or the bidi isolates, so the per-candidate check adds one
  regex over the same class as the schema's text pattern. The candidate check runs
  over every string in an observation (identifiers and provenance included), so it
  still holds if a schema pattern is ever loosened. `RecursionError` is caught in
  `parse_feed_page` only; `_parse_strict_json` itself is unchanged, so `--capture`
  behavior does not move.
- **Frame.** `<knowledge-candidates version="knowledge-candidates.v1" snapshot=".."
  items="K" first="S">`, one fixed line, then per item either a seven-line
  `<candidate ...>` block or an `<omitted ordinal entry reason/>` element, then an
  optional `<continuation ordinal="N"/>`, then the closing tag. Unadmitted and
  unverified-provenance labels, and every identifier, are attributes of the
  `<candidate>` element, escaped with the rule `_render_envelope` uses
  (`html.escape(quote=True)`). Body lines start with renderer-owned labels, and no
  field can hold a line terminator. Omission codes: `privacy`, `unsafe_character`,
  `duplicate`, `oversized`.
- **Quarantine.** Closed reason set in `knowledge_store.py`: `malformed`, `unsafe`,
  `unknown_version`, `policy_invalid`, `inconsistent`, `oversized`, `orphaned`,
  `dependent`, `partition_hidden`, `overflow`. One `_Quarantine` collector per read
  (100 entries, then `{reason_code: overflow, omitted: N}`), a locator that must pass
  `_valid_quarantine_locator` or is replaced by the entry's 1-based position in the
  read. Exclusion lives in new code reached only from the read-only entry points:
  `_read_committed_topic_map_excluding` and `_read_committed_topic_excluding`
  (enquiry, `read_committed_topic`, `read_freshness_source`) and
  `_events_excluding_invalid` through `_load_pending_partitions_excluding`
  (`pending_page`). The shared loaders (`_read_committed_topic_map`,
  `_load_pending_partition_window`, `_validated_event_lines`, `_read_events`,
  `_bounded_topic_records`, `_verify_committed_topic_headers`) are untouched. Three
  shared helpers took an optional keyword that defaults to today's behavior:
  `_observation_partitions(quarantine=)`, `_committed_blob_ids(unsafe=)`, and
  `_validate_pending_request(quarantine)`. Output: `quarantine` list plus a
  separate `knowledge-quarantine.v1` element after the unchanged evidence element on
  enquiry; the drain receipt's `diagnostics` on the pending page.
- **Pending-page closure.** A capture whose disposition line is invalid is excluded
  when the line parses as a disposition naming a well-formed capture id. A line that
  parses as a captured event cannot close anything. Any other invalid line (it does
  not parse, or names no readable target) hides every capture in its partition, with
  a `partition_hidden` entry. `workflow-receipts` keeps `replay_required` because the
  selected-capture check runs on the visible set.

### Green and evidence

- The candidate, quarantine, write-path, and differential-corpus suites pass. The
  corpus (over 500 generated pages: one violation per constraint at every node of a
  valid page, plus coordinated cases) agrees between `jsonschema` and the candidate
  validator on every page.

### Deviations from the task row

- **Differential corpus** lives in `tests/roster/test_delivery_contract_bundle.py`,
  the file T1 already extended, so no CI step or parity entry is added.
- **Revised enquiry tests.** `test_enquiry.py` held three whole-refusal cases that
  the per-record contract changes: map headers that disagree with the topic (now
  excluded on enquiry, still refused by `_committed_v1_map_is_coherent` and by a
  named lookup), a committed symlinked topic (now `unsafe` plus `dependent`; the
  symlinked map stays a whole refusal), and an oversized topic blob (now
  `oversized`; an oversized map stays a whole refusal). The topic-size case was split
  from the map-size case in the process.
- **Map rebuild over an invalid map entry.** It rebuilds from the topic files and
  succeeds before and after this slice, so the invalid-map-entry write-path set
  asserts promotion, capture (writer admission), staging, and activation; the
  invalid-topic set asserts all of them plus the rebuild.
- **Partition files.** Only a partition file whose name fails validation is excluded.
  A symlinked or non-regular partition file, a symlinked kind directory, and every
  capacity or budget refusal stay whole, which keeps the pinned
  `test_ac19_cursor_digest_refuses_non_regular_partition` unchanged.
- `selected_topic_body_bytes` in the enquiry receipt counts the bytes read for a
  topic that is then excluded. The receipt's shape is unchanged.
- The boundary lint failure on T1's `delivery_feed_support.py` came from a ruff
  fix that rewrote its loader as `Path(SCRIPTS) / filename`. The controller
  restored the `os.path.join` form the lint traces, with a `PTH118` waiver; the
  lint passes (158 cases).

### T2 controller review fix

- `_quarantine_reason` mapped every refusal code it did not know to
  `malformed`, so a refusal that does not describe the record (for example
  `replay_required` or `staged_dual_writer`) would have become a per-record
  exclusion. AC-0005 limits exclusion to record faults, so unknown codes now
  propagate. Proof: `test_read_quarantine.py::test_a_refusal_that_is_not_a_record_fault_propagates_instead_of_quarantining`
  passes (3 cases); with the old mapping restored, 2 of its 3 cases fail
  (`deadline_exceeded` already propagated).
