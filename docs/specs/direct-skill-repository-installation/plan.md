## Design (LLD)

- `direct_source_acquisition.py`: credential-free GitHub archive acquisition, Family-1 policy, and injectable deadline/progress seams for direct and catalogue routes.
- `bounded_metadata.py`: lifts unchanged bounded frontmatter/TOML primitives and limits from `catalogue_tooling/okf_discovery.py`.
- `direct_source.py`: direct classification, Family-2 inventory, admission, diagnostics, and normalization entry point.
- `direct_source_state.py`: direct provenance and digest inputs for the existing pack/adapter state writer.
- `statelock.py`: the blessed direct-state mutation boundary; direct writers call `persist_state_locked` and compute the 0.5 floor from the state re-read inside that lock.
- `commands/upgrade.py`: direct-upgrade re-consent.
- `--check` resolution mechanism: **unresolved, and owned by T9.** Two attempts were made and both were withdrawn during pre-EXECUTE review. A `ThreadPoolExecutor` cannot enforce AC22's deadline "against in-flight acquisitions" — `concurrent.futures.wait(timeout=...)` bounds the waiter, not the worker, and non-daemon workers are joined at `shutdown`. Sequential resolution is worse in the case that matters: the main thread sits inside the fetch, so one drip-feeding host hangs a read-only command with no wall-clock ceiling at all, and the "pass the remaining deadline as the acquisition's own bound" idea has nothing to bind to, because E11 (`docs/rfc/0098-direct-skill-repository-installation.md:412`) records that there is no total elapsed-time deadline per acquisition and accepts the slow-drip residual. A mechanism that genuinely bounds a drip therefore needs an E11 erratum introducing a total-elapsed bound and its constant, which is *Ask first*. T9 resolves this when it starts, with that erratum decision as its first step; nothing earlier in the plan depends on it.
- `tools/lint-direct-code-table.py` and `tools/test_lint_direct_code_table.py`: published direct-code-table equality lint and its mutation control.
- The four direct modules above remain at top-level `agentbundle/`, outside the ADR-0056 portable-engine boundary. `packages/agentbundle/agentbundle/catalogue_tooling/diagnostics.py` is the established diagnostic registry owner (not a fifth top-level direct module); T0e adds its `DiagnosticCode` members, `DIRECT_CODES`, and `make_direct_diagnostic` there. `packages/agentbundle/agentbundle/catalogue_tooling/file_safety.py` adds `BoundExceeded(UnsafeContentError)`, carrying the breached budget, so the one confined traversal provides typed attribution. `BoundExceeded` covers **both** bound sites, not only the traversal's entry allowance: `list_confined_regular_files` raises it for the entry budget, and `read_confined_regular_file` raises it at both `max_bytes` overrun paths carrying the per-file-bytes budget — otherwise a per-file breach is indistinguishable from the six other bare-`UnsafeContentError` integrity conditions, and AC33's rule that an integrity refusal is not a budget breach cannot hold. Its byte-identical close-work mirror is `packs/core/.apm/skills/close-work/scripts/file_safety.py`, reprojected to `.agents/` and `.claude/`.
- **T0e API — the contract its stub binds to.** The stub set is otherwise shape-only, because this LLD names module responsibilities rather than callables; T0e's three deliverables are pinned here so its stub is a behavioural red test rather than a presence check. Later tasks receive the same treatment when they start.
  - `BoundExceeded(UnsafeContentError)` in `catalogue_tooling/file_safety.py`, constructed as `BoundExceeded(message: str, *, budget: str, limit: int, observed: int)` and exposing `budget`, `limit`, and `observed` as attributes. `budget` is a plain `str` from the stable set `entries`, `depth`, `files`, `selected-skills`, `per-file-bytes`, `total-bytes` — deliberately not a `DiagnosticCode`, so `file_safety.py` gains no import of `diagnostics.py` and its byte-identical four-tree mirror keeps standing alone. Callers map `budget` to the registered member; AC33's "never by parsing message text" is satisfied because the attribute, not the message, carries the attribution.
  - `DIRECT_CODES: frozenset[DiagnosticCode]` in `catalogue_tooling/diagnostics.py`, written as an explicit frozenset literal of enum members — never a comprehension or a filter over `DiagnosticCode`, because AC31's `tools/lint-direct-code-table.py` reads this file by `ast` parse without importing it and can only see literal members. There is deliberately **no member count** here. Two were written during review — nine, then twelve — and both were stale on inspection, because AC27 separately names malformed owner/repository, bare `main`, hex-shaped tag, interpreter-floor, inactivity limit, download limit, archive-filter failure and missing remote `--yes`, and AC21 names missing re-consent, unknown old capabilities and direct-pack selectors. A number in this position ages every time a criterion adds a refusal. T0e's **first step** is therefore to enumerate the set by walking every AC that mandates a registered refusal — AC3, AC5, AC6, AC8/AC18, AC10, AC11, AC13, AC14, AC20, AC21, AC23, AC27, AC31, AC33, AC34, AC38 — and to record that walk beside the frozenset so a later reader can re-derive it. AC31's lint is what enforces exact coverage; this LLD pins the derivation, not a total. T0e enumerates the full set, which by AC31 is exactly the codes direct-route refusals emit.
  - `make_direct_diagnostic(code, severity, message, *, pack=None, path=None, line=None, col=None, remediation=None) -> Diagnostic` in `catalogue_tooling/diagnostics.py`, mirroring the established `catalogue_tooling/lint.py:160 _diag` shape and returning `catalogue_tooling/results.py:20 Diagnostic`. It raises `ValueError` when `code not in DIRECT_CODES` — `ValueError` rather than a new exception type or a `CatalogueError`, because an unregistered code is a programmer error at a registration boundary, not an admission refusal, and `UnsafeContentError` already subclasses `ValueError` so the direct route needs no second error family.
- Normalization flattens an E14 category level into `skills/<leaf>/`, because `_project_direct_directory` projects only one `skills/` level; the orphan sweep must fail closed rather than delete direct skills when an old reader rejects state 0.5.

### T3: Classify roots and inventory

**AC:** AC1–AC2, AC14–AC17, AC25, AC32–AC36  
**Depends on:** T0e, T4a  
**Verification:** TDD.

**Tests:** shape matrix, measured paths rooted only at `skills/` plus direct-pack root `pack.toml`, or root `SKILL.md` plus payload directories (never repository context), and the Family-2 measure order (enumeration budgets, then read per-file → total). **T3 owns the diagnostic-attribution mechanism.** `list_confined_regular_files` performs the single confined traversal and receives the remaining entry allowance on each call; when it exceeds an allowance it raises `BoundExceeded(UnsafeContentError)` carrying the breached `entries` budget, and callers map that typed value to the registered code without parsing text or walking first. A bare `UnsafeContentError` is an integrity refusal; an untraversable source or an admission-time source change maps to its distinct registered direct code without an offending-path requirement. Named files must be read, never enumerated, while `root=<source>, directory=<payload dir>` makes AC34's binding achievable.
