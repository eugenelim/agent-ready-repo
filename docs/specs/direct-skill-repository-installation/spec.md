# Spec: Direct skill repository installation

- **Status:** Approved
- **Owner:** eugenelim
- **Plan:** [`plan.md`](plan.md)
- **Constrained by:** RFC-0098; RFC-0085; RFC-0031; RFC-0034; ADR-0036; ADR-0039; ADR-0100
- **Shape:** mixed

## Objective

Validate, install, inspect, update, and remove one skill or a skills collection from an explicit local path or hardened GitHub `git+https` source. Direct admission is deterministic and shared by validation and install preflight; it establishes admissibility, not safety.

## Terms

- **Direct pack:** root `pack.toml` plus `skills/<name>/SKILL.md`; one versioned pack lifecycle.
- **Collection:** an E14 collection root (`skills/` or `.claude/skills/`) holding skill envelopes, optionally grouped one level deep by category, with no root `pack.toml`; each selected envelope has a manifestless lifecycle.
- **Manifestless:** a direct skill whose synthetic identity is its validated name; its sentinel version is internal.
- **Direct identity:** `(source-kind, canonical source, source-path)`.
- **Measured envelope:** before AC14 admission, `SKILL.md` plus regular, non-hidden files beneath `scripts/`, `references/`, `assets/`, and `evals/`; a direct pack also measures its root `pack.toml`. For a collection or direct-pack child, another child entry, hidden entry, or link-like/special file refuses. The fixed root marker set (`catalogue.toml`, `packs/`, `pack.toml`, `SKILL.md`, `skills/`, `.claude/skills/`) is always probed and never becomes ignored context. Other root entries for a root single, local path already at a skill, direct pack, or collection are repository context and are ignored, including hidden files and directories. **Admitted envelope** is the measured envelope surviving AC14; it is the set AC13 digests.
- **Skill envelope:** the directory a skill's own content hangs from — the `SKILL.md`-holding directory beneath a collection root for a collection or direct pack, and the source root itself for a root single or a local path already at a skill. E15 measures path depth from it in every shape.
- **Capability drift:** missing, malformed, or unrecoverable old capability data derived from an installed projection; it is `unknown`.
- **Footprint drift:** the independent numeric `DRIFT` value in lifecycle display; it never means capability drift.

## Boundaries

### Always do

- Preserve catalogue selector precedence, normalize admitted direct sources through the canonical pack pipeline, and frame publisher-derived output as untrusted data.

### Ask first

- Raise a Family-1/Family-2 bound, change the digest algorithm/version, admit a redirect host, or change the supported runtime-floor table or `requires-python`.

### Never do

- Add selection UIs, recursive discovery, hidden discovery beyond E14's single admitted `.claude/skills/` collection root, transports/VCS hosts, a registry, runtime dependencies, direct-pack dependencies/recipes, non-skill primitives, a state hierarchy, lockfile, preview, or direct `validate --deep`.
- Execute publisher content, reclassify `catalogue+https`/`archive+https`, change existing field meanings within manifest schema major 1, or repair unrelated catalogue behavior.

## Testing Strategy

**TDD:** shape/admission, normalization parity, bounds, digest/state, diagnostics, and no-write controls.  
**Manual QA:** built `validate`, install, upgrade, uninstall, receipts, confirmation, `list-installed`, and `show`.  
**Goal checks:** T0 spikes and documentation build/link checks.

## Acceptance Criteria

- [ ] **AC1 — Exact shape classification.** After resolution, recognize the canonical-pack bypass; catalogue only with both `catalogue.toml` and `packs/`; and direct pack, collection, root single, and local-path-at-a-skill forms. Refuse partial catalogue, empty root, `packs/` beneath a direct root, a childless collection root, and hidden/unsupported/nested/overlap forms within an applicable child envelope. Candidate-path selection is the collection root plus root `pack.toml` for a direct pack, the collection root for a collection, or root `SKILL.md` plus the four payload directories for a root single/local skill. Ignore root repository context, including hidden files and directories, for root-single/local-skill, direct-pack, and collection shapes. Root-single/local-skill identity uses the frontmatter name.
- [ ] **AC2 — Collection root grammar and envelope identity.** The collection root is `skills/` or `.claude/skills/` per E14; a repository holding both refuses as ambiguous and names both paths. Under that root a direct child holding `SKILL.md` is a skill envelope and a direct child holding none is a category directory whose own `SKILL.md`-holding children are envelopes; exactly two levels are recognised, a third refuses, a category directory holding neither a skill envelope nor `SKILL.md` refuses, and the two kinds may be mixed. Collection and direct-pack identity is the **leaf** envelope directory name, which must equal the frontmatter name; a collection whose envelopes do not have unique leaf names refuses at classification, naming the duplicated leaf and both paths, before any selection or collision check.
- [ ] **AC3 — Source grammar and revision pinning.** Accept explicit local paths or GitHub-only, credential-free `git+https`; reject invalid owner/repository/ref syntax, dot segments, query, fragment, controls, invalid URL components, and bare/defaulted `main`. Percent-encode every owner/repository/ref component with an empty safe set and validate the re-parsed requested `https://github.com/<owner>/<repo>/archive/...` URL. Read the full 40-hex SHA from `pax_global_header`; reject absent/malformed values, expand 7–39-hex refs only when it matches, and require a 40-hex ref to equal it case-insensitively. Record that SHA as `source-revision` and pin branches/tags to it.
- [ ] **AC4 — Stored-provenance request construction.** AC3's grammar governs every request built from **stored** provenance, on the status route and the upgrade route alike: the exact string that passed the grammar is the string the request is built from, with no re-canonicalisation, normalisation, or re-parse between validation and request. A direct row never takes the legacy absent-or-sentinel-source inference branch that resolves through the default chain; a direct row whose stored canonical source is absent or fails the grammar refuses rather than resolving.
- [ ] **AC5 — Acquisition bounds and runtime floor.** Apply E11’s redirect equivalence policy. Apply E11 Family 1 before classification and Family 2 in its two phases: enumeration (entries, depth, files) then read (per-file, total); overlapping limit+1 fixtures assert the first breached code only for bounds in the same phase. E11 owns the runtime-floor table, decompressed-side counter, and inactivity timeout values. Flags, environment, and configuration never raise either family. `packages/agentbundle/pyproject.toml` is advisory; `direct_source_acquisition.py` must refuse before its first `tf.extract` using the E11 `sys.version_info` guard. Both credential-free routes consume these constants and guard; preserve the credentialed descriptor route’s same-origin authorization behavior.
- [ ] **AC6 — Archive extraction and link policy.** Case-fold collisions and device/FIFO refusal apply to both credential-free routes; symlink and hard-link member refusal is direct-only. Before each write validate the library-resolved `TarInfo.name`/`.size` destination, never a reconstructed name; independently require each admitted `linkname` to be relative and in-root. Reject absolute paths, `..`, Windows separators, or escaping destinations/links; preserve pax global attributes; extract remaining members one at a time with `filter="data"` and without ownership restoration. Direct post-extraction inventory also rejects links and junctions/reparse points; catalogue GitHub archives may retain symlinked members and must still install. Every refusal removes its temporary tree.
- [ ] **AC7 — Source-aware CLI grammar and help.** `install` preserves catalogue `--pack`/`--profile` and accepts direct positional sources plus collection `--skill`/`--all-skills`; `validate` accepts supported source directories and `--format json`; `list-installed` accepts default-off `--check` and `--no-check`; and `upgrade` has a required `--pack`/`--all` mutually exclusive group, with `--pack`/`--all` relaxed only for the accepted standalone manifestless `upgrade --skill S` form. Help for install/validate/upgrade/uninstall/list-installed describes these direct forms and `upgrade --accept-new-capabilities`. `validate --format json` and `install --dry-run` report shape.
- [ ] **AC8 — Explicit collection selection.** An unselected manifestless collection refuses before mutation or picker, lists bounded validated names/descriptions, and prints source-preserving `--skill` and `--all-skills` recovery commands. Duplicate/unknown selections and selectors on a direct pack refuse with exit 1.
- [ ] **AC9 — Selector compatibility.** Preserve catalogue selectors and `upgrade --pack P --skill S` filtering. Standalone `upgrade --skill S` accepts repo/user/local only for manifestless skills; a bare primitive upgrade is an `upgrade` invocation that has neither that accepted standalone form nor `--pack` nor `--all`. `--accept-new-capabilities=<pin>` is valid only for that manifestless route and a direct-pack `upgrade --pack P` identified from direct state; it confirms only the computed new capabilities for the displayed pin, never via `--yes`, and remains invalid for catalogue pack upgrades and `upgrade --all`. `upgrade --all --scope repo|user` upgrades every installed direct or manifestless row from recorded provenance. It computes re-consent for every row **before any write**; if any row's capabilities changed it refuses the whole invocation with exit 1, names each changed row and its per-row recovery command (`upgrade --skill S` for manifestless, `upgrade --pack P` for a direct pack), and upgrades nothing. Partial application is never permitted, because AC28 forbids the staging and rollback that would make it recoverable. Retain pack-upgrade scopes. Refuse with exit 2 bare upgrade/uninstall, bare primitive upgrade, `upgrade --pack P --scope local`, bare install, conflicting pack/profile, and pack/profile with a direct source; move catalogue route presence/exclusivity checks to the install handler.
- [ ] **AC10 — Direct manifest contract.** A direct `pack.toml` must declare `schema = 1`; omission fails closed. Admit only its schema-1 skills-only subset and reject unknown keys/content, dependencies, recipes, and non-skill declarations. Preserve default scope/local opt-in/no manifest adapter restriction and CLI precedence; catalogue manifests retain implicit v1. Add `schema` as `{"enum": [1]}` to `contracts/pack.schema.json` and its bundled `_data/` copy in byte parity, and enforce unsupported-major refusal in baseline code. Do not change existing field meanings within schema major 1 or merge schema/state version namespaces.
- [ ] **AC11 — Manifestless identity and collision.** Use the validated skill name as manifestless identity; keep its sentinel internal and prohibit publishers from claiming it. Same-name direct-source and direct/other-source collisions at one adapter refuse in either direction, where same name is NFC-normalized, case-folded equality checked in preflight; `--force` never resolves them.
- [ ] **AC12 — State 0.5 and confinement.** Read 0.4/0.5; write `max(existing, 0.5 when a mutation adds/updates a direct row, else 0.4)` and never downgrade 0.5. Direct identity excludes revision/digest and refuses missing canonical source. Allow `source-kind` `pack` (display `pack`) and `skill` (display `manifestless`); direct-pack `source-path` is absent, while manifestless `source-path` is validated relative POSIX and never empty. Serialize provenance after `source-revision` in this exact order: `source-kind`, present `source-path`, `source-digest`, then `install-route`. Re-establish root confinement before every join. Store repo-scope in-repository sources relatively and refuse out-of-repository sources. Re-derive old capability data from the projection; capability drift is `unknown`. A pinned old reader must refuse 0.5 and direct the user to reinstallation.
- [ ] **AC13 — Content-only digest.** Store `sha256-1:<64 lowercase hex>` over the content-only preimage defined by RFC-0098 E2, which supersedes D4’s execute-byte field. Refuse lifecycle comparison/upgrade for another prefix and direct the user to reinstallation; never recompute or rewrite it. A categorised envelope contributes its **full relative path** from the source root to the digest preimage, never the leaf-normalized identity, so two envelopes sharing a leaf name cannot collapse to one preimage entry; a direct `pack.toml` likewise declares the full relative path. Commit independently derived literal vectors for length-prefix ambiguity, non-NFC refusal, and mtime/ownership stability. Exclude executable mode from updates.
- [ ] **AC14 — Shared, non-bypassable admission.** Validation and install preflight use one direct entry point and yield identical diagnostics. Refuse links, special/nonregular entries, traversal/absolute/platform-poisonous paths as named by the existing pack-tooling validator, case-fold collision, Family-2 breaches, malformed envelope/manifest/metadata, invalid identity, and source conflict. Source conflict includes a resolved source root lying inside the resolved projection target for the selected scope, and a source bearing catalogue markers: a catalogue repository takes the catalogue route and the direct route refuses it with recovery naming that route. Flags, environment, and configuration never bypass mandatory failure/conflict; per-entry diagnostics name the path. Refuse non-NFC logical paths before digest and normalization.
- [ ] **AC15 — Single-observation primitive.** Never follow a direct-source symlink; use exactly one `read_confined_regular_file(..., max_bytes=1 MiB, include_mode=True)` call per direct file, including a measured direct-pack root `pack.toml`, as the sole direct-path observation primitive—never `sha256_confined_regular_file` or an intervening `stat`, except the named candidate-probe carve-out in AC34—so that call supplies digest, mode, and normalized bytes. The byte string returned by that read is the byte string written to the normalized tree; no direct source file is opened twice on any route. Family 2’s 1 MiB per-file bound applies to every direct file, including `SKILL.md`, and dominates the lifted 2 MiB `max_skill_bytes` and 1 MiB `max_pack_toml_bytes`, which remain unchanged for the catalogue caller but are never reached on the direct route. Its bounds allow values equal to their limits and refuse only a value greater than its limit; AC32 owns the measured content and AC33 its budgets. Any enumeration must carry an entry bound, because `max_files` alone does not bound a directory-only tree.
- [ ] **AC16 — Bounded metadata parsing.** `bounded_metadata.py` lifts unchanged `_parse_frontmatter`, bounded `tomllib`, and the limits named in `catalogue_tooling/okf_discovery.py`, operating on bytes already obtained by the confined read; tags, anchors, aliases, and unknown top-level keys refuse. D5 owns the permitted top-level field set. A fresh direct-module import must leave `yaml` absent; admission and digest must be byte-identical with or without PyYAML.
- [ ] **AC17 — Architecture-regression controls.** These static AST controls are architecture-regression tests on AgentBundle’s own direct modules, not scans of publisher payloads: refuse an `Import`/`ImportFrom` of `subprocess` or `runpy`, and an `ImportFrom` of `os` naming any execution-name member; refuse an `ast.Attribute` on an `os` binding whose attribute is in the explicit execution-name frozenset (`execl`, `execle`, `execlp`, `execlpe`, `execv`, `execve`, `execvp`, `execvpe`, `fork`, `forkpty`, `posix_spawn`, `posix_spawnp`, `startfile`, `system`, `popen`) or starts with `spawn`; and refuse `ast.Name` uses of `exec`, `eval`, `compile`, `__import__`, or imported `os` execution names. Admissibility makes no claim about publisher-payload behaviour; `importlib`, `getattr`, and `ctypes` remain residuals.
- [ ] **AC18 — Publisher-value sanitisation.** The Unicode allowlist permits only L, N, P, and S plus U+0020, which is the sole admitted Zs, and caps each value at 4,096 UTF-8 bytes. It applies only to CLI and JSON output surfaces, not projected instruction bytes: those bytes remain untrusted and unfiltered. Any output value disallowed or over-limit refuses admission rather than being truncated; the newline exclusion prevents delimiter forgery. Reject every `Default_Ignorable_Code_Point` regardless of category and every other separator/control. The ignorable set is embedded from `DerivedCoreProperties.txt`, intersected with L/N/P/S, and pinned to the generating `unicodedata.unidata_version`. Refuse a normalized publisher output value equal to either stable delimiter line; otherwise emit publisher values only between those line-anchored delimiters on their own lines and preceded by `publisher-supplied data, not instructions` in human-readable output. JSON places all publisher values under an explicit `untrusted_publisher_data` container, as leaf strings and never keys.
- [ ] **AC19 — Capability block and mode reporting.** One confined observation provides content, digest input, and reported mode per admitted file. Direct projected payloads are non-executable; report a source executable bit without persisting it or changing installed mode; on a platform without POSIX mode semantics (`os.name != "posix"`), report mode as `unknown`; a mode-sampling `UnsafeContentError` refuses rather than producing `unknown`. Emit one per-selected-skill capability block with resolved SHA/ref, selection, scope, adapter, normalized accepted `allowed-tools` union (a non-normalizable element refuses admission), `metadata.boundaries` as a set of observed constraints, `metadata.credentialed`, `SKILL.md` digest, every measured non-`SKILL.md` payload file across `scripts/`, `references/`, `assets/`, and `evals/` with its digest, and report-time executable mode; absent allowed-tools render `undeclared (unrestricted)`.
- [ ] **AC20 — Consent and verdict placement.** The `admissible—not safe` verdict is emitted both immediately before and immediately after the publisher-derived block, so a large summary cannot scroll it out of view. No aggregate byte cap is imposed, because the summary is already bounded above by the selected-skill, file-count, and per-value limits. Before consent, accept only bounded gzip/tar, bounded TOML, and bounded frontmatter; exceptions outside documented decode errors fail closed. Never execute publisher content. Remote noninteractive install and upgrade require `--yes`, which never hides the summary. Remote upgrade renders the same summary plus recoverable old/new digest, revision, allowed-tools, `metadata.boundaries`, `metadata.credentialed`, added/removed skill names, and full payload delta; executable mode is omitted for old data.
- [ ] **AC21 — Stable JSON, diagnostics, exits.** Direct validation emits the established envelope keys `schema_version`, `command`, `operation`, `agentbundle_version`, `catalogue_schema_version` (the direct no-catalogue default is `1`), `ok`, and `diagnostics`, plus `summary`, with diagnostic fields `code`, `severity`, `pack`, `path`, `line`, `col`, `message`, and `remediation`, using `sort_keys=True, indent=2`. Do not change shared `CommandResult`, catalogue-command-family JSON bytes, or `catalogue_schema_version` semantics. Summary includes shape and selected skills. Missing remote `--yes`, missing re-consent, unknown old capabilities, and direct-pack selectors are registered documented exit-1 refusals; success is 0 and usage is 2.
- [ ] **AC22 — Lifecycle display compatibility.** Receipts report kind, source, resolved revision, digest, scope, adapter, and matching commands. Add `KIND` only when necessary and preserve pack-only table-byte identity; `list-installed` JSON always includes `kind` and increments its own schema version as required, while AC21 preserves catalogue-command-family JSON. Direct rows render `STATUS` `unknown` and issue no outbound request unless `--check` is passed; `--no-check` omits `LATEST`/`STATUS` as it does today. Direct rows rendering `unknown` because no check was requested are excluded from `--updates-only`, which would otherwise list every direct row on every invocation; a row that resolved under `--check` and is genuinely `unknown` is included. Each `--check` request is a credential-free `git+https` acquisition and is subject to E11's Family 1 bounds, redirect equivalence, and runtime floor in full; requests are deduplicated by canonical source, and any resolution failure renders `unknown`. Under `--check`, the stored canonical source must pass AC4, which owns the no-re-canonicalisation rule for every request built from stored provenance; a grammar failure or local/non-GitHub stored value renders `unknown` with no request. For manifestless rows, show `INSTALLED`/`LATEST` as `—`, stored canonical source in conditional `SOURCE`, `STATUS` as `up-to-date`, `upgrade-available`, or `unknown`, independent numeric footprint `DRIFT` (`0` when none), and no reachable `ahead`; JSON/show omit version. Footprint drift never compares source digest.
- [ ] **AC23 — Author documentation and prompt.** Deliver the format reference, how-to, install-routes, CLI reference, docs-site install updates, and `docs/architecture/security.md` current-state update. Include route/help examples, a local-path-only coding-agent prompt (`--dry-run`/`validate` allowed; remote install remains a human action), a direct diagnostic-code table that publishes measured-path-integrity plus the six per-budget `DIRECT_CODES`, stable external raw schema URL, and no RFC/ADR/spec identifiers; record that commit-pinned remote provenance remains bounded by the configured TLS trust store; exercise every documented command with a fixture.
- [ ] **AC24 — Normalization parity.** For each direct shape, hand-author tracked canonical-equivalent and expected-normalized fixtures; their repo/user projections and per-file plans must be byte-identical through both renderers. For local scope, projection, exclude-block, and state location must match. Never generate canonical, direct, or expected-normalized fixtures with code under test.
- [ ] **AC25 — No write before admission.** For any mandatory direct-source refusal, target, adapter directories, state, and local `.git/info/exclude` remain byte-identical and no temporary acquisition/normalization tree survives; create, modify, remove, empty-directory, and mode changes are all prohibited.
- [ ] **AC26 — Sentinel absence and non-comparison.** Human-readable output and JSON never expose `0.0.0` or `+agentbundle`; `manifestless` remains a permitted kind label. Decide updates by digest only: unchanged digest with changed recorded version offers none; changed digest offers one.
- [ ] **AC27 — Diagnostic parity and fail-closed admission.** Every mandatory refusal emits an offending-path diagnostic constructed from `DiagnosticCode`; unregistered strings cannot reach users. Before a root exists, use the validated source string as `path`. Cover malformed owner/repository, bare `main`, a hex-shaped tag that cannot safely be classified as an abbreviated SHA, interpreter-floor, inactivity/download limits, archive-filter failures, missing remote `--yes`, measured-path integrity, and one registered member per AC33 budget: entries, path depth, file count, selected skills, per-file bytes, and total bytes. That integrity code and those six per-budget codes are `DIRECT_CODES` members and appear in AC23/AC31’s published table. Catalogue-route Family-1 refusal raises `CatalogueError(message, code: DiagnosticCode | None = None, remediation: str | None = None)` carrying the registered diagnostic and recovery. Validate and install preflight must emit equal `(code, path, message, remediation)` for a failure; incomplete mandatory checks refuse.
- [ ] **AC28 — Interrupted-install post-condition.** Add no transaction/staging/rollback/repair/reconcile extension. A local-scope state-write failure rolls back. A hard interruption after projection and before direct-row state write may leave unowned projection files; `uninstall --skill` requires an owning row. At every scope, install/list surfaces unowned projections; retry follows footprint/ownership controls, and local hard-kill recovery requires manual removal. Promise an uninstall receipt command only when the row exists.
- [ ] **AC29 — Security-checklist evidence.** Before merge, record resolved path/file, outbound-acquisition, supply-chain, exceptional-condition, and agentic-skills findings for this boundary.
- [ ] **AC30 — Upgrade capability re-consent.** Any direct manifestless or direct-pack upgrade triggers re-consent when the normalized `allowed-tools` state differs, including declared-to-undeclared; absence is the `undeclared (unrestricted)` state and is named in the computed addition set. It also triggers for `SKILL.md` digest inequality, any inequality of the admitted skill-identity set, any per-file digest/set changes below `scripts/`, `references/`, `assets/`, or `evals/`, any inequality of the observed `metadata.boundaries` constraint set, or any inequality of the normalized `metadata.credentialed` value, including absence. A remote run still requires `--yes`; the accepting remote run is SHA-pinned, and a local accepting run supplies the refusal-printed digest pin in `--accept-new-capabilities=<pin>` and refuses if the recomputed pin differs. Name every difference and no unchanged tool; it confirms nothing implicitly. Re-derive old data from the installed projection; each adapter must round-trip compared `allowed-tools`, `metadata.boundaries`, and `metadata.credentialed` losslessly or capability drift is `unknown`, refuses even with the flag, and directs reinstallation. Unchanged capabilities proceed under the applicable confirmation rule without the flag.
- [ ] **AC31 — Diagnostic-code coverage.** `DIRECT_CODES` is an explicit frozenset subset of `DiagnosticCode`, including measured-path-integrity and distinct entry/depth/file-bound members. Across committed direct fixtures, every emitted direct `code` equals the `.value` of a `DIRECT_CODES` member, exactly covers that set, and is reachable; `make_direct_diagnostic` accepts a `DiagnosticCode` parameter and rejects codes outside `DIRECT_CODES`. `tools/lint-direct-code-table.py` reads `DIRECT_CODES` from the worktree source by `ast` parse rather than importing it, so a stale editable install or an unrelated copy on `sys.path` cannot satisfy the check; it parses the published direct diagnostic-code table and asserts set equality.
- [ ] **AC32 — Measured content of the shape.** Measurement covers only the content the shape selects, in two kinds. **Enumerated directories:** the E14 collection root (`skills/` or `.claude/skills/`) for a collection or direct pack; `scripts/`, `references/`, `assets/`, and `evals/` for a root single/local skill. **Named files:** root `SKILL.md` for a root single or local path already at a skill, and root `pack.toml` for a direct pack; a collection has none. A named file is observed only by AC15's single confined read and is never enumerated—it is known by path, contributing one file and its bytes to the shape budgets. Directory content is enumerated under confinement with the resolved source root as the confinement root. Repository context is neither walked nor counted, and is never normalized, hashed, reported, or projected.
- [ ] **AC33 — Shape budgets and their diagnostics.** Shape-wide budgets are 5,000 entries, 1,000 files, 500 selected skills, 1 MiB per file, and 25 MiB total, each accumulated across every enumerated directory and named file; path depth is bounded at 12 relative to **each skill envelope** per E15—never relative to the enumeration root, so category grouping and the choice of collection root cannot change it—and is a per-envelope maximum, never a consumed allowance. A value equal to a limit is admitted; only a greater value refuses. Each budget has its own registered `DIRECT_CODES` member and is independently reachable. Each refusal is attributed to its registered member without parsing `UnsafeContentError` message text. An entry-integrity refusal—link-like, reparse point, special, non-regular, or uninspectable—is **not** a budget breach: it carries its own registered member and names the offending path. A budget breach names the breached budget and its limit.
- [ ] **AC34 — Measured-path integrity.** Before any enumeration or read, use a named `lstat`/reparse-point probe carve-out—one named function in one named module, whose result may only produce a refusal and may never supply mode, size, digest, or admitted bytes—to refuse with a registered diagnostic when any fixed root marker (`catalogue.toml`, `packs/`, `pack.toml`, `SKILL.md`, `skills/`, `.claude/skills/`) or any of AC32's measured paths is link-like, a reparse point, or the wrong type for its kind. The confinement root is always the resolved source root and only traversal starts at an enumerated directory; root entries outside AC32's measured set remain ignorable context, and a link-like root entry that is not a measured path is ignored rather than refused.
- [ ] **AC35 — Corpus admission evidence.** Against a recorded corpus of at least fifteen real public skill repositories, classification and both bound families produce one recorded verdict per repository, committed as a fixture table carrying each repository's shape and its measured entries, depth, files, selected skills, largest file, and total bytes. Every refusal is attributable to a named shape exclusion or a named budget; an unclassified or unattributable refusal fails this criterion. The table is regenerated and re-asserted whenever a bound or a shape rule changes.
- [ ] **AC36 — Budget cost ceiling.** Family-2 budgets are legibility and sanity bounds, not the resource control — Family 1 owns resource exhaustion at the transport, before classification. Their **cost ceiling** is 5 seconds wall-clock and 256 MiB resident, measured with every Family-2 budget simultaneously at its limit on reference hardware; a proposed budget whose measured cost exceeds that ceiling is refused rather than negotiated. An admitted repository measuring above half of any budget is reported with both the corpus maximum and the measured cost at that limit; the report surfaces the conflict and never itself raises a bound, because a bound that tracks the corpus tracks the ecosystem rather than the threat. Raising any budget remains *Ask first*, and deciding an input is out of scope is an equally valid outcome.

## Assumptions and discovery predicates

- `read_confined_regular_file(..., include_mode=True)` samples bytes and mode from one validated descriptor (`packages/agentbundle/agentbundle/catalogue_tooling/file_safety.py`).
- `catalogue_tooling/okf_discovery.py` owns the lifted bounded-metadata limits; Family 2 supplies the stricter direct per-file limit.
- `list-installed` JSON carries its own `schema_version` (`packages/agentbundle/agentbundle/commands/list_installed.py`).
- `https_catalogue.py`, rather than `catalogue.py`, owns descriptor-route resource constants.
