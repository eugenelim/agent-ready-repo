- **Constrained by:** RFC-0098; RFC-0085; RFC-0031; RFC-0034; ADR-0036; ADR-0039; ADR-0100

## Objective

Validate, install, inspect, update, and remove one skill or a skills collection from an explicit local path or hardened GitHub `git+https` source. Direct admission is deterministic and shared by validation and install preflight; it establishes admissibility, not safety.

## Terms

- **Direct pack:** root `pack.toml` plus `skills/<name>/SKILL.md`; one versioned pack lifecycle.
- **Collection:** an E14 collection root (`skills/` or `.claude/skills/`) holding skill envelopes, optionally grouped one level deep by category, with no root `pack.toml`; each selected envelope has a manifestless lifecycle.
- **Manifestless:** a direct skill whose synthetic identity is its validated name; its sentinel version is internal.
- **Direct identity:** `(source-kind, canonical source, source-path)`.
- **Measured envelope:** before AC14 admission, every regular, non-hidden file in the skill envelope's subtree; a direct pack also measures its root `pack.toml`. A hidden entry or a link-like/special file still refuses. The envelope is deliberately **not** an allowlist of `scripts/`, `references/`, `assets/`, and `evals/`: the Agent Skills specification describes the folder as "a directory for supporting files" and its own worked example places `reference.md` and `examples.md` at the envelope root, so an allowlist refuses the specification's own example. Measured against 2,548 real envelopes, 11% carry an entry outside those four directories — most often `examples/`, `README.md`, or `LICENSE.txt` — and because one non-conforming envelope refused its whole repository, that 11% refused 18 of 20 repositories including `anthropics/skills`. Stripping the extras instead is worse than refusing: 61% of those envelopes have a `SKILL.md` that names the stripped file, so stripping converts an install-time refusal into a runtime failure. Volume is bounded by AC33's budgets, which bound it far better than a filename allowlist can. The fixed root marker set (`catalogue.toml`, `packs/`, `pack.toml`, `SKILL.md`, `skills/`, `.claude/skills/`) is always probed and never becomes ignored context. Other root entries for a root single, local path already at a skill, direct pack, or collection are repository context and are ignored, including hidden files and directories. **Admitted envelope** is the measured envelope surviving AC14; it is the set AC13 digests.
- **Skill envelope:** the directory a skill's own content hangs from — the `SKILL.md`-holding directory beneath a collection root for a collection or direct pack, and the source root itself for a root single or a local path already at a skill. E15 measures path depth from it in every shape.
- **Capability drift:** missing, malformed, or unrecoverable old capability data derived from an installed projection; it is `unknown`.
- **Footprint drift:** the independent numeric `DRIFT` value in lifecycle display; it never means capability drift.

## Boundaries

### Always do

- Preserve catalogue selector precedence, normalize admitted direct sources through the canonical pack pipeline, and frame publisher-derived output as untrusted data.

### Ask first

- Raise a Family-1/Family-2 bound, change the digest algorithm/version, admit a redirect host, change the supported runtime-floor table or `requires-python`, or change the direct route's TLS trust-anchor policy as AC37 records it.

### Never do

- Add selection UIs, recursive discovery, hidden discovery beyond E14's single admitted `.claude/skills/` collection root, transports/VCS hosts, a registry, runtime dependencies, direct-pack dependencies/recipes, non-skill primitives, a state hierarchy, lockfile, preview, or direct `validate --deep`.
- Execute publisher content, reclassify `catalogue+https`/`archive+https`, change existing field meanings within manifest schema major 1, or repair unrelated catalogue behavior.

## Testing Strategy

**TDD:** shape/admission, normalization parity, bounds, digest/state, diagnostics, and no-write controls.  
**Manual QA:** built `validate`, install, upgrade, uninstall, receipts, confirmation, `list-installed`, and `show`.  
**Goal checks:** T0 spikes and documentation build/link checks.

- [x] **AC1 — Exact shape classification.** After resolution, recognize the canonical-pack bypass; catalogue only with both `catalogue.toml` and `packs/`; and direct pack, collection, root single, and local-path-at-a-skill forms. Refuse partial catalogue, empty root, `packs/` beneath a direct root, a childless collection root, and hidden/unsupported/nested/overlap forms within an applicable child envelope. Candidate-path selection is the collection root plus root `pack.toml` for a direct pack, the collection root for a collection, or root `SKILL.md` plus the four payload directories for a root single/local skill. Ignore root repository context, including hidden files and directories, for root-single/local-skill, direct-pack, and collection shapes. Root-single/local-skill identity uses the **envelope directory name**, the same rule AC2 applies to collection and direct-pack shapes: one source may not carry two identity rules, and RFC-0098 E17 records the corpus evidence for moving off the frontmatter name. For a **remote** root-single the enclosing directory is the archive's `<repo>-<ref>` wrapper, which encodes the commit and would change on every upgrade, so acquisition supplies the repository name as the identity instead; a local root-single uses its own directory name, which the adopter chose.
- [x] **AC2 — Collection root grammar and envelope identity.** The collection root is `skills/` or `.claude/skills/` per E14; a repository holding both refuses as ambiguous and names both paths. Under that root a direct child holding `SKILL.md` is a skill envelope and a direct child holding none is a category directory whose own `SKILL.md`-holding children are envelopes; exactly two levels are recognised, a third refuses, a category directory holding neither a skill envelope nor `SKILL.md` refuses, and the two kinds may be mixed. Collection and direct-pack identity is the **leaf envelope directory name**, and nothing else. The frontmatter `name` is a *display* string, never an identity: the Agent Skills specification defines it as the "Display name shown in skill listings" that "Defaults to the directory name", and it is optional. Requiring the two to match refused 6% of a 2,545-skill corpus — `Eventbrite Automation` is a valid display name and an invalid slug at once, and `video-downloader/` legitimately declares `name: youtube-downloader`. A missing `name` is therefore admitted, a differing `name` is admitted and displayed, and only the directory name is held to AC11's slug grammar. A collection whose envelopes do not have unique leaf names refuses at classification, naming the duplicated leaf and both paths, before any selection or collision check.
- [x] **AC3 — Source grammar and revision pinning.** Accept explicit local paths or GitHub-only, credential-free `git+https`; reject invalid owner/repository/ref syntax, dot segments, query, fragment, controls, invalid URL components, and bare/defaulted `main`. Percent-encode every owner/repository/ref component with an empty safe set and validate the re-parsed requested `https://github.com/<owner>/<repo>/archive/...` URL. Read the full 40-hex SHA from `pax_global_header`; reject absent/malformed values, expand 7–39-hex refs only when it matches, and require a 40-hex ref to equal it case-insensitively. Record that SHA as `source-revision` and pin branches/tags to it.
- [ ] **AC4 — Stored-provenance request construction.** AC3's grammar governs every request built from **stored** provenance, on the status route and the upgrade route alike: the exact string that passed the grammar is the string the request is built from, with no re-canonicalisation, normalisation, or re-parse between validation and request. A direct row never takes the legacy absent-or-sentinel-source inference branch that resolves through the default chain; a direct row whose stored canonical source is absent or fails the grammar refuses rather than resolving.
- [x] **AC5 — Acquisition bounds and runtime floor.** Apply E11’s redirect equivalence policy. Apply E11 Family 1 before classification and Family 2 in its two phases: enumeration (entries, depth, files) then read (per-file, total); overlapping limit+1 fixtures assert the first breached code only for bounds in the same phase. E11 owns the runtime-floor table, decompressed-side counter, inactivity timeout, `LIST_INSTALLED_CHECK_DEADLINE_SECONDS = 90`, and `LIST_INSTALLED_CHECK_MAX_RESOLUTIONS = 25`. Flags, environment, configuration, and injectable numeric seams never raise either family: before resolving every supplied seam value must refuse `None`, `bool`, a non-`int`, a negative value, or a non-finite value, then use `min(MODULE_CONST, value)` in that order and may only tighten the bound. The clock and progress seams are keyword-only and private, no production call site supplies either, an injected clock must advance, and an injected progress callback resets the inactivity timer only after its value passes that validation. `packages/agentbundle/pyproject.toml` is advisory; `direct_source_acquisition.py` must refuse at acquisition entry using the E11 `sys.version_info` guard, before any archive byte is read and regardless of whether extraction is reached, so a route that refuses before reaching extraction still carries the floor in full. Both credential-free routes consume these constants and guard; preserve the credentialed descriptor route’s same-origin authorization behavior.
- [x] **AC6 — Archive extraction and link policy.** Case-fold collisions and device/FIFO refusal apply to both credential-free routes; symlink and hard-link member refusal is direct-only. Before each write validate the library-resolved `TarInfo.name`/`.size` destination, never a reconstructed name; independently require each admitted `linkname` to be relative and in-root. Reject absolute paths, `..`, Windows separators, or escaping destinations/links; preserve pax global attributes; extract remaining members one at a time with `filter="data"` and without ownership restoration. Direct post-extraction inventory also rejects links and junctions/reparse points; catalogue GitHub archives may retain symlinked members and must still install. Every refusal removes its temporary tree.
- [ ] **AC7 — Source-aware CLI grammar and help.** `install` preserves catalogue `--pack`/`--profile` and accepts direct positional sources plus collection `--skill`/`--all-skills`; `validate` accepts supported source directories and `--format json`; `list-installed` adds no new flag: `--no-check`, `--offline`, and `--check-drift` keep exactly their current meanings and catalogue-row resolution keeps its current default-on behaviour, because this feature introduces no direct-row status probe; and direct `DRIFT` renders from recorded state without `--check-drift`, which continues to govern catalogue drift only; when the `DRIFT` column appears in a mixed table without `--check-drift`, catalogue rows whose drift was never computed render `—` rather than `0`, because a numeric zero would assert a measurement that was not taken; and `upgrade` has a required `--pack`/`--all` mutually exclusive group, with `--pack`/`--all` relaxed only for the accepted standalone manifestless `upgrade --skill S` form. Help for install/validate/upgrade/uninstall/list-installed describes these direct forms and `upgrade --accept-new-capabilities`. `validate --format json` and `install --dry-run` report shape.
- [x] **AC8 — Explicit collection selection.** An unselected manifestless collection refuses before mutation or picker, lists bounded validated names/descriptions, and prints source-preserving `--skill` and `--all-skills` recovery commands. Duplicate/unknown selections and selectors on a direct pack refuse with exit 1. Those names and descriptions are publisher-supplied and are inside AC18's sanitisation input set; a candidate value that AC18 disallows refuses the whole invocation with exit 1 under a registered `DIRECT_CODES` member rather than being elided, so a partial listing is never printed alongside recovery commands covering a larger set.
- [ ] **AC9 — Selector compatibility.** Preserve catalogue selectors and `upgrade --pack P --skill S` filtering. Standalone `upgrade --skill S` accepts repo/user/local only for manifestless skills; a bare primitive upgrade is an `upgrade` invocation that has neither that accepted standalone form nor `--pack` nor `--all`. `--accept-new-capabilities=<pin>` is valid only for that manifestless route and a direct-pack `upgrade --pack P` identified from direct state; it confirms only the computed new capabilities for the displayed pin, never via `--yes`, and remains invalid for catalogue pack upgrades and `upgrade --all`. `upgrade --all --scope repo|user` upgrades every installed direct or manifestless row from recorded provenance. It computes re-consent for every row **before any write**; if any row's capabilities changed it refuses the whole invocation with exit 1, names each changed row and its per-row recovery command (`upgrade --skill S` for manifestless, `upgrade --pack P` for a direct pack), and upgrades nothing. Partial application is never permitted, because AC28 forbids the staging and rollback that would make it recoverable. Retain pack-upgrade scopes. Refuse with exit 2 bare upgrade/uninstall, bare primitive upgrade, `upgrade --pack P --scope local`, bare install, conflicting pack/profile, and pack/profile with a direct source; move catalogue route presence/exclusivity checks to the install handler.
- [x] **AC10 — Direct manifest contract.** A direct `pack.toml` must declare `schema = 1`; omission fails closed. Admit only its schema-1 skills-only subset and reject unknown keys/content, dependencies, recipes, and non-skill declarations. Preserve default scope/local opt-in/no manifest adapter restriction and CLI precedence; catalogue manifests retain implicit v1. Add `schema` as `{"enum": [1]}` to `contracts/pack.schema.json` and its bundled `_data/` copy in byte parity, and enforce unsupported-major refusal in baseline code. Do not change existing field meanings within schema major 1 or merge schema/state version namespaces.
- [x] **AC11 — Manifestless identity and collision.** A direct identity name must match `^[a-z0-9][a-z0-9-]*$` and be at most 64 characters, using a dedicated `DIRECT_CODES` member for refusal; use that validated skill name as manifestless identity, keep its sentinel internal, and prohibit publishers from claiming it. Same-name direct-source and direct/other-source collisions at one adapter refuse in either direction, where same name is NFC-normalized, case-folded equality checked in preflight; `--force` never resolves them. Every value interpolated into a printed recovery command—publisher- or user-supplied, including the source string and any path—is shell-quoted.
- [x] **AC12 — State 0.5 and confinement.** Read 0.4/0.5; every direct state mutation goes through `agentbundle.statelock.persist_state_locked`, and it computes `max(existing, 0.5 when a mutation adds/updates a direct row, else 0.4)` against the state re-read inside that lock, never a pre-lock snapshot; 0.5 is never downgraded. Direct identity excludes revision/digest and refuses missing canonical source. Allow `source-kind` `pack` (display `pack`) and `skill` (display `manifestless`); direct-pack `source-path` is absent, while manifestless `source-path` is validated relative POSIX and never empty. Serialize provenance after `source-revision` in this exact order: `source-kind`, present `source-path`, `source-digest`, then `install-route`. Re-establish root confinement before every join, using the mechanism AC39 assigns to that join's kind. Store repo-scope in-repository sources relatively and refuse out-of-repository sources. Re-derive old capability data from the projection; capability drift is `unknown`. A pinned old reader must refuse 0.5 and direct the user to reinstallation.
- [x] **AC13 — Content-only digest.** Store `sha256-1:<64 lowercase hex>` over the content-only preimage defined by RFC-0098 E2, which supersedes D4’s execute-byte field. Refuse lifecycle comparison/upgrade for another prefix and direct the user to reinstallation; never recompute or rewrite it. A categorised envelope contributes its **full relative path** from the source root to the digest preimage, never the leaf-normalized identity, so two envelopes sharing a leaf name cannot collapse to one preimage entry; a direct `pack.toml` likewise declares the full relative path. Commit independently derived literal vectors for length-prefix ambiguity, non-NFC refusal, and mtime/ownership stability. Exclude executable mode from updates.
- [x] **AC14 — Shared, non-bypassable admission.** Validation and install preflight use one direct entry point and yield identical diagnostics. Refuse links, special/nonregular entries, traversal/absolute/platform-poisonous paths as named by the existing pack-tooling validator, case-fold collision, Family-2 breaches, malformed envelope/manifest/metadata, invalid identity, and source conflict. Source conflict includes a resolved source root lying inside the resolved projection target for the selected scope, and a source bearing catalogue markers: a catalogue repository takes the catalogue route and the direct route refuses it with recovery naming that route. Flags, environment, and configuration never bypass mandatory failure/conflict; per-entry diagnostics name the path. Refuse a logical path segment containing a C0, C1, or DEL code point before enumeration, digest, normalization, or diagnostic emission, and refuse non-NFC logical paths before digest and normalization. At the same point and under its own registered `DIRECT_CODES` member, refuse any logical path segment containing a surrogate code point — equivalently, any segment whose decoded form does not round-trip through `.encode("utf-8")`. `tarfile` decodes member names with `errors="surrogateescape"` and AC2 places no grammar on a category directory name, so without this refusal a lone surrogate reaches three sinks that cannot carry it: AC13's digest preimage, AC12's `state.toml` `source-path`, and AC21's JSON envelope — the `state.toml` write failing only *after* projection, which converts AC28's hard-interruption residual into an outcome a publisher chooses.
- [x] **AC15 — Single-observation primitive.** Never follow a direct-source symlink; use exactly one `read_confined_regular_file(..., max_bytes=1 MiB, include_mode=True)` call per direct file, including a measured direct-pack root `pack.toml`, as the sole direct-path observation primitive—never `sha256_confined_regular_file` or an intervening `stat`, except the named candidate-probe carve-out in AC34—so that call supplies digest, mode, and normalized bytes. The byte string returned by that read is the byte string written to the normalized tree; no direct source file is opened twice on any route. Family 2’s 1 MiB per-file bound applies to every direct file, including `SKILL.md`, and dominates the lifted 2 MiB `max_skill_bytes` and 1 MiB `max_pack_toml_bytes`, which remain unchanged for the catalogue caller but are never reached on the direct route. Its bounds allow values equal to their limits and refuse only a value greater than its limit; AC32 owns the measured content and AC33 its budgets. Any enumeration must carry an entry bound, because `max_files` alone does not bound a directory-only tree.
- [x] **AC16 — Bounded metadata parsing.** `bounded_metadata.py` lifts unchanged `_parse_frontmatter`, bounded `tomllib`, and the limits named in `catalogue_tooling/okf_discovery.py`, operating on bytes already obtained by the confined read; YAML tags, anchors, and aliases refuse, because they are parser-level constructs rather than publisher data. An **unrecognised top-level key does not refuse**: it is ignored and never projected as instruction bytes. Refusing one is unsustainable in both directions — the specification's field set grows by release (`background` needs v2.1.218+), and publishers already carry keys it never defined, with `requires` appearing 832 times across a 2,545-skill corpus, then `version`, `author`, and `tags`. Claude Code itself tolerates them, so refusing here would reject skills that work. The recognised set is the specification's own: `name`, `description`, `when_to_use`, `argument-hint`, `arguments`, `disable-model-invocation`, `user-invocable`, `allowed-tools`, `disallowed-tools`, `model`, `effort`, `context`, `agent`, `background`, `hooks`, `paths`, `shell`, and `metadata`. D5 owns the permitted top-level field set. The subset admits YAML **block scalars** — literal `|` and folded `>`, each with clip, strip, and keep chomping — because 549 of 2,545 corpus skills (22%) write `description` that way, so refusing them would reject a fifth of real sources over formatting alone; folding, chomping, and indentation follow YAML rather than an approximation of it, verified by differential comparison against PyYAML across all 512 corpus skills that use one. An explicit indentation indicator (`>2`) refuses rather than being guessed at, because mis-reading the indent width silently changes the parsed value. A fresh direct-module import must leave `yaml` absent; admission and digest must be byte-identical with or without PyYAML.
- [x] **AC17 — Architecture-regression controls.** These static AST controls are architecture-regression tests on AgentBundle’s own direct modules, not scans of publisher payloads: refuse an `Import`/`ImportFrom` of `subprocess` or `runpy`, and an `ImportFrom` of `os` naming any execution-name member; refuse an `ast.Attribute` on an `os` binding whose attribute is in the explicit execution-name frozenset (`execl`, `execle`, `execlp`, `execlpe`, `execv`, `execve`, `execvp`, `execvpe`, `fork`, `forkpty`, `posix_spawn`, `posix_spawnp`, `startfile`, `system`, `popen`) or starts with `spawn`; and refuse `ast.Name` uses of `exec`, `eval`, `compile`, `__import__`, or imported `os` execution names. Also refuse `lstat`, `stat`, `fstat`, `resolve`, `realpath`, `abspath`, and `readlink` as `ast.Attribute` and `ast.Name` uses — `realpath` and `abspath` are named because they are the spellings that defeat AC39's caller-side-canonicalization rule while passing a ban written only against `resolve` — the same two node kinds the clauses above name, not `Import`/`ImportFrom` — except for the `(packages/agentbundle/agentbundle/direct_source.py, probe_measured_path)` candidate-probe carve-out of AC34; that function returns a refusal decision, never a `stat_result`. Because the ban is on those two node kinds and not on imports, a module-level `import stat` in `direct_source.py` is admitted and outside the carve-out's scope, which AC34 requires so the probe can test `stat.S_ISDIR`/`S_ISLNK` for the wrong-type-for-its-kind refusal. Admissibility makes no claim about publisher-payload behaviour. Named residuals: `importlib`, `getattr`, `ctypes`, and — because these controls observe only a direct module's own imports — the lazy peer import of `system_trust`, whose AC37 trust fallback runs `subprocess.run` against `/usr/bin/security`, so the direct route does reach a process spawn that no AST assertion here can see.
- [x] **AC18 — Publisher-value sanitisation.** The Unicode allowlist permits only L, N, P, and S plus U+0020, which is the sole admitted Zs, and caps each value at 4,096 UTF-8 bytes. Its input set is publisher-derived metadata values rendered in the capability block, summary, receipt, diagnostic message/remediation, `pack`, AC8's pre-admission collection candidate listing of names and descriptions, and every publisher field on `show` and `list-installed`; the candidate listing is inside the set precisely because it renders publisher strings before admission, when least is known about the source. It excludes diagnostic `path`, which AC21 keeps as a top-level diagnostic field. It applies only to CLI and JSON output surfaces, not projected instruction bytes: those bytes remain untrusted and unfiltered. Any value in that input set disallowed or over-limit refuses rather than being truncated; the newline exclusion prevents delimiter forgery. For every member except the candidate listing that refusal is a refusal of admission. Because AC8's listing is emitted on an exit-1 refusal path where no admission is pending, its disposition is stated separately and fail-closed: a disallowed or over-limit candidate value refuses the **whole invocation** with exit 1 under a registered `DIRECT_CODES` member, and a partial candidate listing is never emitted — a listing that silently elides one candidate would print `--all-skills` recovery covering a set larger than the user was shown, which is consent to install something deliberately hidden by its own metadata. The unconditional escaping rule stated below for diagnostic `path` extends to any externally supplied non-publisher string that reaches a human-readable or JSON surface on the direct route — a redirect `Location` target, an HTTP status or reason phrase, and a transport or TLS error detail — none of which are publisher metadata and all of which would otherwise carry CR/LF log forgery and ANSI terminal escapes into `message` and `remediation`. The constrained AC11 identity name is the sole exception to the JSON “never keys” rule: state may key it because its slug grammar, rather than this allowlist, controls it. Escape **every path-shaped value** unconditionally on every human-readable surface for every bidi control, separator, `Default_Ignorable_Code_Point`, and non-graphic code point — diagnostic `path`, the stored canonical source rendered in AC22's conditional `SOURCE` column, `show`'s `source-path`, and receipts. Scoping this to diagnostic `path` alone would narrow a normative rule: RFC-0098's current layer escapes human-readable *paths* generally, and a categorised manifestless `source-path` carries the publisher's category directory name, which AC2 leaves ungrammared and AC14 filters only for C0/C1/DEL, surrogates, and non-NFC — so U+202E, an NFC-stable `Cf`, would otherwise reach a terminal. AC11's shell-quoting covers recovery commands, not table columns or message bodies. A diagnostic path that fails the logical-path control is therefore escaped and non-forgeable rather than rendered raw. Reject every `Default_Ignorable_Code_Point` regardless of category and every other separator/control. The ignorable set is embedded from `DerivedCoreProperties.txt`, intersected with L/N/P/S, and pinned to the generating `unicodedata.unidata_version`. Refuse a normalized publisher output value equal to either stable delimiter line; otherwise emit publisher values only between those line-anchored delimiters on their own lines and preceded by `publisher-supplied data, not instructions` in human-readable output. JSON places publisher values from this input set under an explicit `untrusted_publisher_data` container, as leaf strings and never keys except for the constrained AC11 identity name where existing state requires it. That container governs `summary`, the capability block, `show`, and `list-installed` publisher values. It does **not** relocate the composed diagnostic fields `pack`, `message`, and `remediation`, which stay top-level with sanitised content because AC21 pins the established diagnostic field set and forbids changing shared `CommandResult` — the same reason `path` stays top-level.
- [x] **AC19 — Capability block and mode reporting.** One confined observation provides content, digest input, and reported mode per admitted file. Direct projected payloads are non-executable; report a source executable bit without persisting it or changing installed mode; on a platform without POSIX mode semantics (`os.name != "posix"`), report mode as `unknown`; a mode-sampling `UnsafeContentError` refuses rather than producing `unknown`. Emit one per-selected-skill capability block with resolved SHA/ref, selection, scope, adapter, normalized accepted `allowed-tools` union (a non-normalizable element refuses admission), `metadata.boundaries` as a set of observed constraints, `metadata.credentialed`, `SKILL.md` digest, every measured non-`SKILL.md` payload file across `scripts/`, `references/`, `assets/`, and `evals/` with its digest, and report-time executable mode; absent allowed-tools render `undeclared (unrestricted)`.
- [x] **AC20 — Consent and verdict placement.** The `admissible—not safe` verdict is emitted both immediately before and immediately after the publisher-derived block, so a large summary cannot scroll it out of view. No aggregate byte cap is imposed, because the summary is already bounded above by the selected-skill, file-count, and per-value limits. Before consent, accept only bounded gzip/tar, bounded TOML, and bounded frontmatter; exceptions outside documented decode errors fail closed. Never execute publisher content. Remote noninteractive install and upgrade require `--yes`, which never hides the summary. Remote upgrade renders the same summary plus recoverable old/new digest, revision, allowed-tools, `metadata.boundaries`, `metadata.credentialed`, added/removed skill names, and full payload delta; executable mode is omitted for old data.
- [x] **AC21 — Stable JSON, diagnostics, exits.** Direct validation emits the established envelope keys `schema_version`, `command`, `operation`, `agentbundle_version`, `catalogue_schema_version` (the direct no-catalogue default is `1`), `ok`, and `diagnostics`, plus `summary`, with diagnostic fields `code`, `severity`, `pack`, `path`, `line`, `col`, `message`, and `remediation`, using `sort_keys=True, indent=2`. Do not change shared `CommandResult`, catalogue-command-family JSON bytes, or `catalogue_schema_version` semantics. Summary includes shape and selected skills. Missing remote `--yes`, missing re-consent, unknown old capabilities, and direct-pack selectors are registered documented exit-1 refusals; success is 0 and usage is 2.
- [ ] **AC22 — Lifecycle display compatibility.** Receipts report kind, source, resolved revision, digest, scope, adapter, and matching commands. Add `KIND` only when necessary and preserve pack-only table-byte identity; `list-installed` JSON always includes `kind` and increments its own schema version as required, while AC21 preserves catalogue-command-family JSON. Direct rows **never issue an outbound request**: a direct row's `STATUS` is always `unknown`, and `--no-check` omits `LATEST`/`STATUS` as it does today. - [x] **AC37 — TLS trust-anchor policy and its residual.** The credential-free direct route uses the same trust posture as the credential-free catalogue route and introduces no per-route divergence: verification starts from `ssl.create_default_context()`, and on a verification failure the existing single retry against `system_trust.system_anchor_pem` applies, with `AGENTBUNDLE_NO_SYSTEM_TRUST` as its opt-out. That fallback is macOS-only and has two branches: by default it reads the administrator keychain `/Library/Keychains/System.keychain` and never the user-writable login keychain, and **only when the default trust store holds no anchors** it additionally reads Apple's public TLS export `/etc/ssl/cert.pem`, falling back to `/System/Library/Keychains/SystemRootCertificates.keychain` when that export is absent. The store-replacing `ssl.SSLContext(PROTOCOL_TLS_CLIENT)` construction is confined to `https_catalogue._build_opener`, which serves the `catalogue+https` and `archive+https` routes with or without a bearer token, and is unreachable from the direct route. The retry and its certificate-verification classifier are consumed through one shared, named, non-private entry point in `packages/agentbundle/agentbundle/catalogue.py` rather than restated per route — every candidate is private today, so this promotes an existing helper and makes `catalogue.py` an `Engine-Change-RFC` file for this feature. That entry point **returns a classified outcome carrying the originating exception**, plus the resolved anchors and a certificate-verification-failure flag, and never raises and never formats a message. Naming the intercepted set is part of the contract, because "never raises" is only meaningful against a stated catch: it intercepts `urllib.error.URLError` (and therefore `HTTPError`), `ssl.SSLError`, `TimeoutError`, `OSError`, `tarfile.TarError`, and `gzip.BadGzipFile` — the last two because an archive-decode failure must be observable through this seam rather than escaping past it uncaught. Carrying the exception rather than enumerating outcome values is deliberate and was reached by elimination: a three-valued outcome could not separate a non-certificate TLS failure from a socket timeout, and a four-valued one still could not separate a non-2xx HTTP status, because `urllib.error.HTTPError` subclasses `urllib.error.URLError` and lands in the same `except` tuple. Each added value leaves the next collapse, so the caller receives the exception and classifies it directly. Two predicate rules are mandatory because the transport hides them. First, every TLS test inspects the **unwrapped** `URLError.reason` as well as the top-level exception: `urlopen` re-raises a connect-time `OSError` — which `ssl.SSLError` is — as `URLError`, so a handshake alert, protocol-version mismatch, or downgrade arrives wrapped, and matching the bare type silently never fires, exactly as the existing certificate predicate documents. Second, an `HTTPError` is recognised before the generic `URLError` branch, since it is a subclass of it. Without both, an on-path attacker who cannot present a certificate renders a silent `unknown`. Message construction and raising stay per-route, so each caller renders its own diagnostic and applies AC18's escaping to any transport detail before it reaches a surface. Because `source-revision` is derived from the acquired archive bytes, TLS is the only binding between installed bytes and the publisher's commit; changing this policy is *Ask first*.
