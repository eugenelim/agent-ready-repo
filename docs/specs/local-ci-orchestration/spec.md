## Objective

Contributors run the repository's local CI entry points without repeating the
same pre-PR gate chain. `make ci` retains the complete coverage provided by
`build-check`, lint, type checking, and tests, while `make pre-pr` and
`make build-check` retain their independent lifecycle roles. Make-backed Python
commands use the active Python executable without paying the pyenv shim startup
cost for every recipe, and targets that do not use Python remain unaffected.

## Boundaries

### Always do

- Preserve every current semantic gate reachable from `make ci`; remove only a
  duplicate orchestration edge, not a gate implementation or coverage source.
- Preserve `make build-check`'s portable verification, persistent build,
  repository gate chain, local SAST/SCA tail, and terminal verdict semantics.
- Preserve standalone `make pre-pr` as a verification-first catalogue gate and
  preserve the nested build-check call to the same aggregator with
  `--skip-verify`.
- Resolve Make's default Python lazily, once per Make process, to the executable
  selected by `python3`, while preserving explicit `PYTHON` environment and
  command-line overrides.
- Keep the repository free of generated bytecode and other test residue.

### Ask first

- Change gate membership or ordering inside `build-check`, `pre-pr`, `test`,
  `lint-ruff`, or `lint-mypy`.
- Change SAST/SCA execution, output ordering, scanner concurrency, pip-audit
  behavior, or the local/delegated SAST split.
- Change a GitHub Actions job graph, required-check boundary, or workflow
  command.
- Introduce a numeric runtime threshold or a new build dependency.

### Never do

- Merge independent gates, skip a gate on the basis of this optimization, or
  replace coverage with an unverified claim of equivalence.
- Resolve the default Python executable eagerly for targets that do not expand
  `$(PYTHON)`, or override an operator-supplied `PYTHON` value.
- Export the resolved Make variable as a new cross-process contract.
- Edit the bodies of shipped specifications to rewrite historical decisions.

## Testing Strategy

The orchestration graph and Python-selection rules use **TDD** because their
invariants are compact and mutation-testable. A construction test reads the
real Makefile, proves that `pre-pr` is not a direct `ci` prerequisite, and proves
that the pre-PR aggregator remains transitively reachable through
`build-check`. Real-Make subprocess cases prove lazy one-time resolution,
non-Python target behavior, path quoting, and environment/command-line
overrides. The launcher subprocess cases run only when both POSIX execution and
Make are available; the Make-graph assertions remain platform-independent.

Stub tally: one TDD task has one materialized red stub covering AC1-AC9; two
delivery tasks record `no stub` for their goal-based and manual-QA modes.

The complete local and GitHub-facing behavior uses **goal-based checks** at
integration and end-to-end surfaces. Existing build-chain, CI-parity, workflow,
and SAST-reachability tests establish that no gate or GitHub route moved. A
real `SKIP_SAST=1 make build-check` exercises the full non-SAST local chain, and
a real `SKIP_SAST=1 make ci` exercises the optimized developer journey while
retaining the explicit incomplete verdict. SAST itself is not restructured by
this slice and remains covered by its existing focused tests and reachability
guard. An additional before/after slice comparison fails if the `sast:` recipe
— including pip-audit commands and scanner order — differs from its pre-change
Git version.

## Acceptance Criteria

- [x] AC1: `make ci` has `build-check`, `lint-ruff`, `lint-mypy`, and `test` as
  its direct gate prerequisites, and does not have `pre-pr` as a direct
  prerequisite.
- [x] AC2: One `make ci` invocation reaches the pre-PR catalogue aggregator
  exactly once through `build-check`, and that nested invocation passes
  `--skip-verify`.
- [x] AC3: One `make ci` invocation reaches portable catalogue verification
  exactly once and retains every repository gate, lint gate, type-check gate,
  test gate, SAST/delegation decision, and terminal verdict reachable before
  this change.
- [x] AC4: Standalone `make pre-pr` remains verification-first, and standalone
  `make build-check` retains the sequence portable verification, persistent
  build, pre-PR aggregation with `--skip-verify`, then the existing SAST/SCA
  decision and verdict.
- [x] AC5: The first expansion of Make's default `PYTHON` resolves the executable
  selected by `python3`; later `$(PYTHON)` expansions in that Make process reuse
  the resolved value without relaunching the selector.
- [x] AC6: A Make target that does not expand `$(PYTHON)` does not invoke the
  Python selector.
- [x] AC7: Command-line and environment `PYTHON` overrides bypass default
  resolution and are used verbatim according to existing Make precedence.
- [x] AC8: A default Python executable path containing shell-significant spaces
  is shell-quoted before Make recipes use it.
- [x] AC9: Python resolution does not import from the working directory or write
  bytecode, and an empty resolution fails during expansion with an actionable
  Make error rather than running an empty command.
- [x] AC10: GitHub Actions workflow commands, job graphs, and SAST delegation
  remain byte-unchanged; existing workflow posture and local-parity tests pass.
- [x] AC11: SAST scanner ordering/output, pip-audit behavior, and scanner
  concurrency are unchanged.
- [x] AC12a: Focused construction tests, the repository's lint/type checks, and
  a non-SAST `build-check` complete successfully without leaving generated
  worktree residue. The non-SAST `ci` run reaches tests through the single
  `build-check` route after lint and type checking, without a second pre-PR
  phase.
- [ ] AC12b: (deferred: pre-existing-enterprise-agentbundle-full-suite) The
  non-SAST `ci` run completes its unchanged full test tail and
  terminal verdict in an environment permitted to read its temporary CA
  fixtures.

## Assumptions

- Technical: `build-check` already invokes
  `tools/catalogue/pre_pr_catalogue.py --skip-verify` through
  `tools/repo/build_gate_chain.py`, while the Make `ci` target also names
  `pre-pr` directly (source: `Makefile` and
  `tools/repo/build_gate_chain.py`, inspected 2026-08-21).
- Technical: an observed `SKIP_SAST=1 make build-check` run completed in about
  9 minutes 40 seconds, and full local SAST adds further time; eliminating the
  duplicate `pre-pr` edge improves `make ci`, not the internal duration of
  `make build-check` (source: local timing probe 2026-08-21).
- Technical: the pyenv-selected `python3` shim took about 1.75 seconds for a
  no-op launch while its resolved interpreter took about 0.10 seconds, and the
  `test` recipe graph contains roughly 60 `$(PYTHON)` launches (source: local
  timing and Makefile inventory probes 2026-08-21).
- Technical: GNU Make 3.81 supports the tested lazy self-replacing variable
  expression, including bypass by command-line overrides and no resolution for
  an unrelated target (source: isolated `/private/tmp` prototype 2026-08-21).
- Process: GitHub `gate-main` invokes `make build-check ... SAST_DELEGATED=1`,
  GitHub `gate-sast` invokes `make sast`, and no GitHub workflow invokes
  `make ci` (source: `.github/workflows/build-check.yml`, inspected 2026-08-21).
- Process: shipped `build-check-single-verify` and `local-gate-ci-parity`
  specifications remain historical constraints rather than edit targets
  (source: `docs/specs/`, inspected 2026-08-21).
- Product: orchestration deduplication and Make interpreter selection are in
  scope; SAST parallelism is investigation-only because interleaved terminal
  output harms diagnosis (source: user confirmation 2026-08-21).
- Product: pip-audit optimization joins scope only at high confidence; the
  managed-environment prototype could not establish that confidence, so it is
  excluded (source: user confirmation and isolated prototype 2026-08-21).
