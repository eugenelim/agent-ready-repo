## Objective

Replace the method-and-scaffold-oriented `user-guide-diataxis` pack with a
`product-documentation` canonical pack plus a minimal deprecated compatibility
shim. The canonical pack's primary skill is `author-product-docs`, supporting
five explicit modes (create, revise, retrofit, audit, verify) with
directory-agnostic Diátaxis as a page contract rather than a mandatory folder
scaffold. The compat shim retains the `user-guide-diataxis` machine identifier,
depends on the canonical pack, has no seeds, and provides a thin `new-guide`
redirect skill. This phase establishes the authoring contract and repository
ownership model; it does not migrate every existing guide, move all journeys, or
redesign the frontend.

## Assumptions

1. agentbundle does NOT auto-install a pack's `[[pack.dependencies.required]]`
   deps — it errors with a clear "install X first" message when the dep is absent
   and not co-installed in the same profile batch. Consequently, a bare
   `agentbundle install --pack user-guide-diataxis` on the shim will fail unless
   `product-documentation` is already installed. This is the expected migration
   experience: the error message directs the adopter to install
   `product-documentation` first. New installs should target `product-documentation`
   directly; the shim serves profile-level compat only (co-installed in a profile
   that includes both packs).
2. The `core` dependency in the current pack is a seeds/CONVENTIONS.md scaffold
   alignment convention, not a runtime requirement of the authoring skill. The
   new pack omits it.
3. `product-documentation` has no seeds → eligible for `user` or `repo` scope;
   default remains `repo` since documentation work is inherently per-project.
4. Frozen ADR/RFC documents are not edited; living specs and docs are updated.
5. `docs/CONVENTIONS.md` is projected from `packs/core/seeds/docs/CONVENTIONS.md`,
   which is pack-neutral. No edit needed to the core seed.
6. All adapter-projected skill files under `.claude/skills/` and `.agents/skills/`
   are regenerated by `make build-self` — they are not hand-edited.
7. Both `product-documentation` and `user-guide-diataxis` stay in the self-host
   include list so both packs' skills project into this repo's `.claude/skills/`.
   This ensures `author-product-docs` is available in the repo tree and the
   shim's `new-guide` redirect can name it by skill slug.

## Boundaries

**In scope:**
- Create `packs/product-documentation/` canonical pack with no seeds
- Convert `packs/user-guide-diataxis/` to deprecated compat shim
- New `author-product-docs` skill with five modes and directory-agnostic Diátaxis
- Skill reference files: artifact-model, page-contracts, repository-ownership,
  conversation-first, rendered-verification, clear-prose
- Evals: 8–10 positive, 8–10 near-miss, strong+weak output fixtures
- Deterministic tests for compat behavior and collision-freedom
- Rename `guides/user-guide-diataxis/` → `guides/product-documentation/`
- Rewrite guide content for new pack identity; add maintainer how-to in `docs/guides/how-to/`
- Update guides/README.md, _shared/ references, and AGENTS.local.md
- All manifests, profiles, web content, docs-site, agentbundle tests updated
- Add `product-documentation` web pack + journey entries; update existing `user-guide-diataxis` entries to reflect shim status
- Governance artifact (ADR) for future machine-ID migration

**Out of scope (record as deferred):**
- Bulk-flatten top-level `guides/` tree
- Delete `docs/guides/`
- Move all journeys into pack folders
- Change journey renderer
- Retrofit Atlassian pages or strengthen Atlassian skills
- Redesign public documentation frontend
- Migrate every other pack's README
- Implement native agentbundle alias/supersession mechanism (separate RFC)

## Testing Strategy

**Verification mode per task:** Goal-based check (build commands, lint, pytest).
The authoring skill output quality is verified via eval fixtures (strong/weak) and
activation evals (eval_queries.json).

**Deterministic checks to add (new tests in packages/agentbundle/tests/):**
- T-D1: Install `user-guide-diataxis` shim alone → agentbundle errors with "install product-documentation first"
- T-D2: Install `product-documentation` then `user-guide-diataxis` → succeeds; installed tree has exactly one `author-product-docs` skill implementation
- T-D3: Shim install tree has no `seeds/guides/` directory
- T-D4: `product-documentation` install tree has no `seeds/guides/tutorials/`, `seeds/guides/how-to/`, `seeds/guides/reference/`, `seeds/guides/explanation/` paths
- T-D5: `lint-skill-spec.py` on canonical pack passes (no CAT-S006 violation)

**Existing gates to pass:**
- `make build-self` + `make build-check` (projection integrity)
- `python3 tools/lint-skill-spec.py` (spec metadata invariants)
- `python3 tools/lint-agent-artifacts.py` (artifact validity)
- `pytest packages/agentbundle` (unit + integration)
