# Rounds 5 and 6 Experimental evidence archive

This note preserves the manifested, redacted evidence reviewed for the
2026-08-16 RFC-0088 round-5 Experimental run and its 2026-08-17 round-6
correction pass. **Every results file it carries was produced by the fixture
sources it ships**, and every one carries a provenance block naming the
platform, uid and per-run nonce it was produced on — `build-archive.py` refuses
to build otherwise, and `run-linux.sh` refuses to copy a container artifact back
unless that artifact's own provenance says `linux`. An earlier version of this
note claimed the provenance property when 4 of 10 files had it. It excludes third-party package
trees, browser binaries and profiles, TLS private key material, downloads, and
every other transient runtime file.

- Archive media type: `application/gzip` containing a tar archive
- Archive size: 74,882 bytes
- Archive SHA-256:
  `598818b0a1ed45a8e617bd43d789d500d29a48a0e7641add495cca7c8aa3afcb`
- Members: 37 bounded regular files: the manifest plus the
  36 manifested files
- Uncompressed member bytes: 288,999
- Largest member: 20,092 bytes

The archive is evidence support, not a production deliverable. Its executable
fixture sources are inert until a reviewer deliberately reconstructs and runs
them in an approved temporary path. No third-party package tree, browser
payload, profile, cookie store, credential value, TLS private key, or download
is included.

Every promoted observable passes a redaction step, and `build-archive.py` —
itself a manifested member, so the gate is auditable — enforces it. The build
fails on any home directory, path-mangled account name, per-user temporary
path, uid-bearing temporary root, hostname, or key material. Members that name
those strings as their own detection patterns carry a per-file exemption for
the bare literal only; a key marker followed by PEM body fails even there.

The method-policy fixture generates a throwaway TLS chain with `openssl` into a
temporary root **outside** the evidence tree and deletes it at teardown, so no
key material is reachable from this archive. The privacy gate fails closed on a
PEM body regardless of which member carries it, and it no longer exempts short
hostnames — an earlier length floor let any host named in three characters or
fewer through.

**Numeric uids are promoted deliberately, and the decision is recorded here
rather than left implicit.** Round 6's provenance blocks carry a `uid` field.
That is load-bearing evidence: the Linux platform row's whole claim is that it
was measured as an unprivileged user (uid 1001) rather than as root, and the
namespace boundary row discloses the opposite (uid 0). Those are container
account ids, not a person's. The macOS blocks carry uid 501, which is the
default first-user id on essentially every single-user macOS install — it
carries no name, no path, no handle, and no directory identifier, and the
privacy rule this repo enforces targets names, addresses, handles, org domains,
directory identifiers, device names and user-specific filesystem paths, none of
which a bare integer is. The gate continues to fail closed on all of those. If a
future round needs to drop the field, the macOS claims do not depend on it —
only `runningAsRoot` does.

`verify-note-figures.py` ships here too and runs unchanged from a
reconstruction. Two of its facts — the archive's own digest — cannot be
re-derived there, because the archive blob is not a member of itself; it reports
those by name under `figuresNotCheckableHere` rather than silently checking two
fewer things, which is what an earlier version did. The manifest-derived member
count is checkable from a reconstruction, and the digest itself is verified by
the procedure above before extraction. `run-all.sh` and `run-linux.sh` ship as well, so
the run order and the platform split are auditable rather than described.
