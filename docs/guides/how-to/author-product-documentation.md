# How to author product documentation (maintainer)

**Audience:** Maintainers and contributors adding or updating documentation in
this catalogue.
**Use this when:** you need to create or update a guide, pack README, or journey
page in the correct location, or you want to understand where different kinds of
documentation live.

## Where documentation lives

This catalogue has two documentation trees with distinct ownership:

### `guides/` — catalogue-facing product documentation

Top-level `guides/` contains user-facing documentation for catalogue users:
tutorials, how-to guides, reference pages, and explanations for people installing
and using packs. Organized by pack: `guides/<pack>/<kind>/<slug>.md`.

**Write here** when the audience is an external user of the catalogue or its packs.

### `docs/guides/` — internal maintainer and contributor guidance

`docs/guides/` contains authoring how-tos, operating procedures, and contributor
guidance for people who maintain or extend this catalogue. You are reading a file
from this tree now.

**Write here** when the audience is a maintainer or contributor.

### Pack README — `packs/<pack>/README.md`

The pack's canonical landing document for users evaluating or installing it.
Machine facts (version, scope, dependencies) are validated against `pack.toml`.
This is the first thing a user sees before installing.

### DESIGN — `packs/<pack>/DESIGN.md`

Maintainer-facing design notes. Not a product-documentation page. Read it to
verify facts when updating product docs; do not update it as part of a
product-documentation task.

### `web/` and `docs-site/`

Rendering systems. They consume canonical content but are not sources of new
documentation. When rendered content is stale, update the source (`guides/`,
`packs/*/README.md`) and regenerate — do not edit built output directly.

## How to use the product-documentation skill

The `author-product-docs` skill (from the `product-documentation` pack) handles
create, revise, retrofit, audit, and verify modes. You do not need to name
the mode — the skill infers it.

Ask your agent:

> Write a how-to guide for [user task] in the [pack name] pack.

> Revise the README for [pack name] to lead with outcomes.

> Audit the onboarding guides for inventory-first writing.

The skill reads `pack.toml` and skill sources before drafting. It does not
invent capabilities.

For the user-facing guide to this skill, see
[`guides/product-documentation/how-to/author-product-docs.md`](../../guides/product-documentation/how-to/author-product-docs.md).

## Avoiding accidental edits to generated output

Some files in this repo are projected from pack seeds or generated by build
tools. Editing them directly produces changes that `make build-check` will
reject on the next projection run.

Generated files include:
- `docs/CONVENTIONS.md` (projected from `packs/core/seeds/docs/CONVENTIONS.md`)
- `/.claude/skills/` and `/.agents/skills/` subtrees (projected by `make build-self`)
- `/.claude-plugin/marketplace.json` (generated by `make build-self`)

To update a projected file, edit its source in `packs/<pack>/seeds/` or
`packs/<pack>/` and run `FORCE=1 make build-self`.
