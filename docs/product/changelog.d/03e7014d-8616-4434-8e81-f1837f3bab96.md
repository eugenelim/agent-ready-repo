## Highlights
- Experience Design now writes the words your screens show: `ux-writing` drafts error, empty-state, button, and label copy keyed to each screen and state.

## Added
- **`ux-writing`**, from product-engineering 2.0.0. It characterizes your product's UI voice, then writes error, empty-state, button, and label copy. With a `user-flow` state matrix it writes one string per screen and state, in the voice of the `content-design` brand register. Its name, description, and voice-chart path (`docs/product/voice/<slug>.md`) are unchanged.
- **If you also have product-engineering**, use the scope you installed at (`user` or `repo`) in every command.

  `agentbundle upgrade` and `agentbundle uninstall` ask you to confirm; add `--yes` when no one is at the terminal. If you use more than one adapter, run each command once per adapter and add `--adapter <name>` to it, including each `install`.

  If you have both packs:

  1. Upgrade both packs, in either order:

     ```bash
     agentbundle upgrade --pack product-engineering --scope <user|repo>
     agentbundle upgrade --pack experience-design --scope <user|repo>
     ```

     If you upgrade experience-design first, the product-engineering upgrade prints "1 installed file(s) have local edits". That is expected: you did not edit anything, no `.upstream` file is written, and the next step clears it.
  2. Reinstall product-engineering:

     ```bash
     agentbundle uninstall --pack product-engineering --scope <user|repo>
     agentbundle install --pack product-engineering --scope <user|repo>
     ```

  If you have product-engineering and are installing experience-design for the first time:

  1. Upgrade product-engineering: `agentbundle upgrade --pack product-engineering --scope <user|repo>`.
  2. Reinstall product-engineering with the two commands above.
  3. Then run `agentbundle install --pack experience-design --scope <user|repo>`. Before step 2, this install is refused because product-engineering still claims the `ux-writing` files.
