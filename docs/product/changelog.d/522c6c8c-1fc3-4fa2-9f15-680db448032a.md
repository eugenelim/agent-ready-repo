## Highlights
- work-loop's Unfamiliar risk trigger now allows one throwaway spike, outside the tracked tree and never committed, to ground a design before full mode fires.
- bug-fix diagnoses a defect, earns its failing test in scratch, and hands the fix to work-loop, which decides where the test lives.
- work-loop has two new verification modes: behavior pin for refactors and measurement for performance claims. Every other mode list now points at work-loop's PLAN step 7.
- An adversarial-reviewer finding about how code behaves carries the command and its output when a run is safe and cheap, and work-loop's FIX reruns that command before and after the fix.

## Changed
- `work-loop`: the Unfamiliar risk trigger permits one bounded spike; PLAN step 1b routes an undiagnosed defect through `bug-fix`; PLAN steps 7 and 8, EXECUTE, and `references/verification-modes.md` add behavior pin and measurement; FIX runs a sustained finding's command before and after the fix.
- `bug-fix`: step 2 earns its red from disposable scratch, the fix runs through `work-loop`, and step 10 keeps the test `work-loop` materializes.
- `adversarial-reviewer`: a behavior finding whose run is feasible carries the command and its output; without it the finding is a Concern at most.
- `new-spec`, `implementer`, `tdd-stubs.md`, `infra-verification.md`, and the core guides point at `work-loop` PLAN step 7 for the list of verification modes.
