## Highlights
- `work-loop`'s dispatch decides what is ready, active or blocked from each artifact's own headers alone, and refuses with `unmigrated_workspace` while `workspace.toml` still holds an entry; run `workspace-status repair-plan`, then `repair-apply --yes`, to move those entries.
- `workspace-status` now answers only `repair-plan` and `repair-apply`.

## Changed
- `dispatch.py --captured` lists captured items for the shaping-item guard, and dispatch loads no other skill's files.
- The `workspace-status` `status`, `reconcile`, `explain`, `selected-membership`, `prune` and `retirement-candidates` subcommands are retired; for status use `work-loop`'s `dispatch.py` or `navigate-intents` `outstanding`. `work-intake` routes status requests to `navigate-intents`.
- The `agentbundle` MCP `workspace_status()` tool reads the packaged header-only dispatch: its items no longer carry `ini_slug`, `shaping` is empty, and `canonical` holds the dispatch output. A dispatched item `type:slug` gives the branch `type/slug`; the three-part `ini_slug/type:slug` form still works.
- A legacy-form `workspace.toml` entry (a bare `spec/<slug>` string or a `{slug = ...}` table) is rewritten or removed by hand, since `repair-plan` plans nothing for it; dispatch refuses with `unmigrated_workspace` until then.

## Removed
- The legacy migration tooling: `repair-plan --migration-selection`, the migration form of `repair-apply`, and the `repair-rollback` removal, with the `[authorization.migration]` table and the four `work-intake-migration-*` schemas. An operation already recorded in `.workspace-migrations.json` can no longer be rolled back; finish or roll it back before upgrading.
- `contracts/jsonschema/spec-retirement-candidates.schema.json`.
