## Highlights
- Adds a read-only `work-loop` dispatch command (`scripts/dispatch.py`) that derives dispatch from a spec's headers; nothing calls it yet.
- Close-work enrolment now fills the lifecycle record's optional `parent` from the spec's `Brief:` header, so a closed spec keeps its link to the brief that shaped it.
- Replays real dispatch decisions against the new command and records the evidence.

## Added
- `work-loop` `scripts/dispatch.py`: a read-only command that prints the ready, active and blocked specs and one decision for an argless, named-start or named-resume invocation, from each spec's own headers through the unchanged canonical reconciliation engine. Several ready or active specs give `ask` with every candidate; nothing picks by order.
- `close-work` `scripts/cooling.py`: the lifecycle record's optional `parent`, `none` or a brief path, which enrolment fills from the spec's `Brief:` header and which every later record change keeps.
