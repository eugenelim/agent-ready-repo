## Highlights
- The work-loop supervisor now keeps each run's product result in a protected Git ref that only the supervisor advances, moving it with `HEAD` in one compare-and-swap. Acceptance still reads `HEAD` in this release, so a run's evidence and reviews are unchanged.
- A reset, rebase, amend, or extra commit on a run's branch either converges to the run's own product or stops `next` with a `history-adoption` decision that the owner answers with `adopt-history`. New refusals: `integration-conflict`, `product-ref-diverged`, `projection-blocked`, `adoption-refused`, and `unsupported-ref-storage` (Git's reftable ref storage is not supported).
- A run already in flight reaches this release only through `regenerate`; it gains its product ref at its next step, and a controller's own commit on top of the run now asks the owner to adopt it.
