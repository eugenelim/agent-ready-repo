## Highlights
- A code review that has not settled after two rounds now stops with a `review-cap` decision. The owner decides from the named open findings: accept the risk, allow one more round, or choose the reviewers again.
- After the first full review, a repair asks again only the reviewers its change earns: one delta pass for a rebase or a small fix, and everyone for anything else. The wording-only tier ships off, so a prose-only edit re-asks reviewers as a minor fix or a full review. The supervisor still reviews in full whenever it is unsure.
- Each reviewer selection now lists `protected_classes`. The reviewers those classes map to, such as the security reviewer for a security boundary, read the whole change on every revision and are never skipped or capped.
