## Highlights
- Plans can declare optional `Reads:` and `Writes:` lines on a task, and the new-spec plan template now explains the entry forms. A task without both, or with a malformed entry, runs one at a time as before.
- The maintainer reference for the execution supervisor documents the `Reads:` and `Writes:` grammar and the closed set of reason codes once. Concurrent attempts stay off by default (`concurrency: sequential`), and no shipped host can run them.
- A permutation corpus runs each concurrent schedule in every forced completion order, with no external agent on the path, and checks that each ends with the same tree and acceptance outcome as the sequential run.
- Concurrent attempts are safer to recover: a held-result ref that exists only in `packed-refs` is now found, and an unreadable or oversized `packed-refs` fails closed. A sibling attempt's Git check can no longer see the supervisor's own product-ref move before it is recorded and refuse the batch.
