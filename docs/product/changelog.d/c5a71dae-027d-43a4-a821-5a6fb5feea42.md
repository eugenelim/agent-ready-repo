## Highlights
- A new blank catalogue from catalogue init now packages and verifies with no hand edits.
- Breaking: a `[catalogue.package].include` entry that names a `_` directory under `packs/`, such as `packs/_example`, now fails with `CAT-PKG-001`. Remove it. If that leaves `include` empty, packaging ships every non-`_` pack, so list the packs to ship instead.

## Changed
- `agentbundle catalogue init` writes a root `AGENTS.md`, the marker `catalogue package` ships, and a root `CLAUDE.md` that holds `@AGENTS.md`. A new catalogue packages and verifies as an empty but valid release. An existing root `AGENTS.md` or `CLAUDE.md` is kept and reported as already present with its on-disk hash.
- A bad `[catalogue.package].include` entry now fails `catalogue package` with a `CAT-PKG-001` diagnostic, not a Python traceback.
- A catalogue made by an earlier release does not gain the root file when you re-run init, because `catalogue.toml` conflicts. Add a root `AGENTS.md` by hand.
