## Highlights
- A read-only brief-level runner in the work-loop skill names the next ready slice of a delivery brief from its Spec map and the specs' approval state, lists every parked approval gate across the brief's slice worktrees in one place, and derives each slice's status from committed records only.
- A brief's standing orders, one numbered constraint per line in `docs/product/standing-orders/<brief-slug>.md`, are read from the base commit and handed to every dispatch and resume as quoted data that can never approve, merge or relax a control.
- `brief-runner.py classify` turns a failed implementation dispatch into one action (split, retry, retry on another model, replace, or abandon and replan after two retries), reading the retry count from the supervisor rather than the controller.
- `supervisor-policy.json` carries a `lease` table (heartbeat, stuck-after runtime per agent kind, retry budget, slices in flight), and the supervisor's `status --json` reports each task's `failed_attempts`.
- Every approval, amendment and merge stays with a named human; the runner only reads.
