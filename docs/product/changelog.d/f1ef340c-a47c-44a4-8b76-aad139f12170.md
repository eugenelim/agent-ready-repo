## Highlights
- Acceptance in a full-mode work-loop run now reads the run's protected product ref instead of `HEAD`: the delivery subject carries lineage `protected-product-ref` and the product ref's commit, so history on the branch that the owner has not adopted changes neither the subject nor readiness.
- This reaches runs started after the release. A run in flight reaches it only where the repository holds the pack source, through `regenerate`, and then runs its gates and reviews once more, because evidence recorded under the earlier subject does not count under the new one; any other run refuses `supervisor-changed`, as any installed-skill change does.
- To go back, reinstall the previous Core release for new runs, or, where the pack source is present, release a patch that sets `result_authority` in `supervisor-policy.json` back to `legacy-worktree` and cross runs in flight through `regenerate`. No product change is lost, since both refs carry the same commits.
