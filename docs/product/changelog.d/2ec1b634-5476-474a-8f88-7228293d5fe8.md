## Highlights
- `ux-writing` now ships in the experience-design pack, beside the screen flows and brand register it writes from. After upgrading, reinstall product-engineering once so it lets go of the old copy; the product-engineering 2.0.0 release note has the steps.

## Removed
- **`ux-writing` leaves this pack and ships in `experience-design` 4.2.0.** Its name, description, and behavior are unchanged, and it still writes voice charts to `docs/product/voice/<slug>.md`. A prompt or script that names product-engineering to get `ux-writing` needs experience-design instead.
- **Every product-engineering adopter runs one extra step.** `agentbundle upgrade` leaves the old `ux-writing` folder in place, still claimed by this pack. Use the scope you installed at (`user` or `repo`) in every command. Files you edited by hand are kept.

  `agentbundle upgrade` and `agentbundle uninstall` ask you to confirm; add `--yes` when no one is at the terminal. If you use more than one adapter, run each command once per adapter and add `--adapter <name>` to it, including each `install`.

  If you have both packs:

  1. Upgrade both packs, in either order:

     ```bash
     agentbundle upgrade --pack product-engineering --scope <user|repo>
     agentbundle upgrade --pack experience-design --scope <user|repo>
     ```

     If you upgrade experience-design first, the product-engineering upgrade prints "1 installed file(s) have local edits". That is expected: you did not edit anything, no `.upstream` file is written, and the next step clears it.
  2. Reinstall product-engineering:

     ```bash
     agentbundle uninstall --pack product-engineering --scope <user|repo>
     agentbundle install --pack product-engineering --scope <user|repo>
     ```

  If you have only product-engineering:

  1. Upgrade it: `agentbundle upgrade --pack product-engineering --scope <user|repo>`.
  2. Reinstall it with the two commands in step 2 above.
  3. To keep `ux-writing`, install experience-design: `agentbundle install --pack experience-design --scope <user|repo>`. Do this only after step 2; before it, the install is refused because product-engineering still claims the files.
