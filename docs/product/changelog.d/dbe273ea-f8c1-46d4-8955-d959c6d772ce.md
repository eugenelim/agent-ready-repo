## Highlights
- The supervisor now runs the approved gate commands itself. A task or final gate passes only on a recorded run (`execute-gates`) that matches the request, and a worker can no longer claim a pass by report alone. An owner can reopen a task that was wrongly admitted with `correct-task`.
- A new `commit-record` verb lands ledger notes you declare in the approved spec without an owner adoption wait.
- A review budget counts rounds, repairs by finding class, active time and retries across replan and adoption, and stops at three rounds or two repeats of one finding class with a clear owner decision to extend.
- `start` now refuses a primary checkout and a checkout another run holds, and `status` says where a run's state lives.

## Changed
- A spec now needs a `gate-declaration` block in its Agent Rules section before a run can report task success. The `new-spec` template shows the form. Runs already in flight keep their old behavior until you regenerate.
- Pass `--allow-primary-checkout` to `start` when you deliberately run in a primary checkout.
