## Highlights
- The execution supervisor now runs every Git command through one hardened helper that ignores system and global config, turns off hooks, fsmonitor, external diff, textconv, replace refs and signing, and refuses to start when repository config would run code.
- Windows process launches now refuse an NTFS stream name and a network or device path, confirm that a process outside its Job Object was ended before saying so, and turn any unexpected launch failure into a stable `denied-launch-failed` refusal with its security event.
- The execution supervisor now records a manifest of the trusted files and Git control state each time it issues a worker request. A worker change to the spec, plan, a cited record, the installed skill, `delivery/`, or Git control state is refused, leaves `attempt-residue` until the named paths are restored, and is never committed as a replan.
- The execution supervisor now pins the hashes of its own scripts, policy, and review rules when a run is first admitted, and every later command refuses `supervisor-changed` if they differ, before it loads any script and without reading bytecode files. It checks trusted files and Git control state again after each gate run and red proof, asks for one `regenerate` step when a run edits the work-loop source and then re-pins the installed skill, and stops with a human decision instead of running repository code for an `untrusted` run that has no verified containment.
- A run admitted by Core 3.1.14 or earlier is refused `supervisor-changed` because it has no pin record, and must be started over. A store directory is created whole, with its spec record, so a crash never leaves one without it. A store directory with no pin record blocks only its own spec until that run's `start` pins it; one with no spec record (only by tampering) refuses every spec until it is removed. A refused attempt whose paths are not yet restored keeps guarding every spec against an installed-file edit, as an open attempt does.
- The execution supervisor now refuses a result that asserts a fact its request kind does not carry (`result-fact-refused`, or `result-kind-refused` for an unknown kind): an `implement-task` result carries only its gate outcome, and a `write-stub` or `regenerate` result carries nothing. An `untrusted` run with no verified containment now gets the same human decision instead of an `implement-task` request. Red proofs and scratch receipts still run with the supervisor's own environment and no recorded launch grant; routing them, and the supervisor's `git` calls, through the safe-process primitive is not part of this release.
