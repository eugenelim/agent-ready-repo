## Highlights
- Plans can now declare the external effects a task performs, and stub fences carry the command and exit codes that prove a test fails first.

## Changed
- The `new-spec` plan template documents an optional `**Effects:**` line: a task names the external effects it performs, unique across the plan, and a header-level line names effects that run once when the whole plan is done.
- The work-loop TDD stub reference documents the `stub` fence: `path`, the `run` command with `{path}` expansion, and `red-exit` codes, so a stub's red can be observed mechanically.
- Core ships a dark execution supervisor in the work-loop skill's scripts. Nothing in the skill calls it yet, and the existing loop engine is unchanged.
- On Windows, a safe-process launch runs in a Job Object that denies breakaway and ends the whole tree on timeout.
