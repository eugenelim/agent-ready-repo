## Blockers

**1. No criterion annotates the frozen spec whose checked criterion this reverses.** `docs/specs/visual-target-confirmation/spec.md:132`. AC-0006 changes the `approved-visual-target` `requires` cell away from `recorded-human-confirmation`, which is the exact value `docs/specs/frontend-visual-authority/spec.md:133` records as met under `- [x] AC-0003a` on a `Shipped` spec, and `.claude/skills/new-spec/references/spec-and-plan-contract.md:51` requires annotating that spec's `Status` field when a later decision reverses part of it — the repository's own precedent for this is `docs/specs/design-to-build-value-handoff/spec.md:276` (AC-0035), which made the annotation a criterion. Fix: add an acceptance criterion requiring `docs/specs/frontend-visual-authority/spec.md`'s `Status` field to carry a supersession annotation naming ADR-0131 and AC-0003a's `requires` value as the superseded part, and give it an owning task.

**2. AC-0017's declared regression test has no subject that can resolve a rung.** `docs/specs/visual-target-confirmation/spec.md:156`. The criterion says a test "fails when a direction artifact ... is resolved to the `approved-visual-target` rung", but `packs/frontend-engineering` ships no executable code outside `tests/` — rung resolution is agent behaviour described in Markdown, and `docs/specs/frontend-visual-authority/spec.md:186` already records that `recorded-human-confirmation` "is a property this pack defines, and no control verifies it ... Only a control outside the agent closes that, and this slice adds none." Fix: restate AC-0017 as the check that actually exists — either an assertion over the shipped rule text that is not already AC-0006/AC-0008, or an eval case under the visual/manual-QA mode — and move it out of the TDD group in Testing Strategy.

**3. Testing Strategy's helper claim is false for three of the criteria it covers.** `docs/specs/visual-target-confirmation/spec.md:99-102`. The bullet asserts AC-0006 through AC-0013 "parse through the shipped `observation_table` and `rule` helpers", but those helpers in `packs/frontend-engineering/tests/skills/frontend-engineering/frontend_engineering_visual_authority_rules.py:100-125` read only `references/visual-observation.md`: AC-0011 targets `packs/experience-design/.apm/skills/design-system/SKILL.md:93`, which the `pack-tests-stay-in-pack` check (`tools/lint-pack-test-boundary.py:1163`) forbids a frontend-pack test from reading at all, and AC-0012/AC-0013 target `frontend-engineering/SKILL.md:151,880`, which those helpers never open. Fix: split the bullet so AC-0011 names an experience-design-local check and AC-0012/AC-0013 name the assertion shape that actually reads `SKILL.md`.

**4. The change silently reverses the shipped rung's producer-neutrality without recording it.** `docs/specs/visual-target-confirmation/spec.md:132-134`. AC-0006 keys the top rung on another pack's template frontmatter vocabulary, which is precisely what `test_visual_authority_precedence.py:44-47` documents as the failure it guards ("A rung keyed on another pack's template vocabulary goes wrong at that template's next edit, and no declared-dependency check can see it") and what `docs/specs/frontend-visual-authority/spec.md:186` records as deliberate ("a writer that records confirmation some other way than the one the reference illustrates still satisfies rung 1"); the guard stays green only because it enumerates the two literals `proposed`/`selected`, and neither spec nor plan acknowledges the reversal — contrary to AGENTS.md § Coding conventions' bar on silently resolving a conflict between documented guidance and code. Fix: record the narrowing in the spec (a Risk plus the criterion that updates the guard's stated scope and rationale), or keep the `requires` cell producer-neutral and express the field requirement in the new rule table only.

**5. The shipped eval case that states the top rung's precondition is left in the superseded vocabulary.** `docs/specs/visual-target-confirmation/plan.md:287-298`. `packs/frontend-engineering/.apm/skills/frontend-engineering/evals/evals.json` case `visual-authority-approved-target` states its precondition as an artifact that "records a human-confirmed composition" with no field — the prose inference ADR-0131 exists to remove — and `packs/AGENTS.md:60` requires a non-cosmetic pack update to update that pack's eval harness, yet T9 only adds four cases and no criterion touches the existing one. Fix: add a criterion and task step updating the shipped `visual-authority-approved-target` case to state the confirmed reading as the field, and name it in T9's Touches.

## Concerns

**6. The plan cites the wrong boundary check, in three places.** `docs/specs/visual-target-confirmation/plan.md:11`, `:30-31`, `:261-262`. `tools/lint-pack-test-boundary.py:1680-1692` registers eight checks in order, and check 8 is `every-suite-dir-has-a-runner`; the rule that confines a pack suite to its own pack — the actual reason guide-tree criteria go to `tests/roster/` — is check 4, `pack-tests-stay-in-pack` (`tools/lint-pack-test-boundary.py:1163`). Fix: cite the check by name rather than by ordinal in all three places.

**7. The `SKILL.md` body-line budget is absent from Constraints with four lines of headroom.** `docs/specs/visual-target-confirmation/plan.md:28-39`. AC-0012 and AC-0013 both add content to `frontend-engineering/SKILL.md`, whose body is 964 lines against the `BODY_BUDGET = 968` pinned at `test_visual_authority_entrypoint.py:30`; that ceiling is owned by AC-0013 of the Shipped `design-to-build-value-handoff` spec (`:196`) and raising it is listed as a Never-do there (`:92`). Fix: add the 968-line ceiling and its owning criterion to the plan's Constraints, and state how T5 pays for its additions within it.

**8. The stated scenario-to-criterion map is not true as written.** `docs/specs/visual-target-confirmation/plan.md:100-104`. It maps selected-with-unconfirmed-target and older-artifact-without-the-field to "AC-0008 plus the AC-0017 regression" while omitting AC-0019 and AC-0020, the two criteria whose subjects those scenarios actually are, and maps explicitly-confirmed to AC-0006 alone — a table-cell string assertion, with no criterion anywhere asserting that a confirmed artifact resolves to the top rung. Fix: correct the map to name every criterion covering each scenario, and add a criterion for the explicitly-confirmed resolution or state which existing one covers it.

**9. AC-0019 does not name the fact that distinguishes it from a shipped eval case.** `docs/specs/visual-target-confirmation/spec.md:159-163`. `evals.json` already ships `visual-authority-direction-only`, whose prompt is "a direction artifact and a token taxonomy ... Nothing records a human-confirmed composition" and whose expected output resolves to `direction-and-taxonomy` — so the criterion as worded reads as met before any work in this PR. Fix: reword AC-0019 to require the case to carry the artifact's explicit `visual_target: unconfirmed` frontmatter reading, so the criterion is false against the shipped corpus.

**10. Three criteria's only possible check is that a sentence exists.** `docs/specs/visual-target-confirmation/spec.md:124-126`, `:130-131`, `:154-155`. AC-0003, AC-0005 and AC-0016 each name no literal a parse can pin — "states that ... neither substitutes for the other", "states that a delegated or still-proposed choice supplies no target confirmation", "states that confirming a direction does not confirm its visual target" — and `.claude/skills/new-spec/SKILL.md:320-330` rules that an obligation whose only check is a sentence's existence is design material for the plan, not a criterion. Fix: give each a literal the suite can pin, or move it to the plan's living design and drop it from the criteria set.

**11. AC-0014's "scoped" is not a decidable predicate, and T8 restates it instead of specifying it.** `docs/specs/visual-target-confirmation/spec.md:150-151`, `docs/specs/visual-target-confirmation/plan.md:273-275`. The criterion asks that the `frame` operation's interrogation instruction be "scoped so it does not apply on the `inherit` route", and T8's only Tests bullet repeats that sentence verbatim — while the shipped file already scopes one sibling clause by route (`creative-direction/SKILL.md:106`) and leaves `Run the interrogation` unqualified at `:108`. Fix: state the assertion — which line or window is read and what literal must appear in it — in both the criterion and T8's Tests bullet.

**12. The T3-before-T4–T6 ordering rationale names an impossibility.** `docs/specs/visual-target-confirmation/plan.md:110-112`, `:324`. The stated reason is "a consumer naming `visual_target: confirmed` while the template still lacks the field", but no T4/T5/T6 artifact reads the template: `pack-tests-stay-in-pack` forbids the frontend suite from reading `packs/experience-design/`, T6's regression uses its own fixture, and the whole change is one PR, so the intermediate state is never observable. Fix: either state the real dependency T3 supplies to T4–T6 or drop the ordering claim and keep the dependency edges the tests actually require.

**13. The corpus figures in Risks are wrong in both halves.** `docs/specs/visual-target-confirmation/plan.md:331-335`. Of the four files under `docs/design/direction/`, `token-verification.md` carries `type: design-system`, so `design-handoff.md`'s `type:` rule skips it and it never reads as `unconfirmed` at all; and "two of them do not even carry the template's `status` vocabulary" undercounts — `marketing-site.md` has no `status` key, both amendments carry `status: active`, and none of the four carries `proposed` or `selected`. Fix: restate the risk against the three artifacts the read contract actually admits and the correct vocabulary count (ADR-0131's Decision drivers carry the same two errors and should be corrected with it).
