## Blockers

**1. AC-0030 obliges a `Highlights` "none" verdict in a file the release pipeline says does not hold it.** `docs/specs/visual-target-confirmation/spec.md:212-215` (and `docs/specs/visual-target-confirmation/plan.md:338-340`). AC-0030 scopes the whole criterion to `docs/product/changelog.md` and then requires each entry to record "an explicit 'none' verdict with its reason where no highlight is owed", but `packs/AGENTS.local.md:31-41` step 4 says the opposite — a yes verdict is drafted as a `### Highlights` subsection in the changelog, a no verdict "and its reason" is recorded "in the PR's *What did you not change that you considered?* answer" — so a goal-based check over the changelog bytes can neither see the none-verdict nor find it legally present. Fix: restate AC-0030 so the changelog-scoped obligation is only what the changelog owns, and route the none-verdict obligation to the surface `packs/AGENTS.local.md` § Marketplace and release pipeline already assigns it, with a check that can reach that surface.

**2. ADR-0131's Confirmation section still claims the regression test the delta deleted.** `docs/adr/0131-visual-target-confirmation-is-an-explicit-state.md:134-140`. It states "A regression test asserts that an artifact carrying `status: selected` and a named target, with no confirmation, does not resolve to the top rung" — that is the unimplementable rung-resolution regression the delta removed when it reworded AC-0017 into a cross-pack drift assertion; no criterion, task, or eval case in the current spec or plan provides it (AC-0019 pins an explicit `visual_target: unconfirmed` prompt, not a `status: selected` artifact), so the ADR names a control nothing in this PR builds. Fix: make the ADR's Confirmation section enumerate only controls the spec's criteria actually establish.

## Concerns

**3. The scenario-to-criterion map's first row cites the absent-field criterion for a scenario whose field is present.** `docs/specs/visual-target-confirmation/plan.md:123`. Row "Selected, target present, confirmation absent" lists AC-0008, whose own text (`spec.md:157-158`) is confined to "an artifact without the field", which is row five's scenario — so the row claims coverage from a criterion that cannot red for it. Fix: map that row only to criteria whose text covers a present field reading `unconfirmed`, and let AC-0008 carry row five alone.

**4. The `delegated or still proposed` scenario row maps a criterion scoped to a selected direction.** `docs/specs/visual-target-confirmation/plan.md:126`. Row four lists AC-0029, which `spec.md:209-211` scopes to "a selected direction with a named target that no human confirmed", while `packs/experience-design/.apm/skills/creative-direction/assets/creative-direction-template.md:8-11` states `converge` writes `proposed` for a choice recorded as delegated — so AC-0029 cannot red for a delegated or still-proposed choice, and the row's only remaining cover is a content pin the completion gate does not read. Fix: either give row four a criterion whose text reaches a `proposed`/delegated artifact, or state in the map that the row is covered by a content pin rather than by AC-0029.

**5. The producing-side gate lands in `converge.md` while two sibling instruction surfaces keep the ungated "approved visual target" rule.** `packs/experience-design/.apm/skills/creative-direction/references/visualize.md:19` and `:41`, and `packs/experience-design/.apm/skills/creative-direction/SKILL.md:118`. AC-0025 rewrites `references/converge.md:80` to gate compositional commitments on `visual_target: confirmed`, but `visualize.md:19` still states unconditionally that "An approved visual target's compositional commitments are written into `<output_dir>/direction/<slug>.md` itself", which is exactly the prose-inference reading ADR-0131 exists to delete, and no criterion, task `Touches:` list, or content pin reaches either file. The consequence is a contradictory instruction pair rather than a proven bad write, since `visualize` writes nothing itself — that gap is named rather than traced. Fix: bring every creative-direction surface that states when commitments reach the doc under the same `confirmed` gate, or record why the prose surfaces are out of scope.

**6. T9 edits an eval case a shipped test pins, and the plan does not name the pin.** `docs/specs/visual-target-confirmation/plan.md:314-322`, against `packs/frontend-engineering/tests/skills/frontend-engineering/test_visual_authority_slice_two.py:136-139,182-190`. AC-0028 restates the `visual-authority-approved-target` case, whose `expected_output` that shipped test requires to hold the literal `resolved`; the plan's Constraints mention `test_visual_authority_slice_two.py` only as a filename not to reuse. Fix: record the `resolved` literal as a constraint on T9 so the restatement cannot drop it.

**7. T5 edits a file whose shipped suite forbids three producer literals, and the plan's Constraints omit that.** `docs/specs/visual-target-confirmation/plan.md:28-47` and `:247`, against `packs/frontend-engineering/tests/skills/frontend-engineering/test_visual_authority_precedence.py:95-99`. That test reds if `references/visual-observation.md` contains `experience-design`, `creative-direction`, or `design-system` anywhere — a natural way to author the new `## Visual-target confirmation` table ("the `creative-direction` template's field") trips it. Fix: add the producer-literal prohibition to the plan's Constraints so T5's table is authored in adopter-address terms.

**8. AC-0027's annotation can be satisfied while the Status line contradicts itself.** `docs/specs/visual-target-confirmation/spec.md:203-205`, against `docs/specs/frontend-visual-authority/spec.md:3`, which currently reads `Shipped (superseded in part by ADR-0130 — 960-line body budget; everything else stands)`. Appending an ADR-0131 clause without retiring "everything else stands" leaves the line asserting both that the `requires` value is superseded and that everything besides the body budget stands. Fix: have AC-0027 require the resulting Status line to be internally consistent, naming both supersessions and no surviving blanket "everything else stands".

**9. AC-0017's "stop agreeing" predicate is undefined across surfaces that carry different value counts.** `docs/specs/visual-target-confirmation/spec.md:175-177`. The template enumerates three values (AC-0001) and `visual-observation.md`'s `states` row enumerates three (AC-0009), but `design-system`'s `SKILL.md` names only `visual_target: confirmed` (AC-0011), so an implementer can satisfy AC-0017 with a subset check that cannot red when a value the design-system surface never carries is renamed. Fix: state the comparison AC-0017 requires — which literal from each surface is compared against which — so the assertion has one readable failure condition.

## Nits
