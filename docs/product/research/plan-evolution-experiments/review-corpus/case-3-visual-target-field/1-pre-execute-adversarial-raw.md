## Blockers

**1. AC-0009 and AC-0010 already pass at HEAD, so T3 can be a no-op and stay green.** `docs/specs/visual-target-field/spec.md:111-115`, `docs/specs/visual-target-field/plan.md:134-151`. This branch already carries `experience-design` `4.1.1` in `pack.toml:3`, `.claude-plugin/plugin.json:3` and the root `.claude-plugin/marketplace.json` entry, against `4.1.0` on `origin/main`, and `docs/product/changelog.md:94-102` already carries a free-standing `## [experience-design][4.1.1]` entry with a `### Highlights` subsection — all of it landed by the sibling `creative-direction-inherit-scope` slice (commits `2ba21c97b`, `eaaa5039a`). Both criteria are therefore satisfied before this slice edits anything, and satisfying them by leaving `4.1.1` in place is exactly what `packs/AGENTS.md` § Version bump rule forbids: "Do not borrow an unreleased version from another change." Fix: make the release criteria measure this slice's own bump — pin the baseline to the version this branch carries at the start of the work rather than to `origin/main`, and make the changelog criterion name an entry that did not exist before this slice.

**2. AC-0009's `origin/main` comparison has no verification artifact.** `spec.md:85-87`, `spec.md:111-113`, `plan.md:139-142`. Testing Strategy names `tests/conformance/test_pack_metadata.py` "plus a version comparison against `origin/main`". That file contains no git invocation and no `origin/main` reference — it checks intra-tree metadata consistency only. The second half of the check is an unnamed manual step, so the only half that actually runs is the half that passes when no bump happened. Fix: name a real artifact for the baseline comparison, or declare it as a recorded manual check with the command and the observed result written down.

**3. T2 is a four-test TDD task carrying neither a stub nor a `no stub (mode)` record, and T1's stub is prose rather than code.** `plan.md:118-132` and `plan.md:107`. `packs/core/.apm/skills/new-spec/references/spec-and-plan-contract.md:224-233` requires a TDD task to carry "the exact test code as the task's compilable, validated red **stub**", with `no stub (mode)` plus a reason as the only alternative. T2 declares four contract tests (AC-0004 through AC-0007) and neither. T1 writes `stub: true — one compilable red assertion over the template's frontmatter`, which is a description of a stub, not one; nothing has been compiled or earned a red. EXECUTE cannot materialize either. Fix: carry the actual compiled, validated red assertion text for every TDD task, or record the closed `no stub (mode)` exception with its reason.

**4. AC-0006 gates `visualize` on a field reading that cannot exist when `visualize` runs.** `spec.md:105-106`, `plan.md:76-82`. `visualize` precedes `converge` on the only route that reaches it — `SKILL.md:43` ("originate … frame → explore → visualize → converge") and `visualize.md:9` ("on `originate`, where `visualize` runs before selection"). `converge` is what copies the template into `<output_dir>/direction/<slug>.md` (`converge.md:80`) and, per this spec, what writes `visual_target`. So at `visualize` time the artifact and the field do not exist; under the plan's own absent-field rule (`plan.md:62`) the reading is always `unconfirmed`, and `visualize.md:21-22`'s instruction to record the three boundaries becomes unreachable. Fix: state AC-0006's condition as the confirmation determination the operation actually has in hand at that point, not as a read of a field written downstream — or move the gate to the surface that holds the field.

**5. AC-0005 and AC-0007 name no literal and no locatable unit, and as worded they sit on the wrong side of this slice's own rail.** `spec.md:103-108`. AC-0004 and AC-0003 name exact literals; AC-0005 ("`converge.md`'s compositional-commitments instruction is gated on the `confirmed` reading") and AC-0007 ("`SKILL.md`'s output-contract entry … is gated on the `confirmed` reading") name none, and `plan.md:36-39` nevertheless asserts "The gating criteria assert a literal inside the instruction rather than the instruction's presence, so removing the gate reds" — a property the criteria as written do not support. AC-0005's target is worse than unanchored: the compositional-commitments instruction is one clause inside the multi-topic paragraph at `converge.md:80` that also covers the template copy and the full fill list, so "the instruction" has no boundary a test can take. Any implementer satisfies both with a whole-file `"confirmed" in text` check — which is the presence-check mechanism `docs/specs/visual-target-confirmation/spec.md:38-41` records as already tried and rejected. Separately, "gated on the `confirmed` reading" reads as a read of the field, which `spec.md:66-68` forbids outright in this slice; the criteria and the Never-do rail contradict each other on their face. Fix: give AC-0005 and AC-0007 the same treatment AC-0004 gets — the exact literal and the bounded unit it must appear in — and word the gate so it does not describe a consumer read.

**6. Nothing in the spec or plan updates the pack's eval harness, which a scoped rule obliges.** `spec.md:29-39`, `plan.md:92-151`. `packs/AGENTS.md` § Security and authoring rules: "A non-cosmetic pack update also updates that pack's eval harness." This slice changes the artifact schema and three producing instructions in `experience-design`, and touches none of `packs/experience-design/.apm/skills/creative-direction/evals/`. The archived predecessor carried AC-0018 and AC-0029 for exactly this; this slice drops them with no `(deferred: <anchor>)` marker and no `workspace.toml [backlog].open` entry, so the obligation is silently gone rather than recorded. Fix: carry a criterion and a task for the eval-harness update, or defer it with a registered anchor.

## Concerns

**7. AC-0002 is an existence check on a bold label, and it leaves the one field the privacy rail governs unconstrained.** `spec.md:94-95`. It is satisfied by the literal string `**Confirmation record:**` appearing anywhere in the section; no possible check of it fails when the line is wrong. It is also the line `spec.md:71-72` forbids from carrying "a person's name, handle, or contact detail" — and the natural placeholder for "who confirmed this" is a name. ADR-0131:64-66 says the line carries "the confirmation's date and where it was recorded"; nothing in the criteria requires the placeholder to say that. Fix: constrain what the placeholder must offer an adopter, so the criterion fails when the line invites the content the rail forbids.

**8. The absent-field reading has no acceptance criterion.** `plan.md:62-64`, ADR-0131:68-70. The plan states that an absent field reads `unconfirmed` and that "the template's comment states it so an adopter writing an artifact today records the disposition deliberately", and the ADR makes that the fail-closed default. AC-0003's literal list (`spec.md:96-98`) does not include it, and no other criterion mentions it. The predecessor's Always-do rail carried it (`docs/specs/visual-target-confirmation/spec.md:101`); this slice's Agent Rules dropped it too. It is the one semantic the successor slice must build on, and this slice ships it unchecked. Fix: put the absent-field reading under a criterion, or record explicitly that it lands with the successor.

**9. AC-0008 does not verify that the re-derived guide excerpt carries the new material.** `spec.md:109-110`, `plan.md:24-28`, `plan.md:109-112`. `tools/lint-guidebook-steps.py:672-689` (`_appears_verbatim_in`) is a contiguous-substring check against a file-level declared source, not a line-range pin. The frontmatter key lands mid-excerpt, so that half is caught. But the excerpt's last line is the template's `**May adapt responsively:**` (`creative-direction-template.md:84` = `establish-design-intent.md:221`), which is the tail of the `## Approved visual target` section — a `**Confirmation record:**` line added after it leaves the existing excerpt verbatim and the lint green, with the adopter-facing guide showing a section that no longer matches the shipped template. Fix: make the criterion check what the excerpt contains, not only that the lint exits zero.

**10. The plan's dependency statement is stale against the tree it is planned into.** `plan.md:86-90`. "Independent of `creative-direction-inherit-scope` … If both are in flight, whichever lands second rebases" — that slice is not in flight. It landed on this branch (`2ba21c97b`, `eaaa5039a`), `docs/specs/creative-direction-inherit-scope/` does not exist, and its release consumed the version number AC-0009 measures against. The one sentence in the plan that reasons about this coupling is reasoning about a state that has already passed. Fix: restate the section against the branch as it stands, including what the sibling's release leaves this slice owing.

**11. Nothing records which bump size this slice owes.** `spec.md:111-113`, `plan.md:134-151`. `packs/AGENTS.md` § Version bump rule classifies bumps — patch for changed content, minor for new primitives, major for removals — and AC-0009 requires only "strictly greater", which a major bump satisfies as readily as a patch. Adding a key adopters author against is the kind of call worth recording once; the criterion cannot detect a bump that violates the classification. Fix: record the size and its reason where T3 reads it, and constrain the criterion to it.
