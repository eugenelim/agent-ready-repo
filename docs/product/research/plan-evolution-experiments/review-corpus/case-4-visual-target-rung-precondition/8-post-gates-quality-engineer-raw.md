## Blockers

**1. Prospective cases have no executable ledger contract.** `docs/product/research/plan-evolution-experiments/review-effectiveness-baseline.json:383-390`, `docs/product/research/plan-evolution-experiments/review-effectiveness-baseline.json:467-472`. The release admits consecutive cases and lists minimized fields, but never freezes the durable case ledger, stable case key, candidate enumeration source, single-writer/update rule, duplicate/conflict handling, or reconciliation counts, so skipped, duplicated, partial, or stale cases can still look valid. Fix: The approved record must freeze the prospective case ledger contract, including identity, statuses, write/recovery rule, conflict rule, and count/digest reconciliation.

**2. The reviewed release record is not digest-bound.** `docs/product/research/plan-evolution-experiments/review-effectiveness-baseline.json:376-379`. The only digest stored is `sha256_before_release_record`, so future cases can cite `t15-prospective-natural-work-v1` without proving which reviewed release-record bytes governed them. Fix: The approved record must bind the canonical digest of the current release record and require every prospective case to reference that digest.

**3. The 80% lineage threshold has no denominator.** `docs/product/research/plan-evolution-experiments/review-effectiveness-baseline.json:441-447`. The decision rule requires “at least 80% complete finding-lineage fields” but does not enumerate the counted fields or missingness denominator, letting the complete/incomplete verdict drift after outcomes are visible. Fix: The approved record must freeze the prospective case/finding lineage schema and how null, unknown, inapplicable, and not-retained values count.

**4. Prose-churn cost is missing from the release scorecard.** `docs/product/research/plan-evolution-experiments/review-effectiveness-baseline.json:454-465`, `docs/specs/plan-evolution-experiments/plan.md:778-780`. The scorecard includes churn rate and general cost fields but omits the required reviewer/adjudicator/repair actions, tokens, and wall time attributable to prose-churn events. Fix: The approved record must require prose-churn cost attribution, aggregate totals, share of normal loop cost, and explicit unavailable values when telemetry is absent.

## Concerns

**5. Retention has no window or loss gate.** `docs/product/research/plan-evolution-experiments/review-effectiveness-baseline.json:467-480`. The record lists retained and not-retained data classes but no retention window, deletion point, or gate before irreversible loss, so audit evidence can disappear too early or minimized data can linger without a frozen rule. Fix: The approved record must freeze retention windows and deletion/quarantine gates for retained, withheld, and not-retained material.
