## Blockers

**1. Worker launch contract omits least privilege (`reason`).** `docs/specs/plan-evolution-experiments/plan.md:27`, `docs/specs/plan-evolution-experiments/spec.md:294`. An attacker who controls a candidate prompt, task tree, or generated patch enters a `codex exec` worker that the contract only says runs without network and with write confinement, so the spec can be satisfied while the worker still inherits host credentials, broad read access, hidden-oracle paths, other cells, or wider delegated authority. Fix: add acceptance criteria for explicit worker sandbox mode, readable and writable roots, environment and credential stripping, tool and delegation ceilings, process/time/token caps, and fail-closed accounting for any unavailable or widened authority.

**2. Archive and run paths are not confined by canonical containment (`hybrid`).** `docs/specs/plan-evolution-experiments/plan.md:22-23`, `docs/specs/plan-evolution-experiments/plan.md:276-282`. An attacker who controls a historical task tree or candidate output can use symlinks, archive members, or path-shaped fields to make controller, oracle, prompt, output, or evidence handling resolve outside the intended roots while still meeting the current "outside candidate" and "no readable parent" prose. Fix: name allowed roots for baseline, candidate, hidden-oracle, prompt, output, and evidence paths; require canonicalize-then-contain checks with symlink, loop, traversal, and Git/archive escape rejection; and require the repo `file_safety` helpers where applicable or a justified equivalent for disposable worktrees.

## Concerns

**3. Report resource recovery has no SSRF policy (`reason`).** `docs/specs/plan-evolution-experiments/spec.md:302`, `docs/specs/plan-evolution-experiments/plan.md:388`. An attacker who influences a linked resource through a source discussion, article, recovered page, or model output can steer controller-side retrieval or `pure.md` recovery toward private, link-local, metadata, or redirecting destinations because the contract requires fetched-resource evidence without fixing schemes, hosts, redirect behavior, or DNS/private-range blocking. Fix: either prohibit arbitrary controller-side fetching or add acceptance criteria for a fixed scheme and host allowlist, private/link-local/metadata blocking, redirect and DNS-rebinding handling, and separation between the Codex service connection and general candidate egress.

**4. Structured result inputs lack strict schema requirements (`hybrid`).** `docs/specs/plan-evolution-experiments/plan.md:98-102`, `docs/specs/plan-evolution-experiments/plan.md:312-329`. An attacker who influences Codex JSONL, self-audit output, adjudication records, or result artifacts can feed malformed fields, oversized values, path-like values, or non-finite metrics into gate decisions or durable evidence because the plan describes selective validation but does not require strict typed schemas for every structured model and JSON input before use. Fix: add acceptance criteria that all structured inputs and model outputs are parsed with declared schemas, size bounds, exact field/type checks, non-finite JSON rejection where numeric metrics are used, no unsafe deserialization, and fail-closed handling before any command, path, grading, gate, or report sink.

## Not checked

- Did not dynamically verify Codex CLI sandboxing, network egress, or filesystem confinement; this was a spec-stage source review with no implementation to exercise.
