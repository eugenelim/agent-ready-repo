## Blockers

**1. T15 can send unscreened real stopped revisions to the shadow model.** `docs/product/research/plan-evolution-experiments/review-effectiveness-baseline.json:392-407`; `docs/specs/plan-evolution-experiments/spec.md:392-397`. A future eligible case whose stopped spec, plan, or review artifact accidentally contains a credential, personal identifier, protected config, private endpoint, or unrelated source body can be reused in a fresh cold shadow/adjudicator prompt because the release record names safe content and non-retention but does not freeze the controller-side pre-prompt screen/quarantine step that the spec requires before persistence or reuse. Fix: require the T15 release record to fail closed on a controller-side privacy/secret/protected-config screen before any retained event row, shadow prompt, or adjudicator prompt is built; suspected material must be represented only by digest, generic reason code, and quarantined/not-retained status.

**2. Shadow and adjudication starts lack a least-privilege authority profile.** `docs/product/research/plan-evolution-experiments/review-effectiveness-baseline.json:403-413`; `docs/specs/plan-evolution-experiments/spec.md:478-492`. A measurement reviewer or adjudicator that inherits a normal agent tool surface could read beyond the exact stopped revision, use network/delegation/approval paths, or mutate repository state during T15 because the release record binds role/model names and start counts but not the no-write, no-network, no-delegation, no-protected-config runtime authority profile required for model starts. Fix: bind T15 measurement starts to an observable least-privilege profile over exact stopped-revision inputs only, with writes, web/network, delegation, external messaging, approval escalation, and protected configuration absent or denied before launch.

## Concerns

**3. The measurement cap limits starts but not token, byte, or wall-clock spend.** `docs/product/research/plan-evolution-experiments/review-effectiveness-baseline.json:409-413`; `docs/product/research/plan-evolution-experiments/review-effectiveness-methodology.md:126-131`. A large stopped revision or verbose shadow/adjudication exchange can still cause unbounded model cost within the 24-start cap because the release record has no per-case or cohort input-token, output-token, prompt-byte, or wall-clock ceiling. Fix: add per-case and cohort prompt byte, input/output token, and wall-clock limits that are checked before launch and counted explicitly when exceeded.

**4. Approval does not bind the release-record bytes.** `docs/product/research/plan-evolution-experiments/review-effectiveness-baseline.json:376-382`; `docs/product/research/plan-evolution-experiments/review-effectiveness-methodology.md:105-111`. A later edit to admission, exclusion, authority, or retention fields could appear to be covered by owner approval because the only stored digest is the baseline before the release record was added, not the approved release record itself. Fix: require independent review and owner approval to cite a digest of the canonical release-record bytes, then require exact digest equality immediately before the first prospective admission.
