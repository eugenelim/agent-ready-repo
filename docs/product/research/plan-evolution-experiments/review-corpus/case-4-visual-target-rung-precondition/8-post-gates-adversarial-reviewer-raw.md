## Blockers

**1. Exclusions are not actually frozen.** `docs/product/research/plan-evolution-experiments/review-effectiveness-baseline.json:392-402`. AC-0022 requires the release record to freeze exclusions before any prospective case starts, but the record only says exclusions are “rule-grounded” and recorded with generic reason codes, leaving the exclusion catalog and evidence test open after outcomes are visible. Fix: freeze a closed exclusion-code catalog, required evidence for each code, decider, and rule for in-flight/ambiguous cases; finding count, model route, outcome, or convenience must not affect admission.

**2. The closure envelope is referenced but never bound.** `docs/product/research/plan-evolution-experiments/review-effectiveness-baseline.json:433-439`. The record reopens broad review for “repair outside the closure envelope” or an omitted whole-change state, while the plan requires each case to capture normal reviews, adjudication, repairs, focused closure review, stopping decision, advisory residue, and exact stopped-revision digest. Fix: freeze the per-case closure-envelope schema and binding rule before launch, including reviewed revision, stopped revision, changed bytes/dependencies, sustained blockers, closure-review scope/result, advisory residue, stop decision, and digests.

**3. The 80% lineage gate has no denominator.** `docs/product/research/plan-evolution-experiments/review-effectiveness-baseline.json:441-447`. The release requires “at least 80% complete finding-lineage fields” and “cost telemetry sufficient” for an effectiveness reading, but it does not enumerate the fields, denominator, completeness rule, or telemetry minimum, so the sufficiency gate can move after cases are seen. Fix: freeze the exact lineage field set, per-case/per-finding denominator, completeness formula, required cost fields, and missingness handling.

**4. The scorecard drops the prose-churn cost measure the plan requires.** `docs/product/research/plan-evolution-experiments/review-effectiveness-baseline.json:454-465`. The governing plan requires directly observed reviewer, adjudicator, and repair cost attributable to prose-churn events, but the release scorecard only names the prose-churn rate and durable-blocker cost fields. Fix: add frozen scorecard fields for prose-churn-attributable review/adjudication/repair actions, input/output tokens, wall-clock time, and their share of observed loop cost.

## Concerns

**5. The pre-record digest is an unverifiable attestation, not a binding.** `docs/product/research/plan-evolution-experiments/review-effectiveness-baseline.json:376-379`. The record points to the same mutable JSON file and gives a `sha256_before_release_record`, but no retained pre-record bytes or reconstruction rule are present, so a reader cannot verify the claimed baseline state. Fix: either retain the pre-record baseline bytes or add a deterministic reconstruction artifact with current/pre hashes; otherwise label the digest as an unverified controller attestation.
