## Blockers

**1. `stable_case_key` changes mid-lifecycle.** `docs/product/research/plan-evolution-experiments/review-effectiveness-baseline.json:407`. The repair defines the stable key with `stopped revision digest when available or literal pending`, so the same case hashes differently between `candidate_enumerated` and `normal_loop_terminal`, breaking the case-ledger identity the sustained quality finding required. Fix: make the case key immutable across lifecycle transitions and store later stopped-revision digest checks as separate ledger or closure-envelope fields that reconcile without changing identity.

**2. Token hard limits are not pre-launch gates.** `docs/product/research/plan-evolution-experiments/review-effectiveness-baseline.json:540`. The hard-limit repair caps observed input/output tokens while the enforcement rule requires per-start/per-case limits to be enforced or observed before launch, so the token budget is either checked only after the launch it was meant to gate or excludes every case as unenforceable. Fix: distinguish pre-launch enforceable limits from post-run telemetry and freeze the enforcement mechanism for any token cap that gates admission.
