### Sync tool

`tools/catalogue/sync_authoring_scaffold.py --check` verifies that scaffold files in
`packages/agentbundle/agentbundle/_data/catalogue-scaffold/` match their source copies.
This covers the scaffold documents (packs/README.md, packs/AGENTS.md, etc.) but NOT the
schema JSON files — those are not covered by the sync tool.

**Gap:** No tool currently verifies that `contracts/` and `agentbundle/_data/` schema files
are byte-identical. This is a manual invariant with no CI gate.

## Generated projections

### `marketplace.json` (Claude-specific marketplace projection)

Location: `.claude-plugin/marketplace.json` (root), also generated at `packages/agentbundle/agentbundle/_data/catalogue-scaffold/.claude-plugin/marketplace.json`

Generated by: `make build-self` / `agentbundle catalogue self-host --root . --write`

Content: Pack listing for Claude plugin marketplace. Hand-maintained? Partially — `make build-self` regenerates it from pack.toml files. The pack description fields come from pack.toml.

**Key issue:** No neutral `catalogue-index.json` exists. The only aggregate machine projection is `marketplace.json`, which is Claude-specific and does not include: pack lifecycle, skill inventory, content digests, optional integrations, journey metadata, effect declarations.

### Per-pack `pack.toml` (primary pack metadata)

Source of truth for each pack's name, version, description, categories, install scope, dependencies, eval coverage, first-value metadata. These are readable machine contracts.

### Catalogue manifest (not yet implemented)

The brief describes `catalogue-manifest.json` as "immutable file and digest evidence." This does not yet exist. The `agentbundle catalogue package` command creates an archive but not a separate manifest with content digests.

Current state: lists 4 of 11 contracts, with governing specs.

### `packs/AGENTS.md` — schema map (hand-maintained, not contract-tested)

The `## pack.toml schema map` section has a table of pack.toml fields. This is:
- Accurate for the fields it covers
- Not explicitly linked to `contracts/pack.schema.json`
- Not tested against the JSON schema (can drift silently)
- Not a complete reproduction of the JSON schema (some fields omitted)

**Authority risk:** Agents that read packs/AGENTS.md may treat this prose table as the

## CLI consumers

### `agentbundle catalogue lint`

Validates pack.toml, plugin-manifest.json, skill frontmatter, eval format.
Reads schemas from `agentbundle/_data/` (bundled).
**Gap:** Does not validate skill content against `skill.schema.json` because that schema
is not bundled.

### `agentbundle catalogue verify`

Full catalogue validation. Exit codes 0/1/2 as documented in catalogue-ci-contract.md.
Reads schemas from bundled `_data/`.
**Gap:** Same as lint — skill.schema.json, guide.schema.json, skill-manifest.schema.json absent from bundle.

### `agentbundle show` (proposed in brief)

Does not currently expose pack integrations (because `[[pack.integrations]]` does not exist).

### `agentbundle catalogue contracts` (proposed in brief)

Does not exist. The brief proposes:
```
agentbundle catalogue contracts list
agentbundle catalogue contracts show pack
agentbundle catalogue contracts show skill
agentbundle catalogue contracts export --output ./contracts
```

This surface would use `importlib.resources`, work without network, expose exact bundled
contracts, distinguish reference export from executable override. Needs RFC acceptance.

## Authority direction (proposed)

```
contracts/
    canonical authored public contracts — normative

        → (deterministic projection rule)

packages/agentbundle/agentbundle/_data/
    executable contracts bundled with AgentBundle — must be byte-identical to contracts/

        → (validation and generation — reads _data/ schemas)

generated neutral catalogue-index.json
    machine projection — distinct from catalogue-manifest.json and marketplace.json

        → (generated or contract-tested references)

AGENTS.md, README.md, and guides
    concise operational and narrative guidance — NOT an independent schema source
    schema maps in AGENTS files must be contract-tested
    complete human reference pages generated or verified from contracts
```

**Changes required to establish this authority direction:**
1. Add `guide.schema.json`, `skill.schema.json`, `skill-manifest.schema.json`,
   `target-vocab.toml` to `agentbundle/_data/` with byte-identity check.
2. Update `contracts/README.md` to list all 11 contracts.
3. Add CI gate verifying schema byte-parity between `contracts/` and `_data/`.
4. Add explicit normative statement in `packs/AGENTS.md` and `profiles/AGENTS.md`
   pointing to the machine source of truth.
5. Generate or contract-test the prose schema maps in AGENTS files.
